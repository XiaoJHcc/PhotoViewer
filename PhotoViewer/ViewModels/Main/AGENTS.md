# ViewModels/Main — 主窗口 VM

> 模块内手册。VM 间联动(MainViewModel 怎么组合子 VM、文件源事件如何驱动文件栏)见[架构文档](../../../Design/architecture.md)；共享几何与命令表见 [PhotoViewer.Shared](../../../PhotoViewer.Shared/AGENTS.md)。

`namespace PhotoViewer.ViewModels.Main`

共享 VM 只做业务状态，不持有任何 UI 框架类型：主图加载由 `Core/Image/PhotoLoadSession` 编排，视口缩放/平移由各端原生层持有；分析栏编排在 `Core/AI/AnalysisPresenter`，四个原生壳共用。原 Avalonia 壳的 `ImageViewModel`、`AnalysisViewModel`、`Views/Main/*.axaml` 已随 6D 退役删除，`UsesNativePresentation` / `nativePresentation` 开关也不存在。显式打开（文件/文件夹/外部打开/拖入）由 `MainViewModel.RequestFitToView()` 触发 `FitToViewRequested`，平台壳订阅后把主图切回适应态（OPEN-05）。控制栏命令统一为 `ReactiveCommand<Unit, Unit>`（打开/上一张/下一张/交换/评分 0–5/分析栏），不再有视口命令与 `PointerContext`。跨模块链路见[架构文档](../../../Design/architecture.md) §5.6–§5.9。

| 模块 | ViewModel | 职责 |
|---|---|---|
| **主窗口 / Main shell** | [MainViewModel.cs](MainViewModel.cs) | 组合文件源、文件栏、控制栏、设置与工具 VM；维护 `CurrentFile` / `LastFile` / 锚点高亮（`IsCurrent` 与 `IsCurrentImage` 双身份，`SetCurrentImageKeepAnchor` 供相似聚类保留锚点）；`RatingWriteFailed` 事件供各端提示条（FILM-06），`OpenFailed` 事件承载共享层统一给出的打开失败文案（STATE-02，壳以 STATE-03 提示条显示），`FitToViewRequested` 供显式打开回适应态（OPEN-05）。构造时创建实例级 `OpenCoordinator` 并暴露为 `OpenCoordinator`；`Dispose` 取消外部打开消费者与会话、释放评分来源浮窗状态（退订全部来源）与设置。`OpenToolsWindow` 仅在 `Tools.IsPresented == false` 时回工具首页，已打开只前置并保留当前页（TOOLS-01）。评分成功/失败后都用 `RatingSourceReader` 逐文件重读**全部**来源回填内存（共享 sidecar 会回到每个文件，内嵌 Conflict 不被单份 After 抹掉），**不 ClearExifData**；所有非 Applied 结果都按磁盘真值重读。写后回读重新发现 sidecar，不信任列表旧索引；刷新按文件存储身份分别校验代际，同文件旧刷新不得覆盖新状态，不同照片互不作废。失败沿用 `RatingWriteFailed`（FILE，rating）兼容四端，并新增 `RatingWriteFailedDetailed` 携带 `RatingWriteFailure`（结果/原因/是否 Partial），避免共享 `LastRatingWriteError` 被后发请求清空串台。`SetRatingAsync` 保持原签名，另提供 `SetRatingWithResultAsync` 返回本次 `RatingWriteOutcome?` 供调用方决定后续处理。 |
| **外部打开协调器** | [OpenCoordinator.cs](OpenCoordinator.cs) | 消费 `Main.OpenRequests` 的唯一消费者（启动即跑，界面就绪前的请求已在通道排队），按投递顺序逐个 await，状态改动一律回到 UI 线程；`PublishAndWaitAsync` 供验收等待本批处理完成。一批只取首个可打开项（文件夹或受支持图片），其余忽略；文件目标一律 `OpenImageAsync(..., refresh: true)` 重新枚举父目录并刷新元数据，重复激活当前照片或同组伴侣时先发 `RepeatActivation`（壳负责前置窗口）并保留滚动与视口，新目标按 OPEN-05 回到适应态并定位；重复激活当前目录先发 `RepeatActivation`，再 `OpenFolderAsync(scrollToCurrent: false, resetView: false)` 原地重枚举（OPEN-06/08）。异常统一经 `Main.ReportOpenFailure`（STATE-02），不静默、不产生未观察 Task。无静态队列或静态处理器。 |
| **文件源** | [FolderViewModel.cs](FolderViewModel.cs) | 仅负责打开文件/文件夹与维护 `AllFiles`；通过 `AllFilesChanged` / `ScrollToCurrentRequested` / `PriorityThumbnailRequested` 事件通知文件栏。每次打开交给一个 [FolderLoadSession.cs](FolderLoadSession.cs)：持有 `Main.StorageAccess` 访问租约、取消源与工作列表，后发打开取消先发的枚举/属性/星级任务，旧结果不发布；枚举成功后才一次提交新列表（失败保留旧快照）；新快照提交成功时释放被取代会话的租约，当前快照保留到下一次提交或文件源释放，不同目录提交时才清 Thumb 缓存（OPEN-08）。打开文件夹且未指定目标时首张取 `PhotoListProjection.Project` 的结果首项（同名合并下即代表文件），筛选为空时回退枚举首项所属合并组的代表文件（OPEN-04）。指定目标优先，父目录不可读/枚举被拒时回退单图模式（OPEN-03）；目标已在当前目录模型只切换、不重建，文件身份只比 `StorageId`，被合并的伴侣文件经组映射到代表文件。显式打开新目标默认 fit（OPEN-05），`resetView:false` 供重复外部激活。同目录刷新复用 `LoadFolderAsync` 的刷新路径：按 `StorageId` 复用仍存在的 `ImageFile` 并换成本次枚举的 sidecar 索引（保持旧顺序后追加新文件，缩略图/EXIF/卡片身份与同名组代表都不变），删除的文件退出列表，当前照片对象不变；**复用对象在后台调用 `ImageFile.RefreshMetadataAsync`** 重读基本属性、完整 EXIF 与全部评分来源，新出现的文件走阶段 3 的属性/星级首读；不重新 fit、不滚动、不整批清缩略图。`OpenImageAsync` 的 `refresh` 参数同时服务单图模式（重读 EXIF/星级而不换对象）与父目录重枚举。每次打开由 [FolderLoadSession.cs](FolderLoadSession.cs) 承担；其 `EnumerateAsync` 在同一次枚举内建立 `RatingSidecarIndex`（`<stem>.xmp` 索引），但**枚举成功完成前 `SidecarIndex` 返回 null**，阶段 1 目标与未枚举的新增目标都回退逐文件查找，不会把尚未建好的空索引当作“目录没有 sidecar”；枚举完成后才暴露真实（可能为空）索引并回填到所有工作文件。单图模式索引恒为 null。 |
| **评分来源浮窗** | [RatingSourcesViewModel.cs](RatingSourcesViewModel.cs) | 来源浮窗状态：`Show(target, group)` 按 `PhotoGroup.RatingSources` 生成来源条目（类型、文件名、状态），`Items` / `IsOpen` 供原生宿主绑定。打开期间订阅 `Target` 与组内全部文件的 `RatingSources` / `Group` 变化，按共享真值 `Refresh`；`Group=null` 是 `PhotoGroupMap.Build` 先清空再回填的过渡态，忽略到新组回填。`Close` 退订，`Dispose` 退订并释放（`MainViewModel.Dispose` 已接入）。状态文案区分 Rated 0（无星级）、Missing（未设置）、Invalid（无效）、Unreadable（无法读取），不合并。`SetRatingAsync` 走 `MainViewModel.SetRatingWithResultAsync` 整组统一写，刷新后只有 `Applied` / `NoChange` 且目标组冲突解除才关闭，其余情况保留并按最新来源刷新（RATING-04）。`MainViewModel.RatingSources` 暴露单例，`ShowRatingSources` 为入口；浮窗宿主由各端原生壳接入，本 VM 不依赖 UI 框架。 |
| **文件栏-容器** | [File/FileViewModel.cs](File/FileViewModel.cs) | 组合筛选条、主缩略图列表与相似聚类面板；`IsRowLayout` / `IsSimilarityPanelOpen` 直通共享状态，供各端原生文件栏决定分区与让位。 |
| **文件栏-筛选** | [File/FilterBarViewModel.cs](File/FilterBarViewModel.cs) | 排序方式 / 方向 / 星级筛选 + 计数 + 相似聚类 toggle。星级筛选含 `Rejected`（已拒绝，命中代表内嵌 Rating=-1）与 `Conflict`（独立维度）；数字与“以上”按代表文件内嵌值命中，冲突不清除数字命中（`PhotoListProjection`）。变化通过 `FilterChanged` / `SortChanged` / `SimilarityPanelToggled` 事件通知下游；`IsSimilarityPanelOpen` 直通 `SettingsViewModel.SimilarityPanelExpanded`（经 `IViewStateStore` 跨会话保留，不进入设置文档）；`FilteredCount` 由 `BindFilteredCountProvider` 注入并可与列表同帧刷新（FILTER-04）。 |
| **文件栏-主缩略图列表** | [File/ThumbnailListViewModel.cs](File/ThumbnailListViewModel.cs) | 维护 `FilteredFiles`、缩略图加载（投递 `DecodeScheduler`：可见/当前 → P1，普通排队 → P2）、可见区域与定位请求；位图预取由 `BitmapPrefetcher` 调度，并在当前图变更时向 `BitmapLoader.SetRetentionRanking` 上报**有序淘汰排名**（① 当前图 ② 上一张浏览过的图 ③ 翻页方向 +1 ④ 反方向 −1 ⑤ 第二张最近浏览 ⑥ 其余邻居按"方向上距离 d 计 d、反方向 2d" ⑦ 其余最近浏览）。翻页方向 = 最近一次 `CurrentFile` 变化的列表索引差符号（无历史时正向），`FlipDirection` 供预取按方向优先排序。翻页经共享 `MoveCurrent`（FILTER-05：当前照片被筛掉时按重算前索引定位最近邻项）；名称排序 `OrdinalIgnoreCase`（FILTER-02），评分筛选暂留与计数同帧（FILM-06 / FILTER-04）。卡片绘制由各端原生卡片承担。 |
| **文件栏-相似聚类列表** | [File/SimilarityPanelViewModel.cs](File/SimilarityPanelViewModel.cs) | 基于 DINOv3 CLS 的真实相似聚类(`Core/AI/SimilarityService`)。**触发门控(SCOPE-01)**:仅当面板展开且文件栏可见(`IsSimilarityPanelOpen && IsThumbnailViewVisible`)时,才随 `CurrentFile` / `FilteredFiles` / 阈值变化重算;收起即取消在途计算,切图不隐式推理;重新展开时 `OnPanelOpened` 按当前图重算并统计覆盖度。三态 UI(Empty / Partial / Full)由 `ShowFullPlaceholder` / `ShowUnindexedPlaceholder` / `IsStateIndexing` 等布尔量给出，"提取全部/补齐全部"按钮原地换进度条;`FolderFeatureIndexer` 一轮扫描同时落 DINO CLS+patch+CV 三类原始数据,`EvaluateMissingPartsAsync` 三路齐备才算已提取。点击相似项通过 `SetCurrentImageKeepAnchor` 切主图但保留原锚点。分数 75%~100% → 柱状条的映射由各端卡片按同一口径实现。提取错误 `IndexError`/`HasIndexError` 在列表态与空态共用;`ShowActionAreaError` 供列表态动作区绑定(SIM-10)。 |
| **控制栏** | [ControlViewModel.cs](ControlViewModel.cs) | 控制栏 EXIF 摘要项与命令集合；按钮按 `Settings.Hotkeys` 的主/次绑定与显隐顺序生成，命令统一为 `ReactiveCommand<Unit, Unit>`（`OnOpen` / `OnPrevious` / `OnNext` / `OnExchange` / `OnSetRating0..5` / `OnToggleAnalysisView`），EXIF 文本由 `Core/Exif/ExifDisplayConverters.cs` 的 `ExifDisplayFormat` 按 TOOLBAR-05 格式化（四端同源）。 |
