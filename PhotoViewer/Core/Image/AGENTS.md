# Core/Image — 图片解码与文件模型

> 模块内手册。图片加载 pipeline(切图触发 → 解码 → 显示 → 预取)的端到端流程见 [架构文档](../../../Design/architecture.md) §5 关键流程。

`namespace PhotoViewer.Core.Image`

P2 原生新增：`IPresentationImageDecoder`（平台主图解码注入口）+ `IPresentationEncodingPolicy`（展示编码协商，I2 起；按尺寸档与压力返回编码，Core 内不含平台判断）；`PhotoLoadSession` 只持展示租约与代际/代理/Full 加载状态，视口变换由原生层负责。原生端到端流程见[架构文档](../../../Design/architecture.md) §5.6（macOS）、§5.7（iOS）与 §5.8（Windows），旧壳仍走原有 ImageViewModel/适配器。`IDisplayLoadSignal` 让压测驱动器（`PhotoViewer/StressFlipDriver.cs`）对"旧壳 ImageViewModel / 原生 PhotoLoadSession"同一口径计时。

`SkiaImageCodec.DecodeToWidth/DecodeToLongEdge` 从 codec 原始尺寸填充 `SourceWidth/SourceHeight`，`ScaleToLongEdge` 继续保留这两项；无 EXIF 尺寸的照片也不能把代理尺寸当成 Full 几何。像素缩放算法和模型输入字节口径不变。

`DecodedImage` P2 扩展：保留 Bgra32/Rgb24，新增 RgbaF16 与 **Rgba8**（I2 起 8 位展示编码，RGBA 字节序，色彩空间由 `ImageColorSpace` 声明）；`PresentationFidelity` 给出展示编码保真度序（F16 可覆盖 8 位请求，反之不可）。色彩标签（Core/Color）、源尺寸、待应用方向与可选 ICC 均显式携带。缓存大小按 `ByteCount` 实际池化分配记账；原生启动期注入后 Thumb 仍是 sRGB8，小图缺少内嵌来源时允许原生子采样，不回退原图全解码。PhotoLoadSession 保持同代际代理覆盖单调增长，不让慢的小代理覆盖大代理/Full；放大态切图直接请求 Full。代理在途原请求取消而新调用仍有效时重发代理，取消不当作解码错误回退 Full；当前代际被外部取消时复位状态并给出可见错误，不再静默黑屏。并发入库用原子更新保留更大代理与缓存租约。

| [PhotoLoadSession.cs](PhotoLoadSession.cs) | 原生展示会话 | 原生壳的加载/展示编排:代际闸、代理 ↔ Full 单调升级、视口物理像素上报(**视口尺寸 < 1 时忽略上报**——否则代理目标会被钳成 1 像素、解码出 1×1 的"合格代理"并永不重载);持有会话租约,订阅者同步上传期间源缓冲有效。**增强预览**(P2/P3)也在这里:开关跨切图持续生效、`Image` 在增强就绪后返回增强图、新图到达自动重算、压力到 Warning 自动关闭并释放;增强算法只在 8 位 sRGB 口径有定义——转 sRGB8 副本后就地均衡,再回**源展示编码**(8 位档保持 8 位 Display P3、F16 表面回 F16);`IsEnhancing` 暴露"已开启但增强图未就绪",供宿主显示计算反馈(失败/取消/关闭后归 false,不静默停留)。 |
| [DecodedImage.cs](DecodedImage.cs) | 像素契约 | 平台中立已解码图像:`byte[] Pixels` + `Width/Height/Stride` + `PixelEncoding`(Bgra32/Rgb24/RgbaF16/Rgba8)。P1-M3 起为**引用租约 + 缓冲池**模型:创建携带 1 份租约(通常归缓存),消费方 `TryAcquire`/`Release` 借用;最后一份租约释放时池化缓冲归还 `ImageBufferPool` 而非丢 GC;租约归零后 `Pixels` 返回空。解码主路径一律 `RentPixels` + `CreatePooled`;小图/工具图可直接 `new`(GC 兜底)。UI 层经 `Platform/DecodedImageAdapter` 转 `WriteableBitmap` 上屏(行拷贝,转换后与原图解耦)。 |
| [ImageBufferPool.cs](ImageBufferPool.cs) | 像素缓冲池 | 2 幂分档(1KB~512MB)租用/归还,档帽(≥16MB 每档 4 个)防失控;消灭 42MP 级 LOH 分配/回收循环(基线:每张 124MB 触发 1 次 gen2 → 池化后 20 张 0 次)。内存客户端自登记,Critical 整池清空。 |
| [SkiaImageCodec.cs](SkiaImageCodec.cs) | 像素操作原语 | Core 唯一像素操作出口(SkiaSharp):`Decode` / `DecodeToWidth` / `DecodeToLongEdge`(P1-M4 代理口径:codec 子采样 + Mitchell 精修)/ `ScaleToLongEdge`(全解码后 Mitchell 精缩,供无子采样能力的平台解码器;守画质红线替换旧最近邻)/ `ToBgra32` / `ApplyOrientation`(旋转+镜像)/ `Crop`(按源像素裁剪,保留源的编码与色彩标签,P2 起支持 F16 表面,供原生细节预览)/ `ScaleToExact` / `SavePng`。DINO 输入缩放用 Linear 采样,口径与原 Avalonia DrawImage 默认一致(契约敏感)。 |
| [ImageOrientationMapping.cs](ImageOrientationMapping.cs) | 方向映射权威表 | 容器方向码 → 显示朝向的几何映射(旋转角+镜像,与 `ApplyOrientation` 同口径)与显示归一化点 → 容器归一化点的反映射。`ColorEngine.ToAnalysisSrgb8` 与 `DisplayCrop` 都从这里取,避免两处表格漂移。 |
| [DisplayCrop.cs](DisplayCrop.cs) | 显示朝向 1:1 细节裁剪 | 从**容器朝向**的原始像素裁出显示朝向下某归一化点周围的方形块(先反映射坐标、裁剪小块、再把小块转 sRGB8 并做方向变换),不复制整幅源图 — 原生大图(42MP F16)的细节预览用。 |
| [ImageEnhancer.cs](ImageEnhancer.cs) | 主图增强 | 只接受 8 位编码（Bgra32/Rgb24/Rgba8；误传 F16 等显式抛出不按字节误算）。 确定性"信息归一化"增强预览：全局**限对比直方图均衡（CLHE）**——亮度直方图按 `ClipFactor` 裁剪封顶 + 均匀回填（防断层 / 防大面积同色尖峰独吞输出范围）→ cdfMin 归一化 LUT → **保色度重建** `ch' = Y' + s·(ch − Y)`（YCbCr 恒定色度，`s = SaturationScale`）。该式结果亮度恒等于 `LUT[Y]` → 亮暗关系严格单调、色相不变；`s=1` 保**绝对**彩度，暗部彩度不随亮度塌缩发灰（取代旧的 `(newY+ε)/(oldY+ε)` 等比增益——那只保**相对**饱和度，暗部彩度仍随亮度趋零而发灰，且加性重建无除法故 ε 取消）。极端亮/暗处绝对彩度越界时逐像素把 s 收到"恰好不越界"，物理最小去饱和、无硬钳位。手感参数 `ClipFactor`（保守↔激进，默认 2.0）+ `SaturationScale`（默认 1.0）。纯算法、不改原文件、不入库；旧壳由 `ImageViewModel` 的增强 toggle 在后台调用，原生壳由 `PhotoLoadSession` 调用（算法只在 8 位 sRGB 口径上有定义，F16 表面经 sRGB 往返一次）。**两遍逐像素阶段按行并行、直方图分区统计后整数合并**（合并结果与串行完全一致）；`Enhance(source)` 拷贝后处理，`EnhanceInPlace(image)` 直接在调用方独占的 8 位缓冲上处理（省一次整图拷贝，输出逐字节等同）。输入输出均为 `DecodedImage`。设计意图 / 选型理由见 plan-3-1 §1.2。 |
| [HistogramRenderer.cs](HistogramRenderer.cs) | 直方图渲染 | 8 位档按存储通道计数（Bgra32/Rgb24/Rgba8；Rgba8 已是 Display P3 编码值，与 F16 档"线性→sRGB 编码后量化"同一显示参考口径），其余编码显式抛出。 把 `DecodedImage` 渲成 RGB 256 级直方图图像（透明底 + 三通道纯原色叠加填充曲线，重叠取 max → 三色重叠恰为白）。纯算法；分析栏"直方图"瓦片用它从当前主图（原片或增强图）现算，随增强切换实时重算，透明底让 DiagnosticTile 的 #222 透出。P2 起直接支持原生 F16 线性表面（按线性→sRGB 编码后量化，与 8 位口径可比），避免为直方图把整幅大图转成 8 位。 |
| [BitmapPrefetcher.cs](BitmapPrefetcher.cs) | 预加载器 | Background prefetch of N neighbours around the current image. latest-wins(新请求取消旧轮 CTS);每张邻居一个 P2 工作项投递 `DecodeScheduler`(构造时把 `Settings.NativePreloadParallelism` 同步为调度器并发度,Warning 压力降为 1)。**P1-M4b 分级预取**:±1 邻居取 Full(变焦连续),其余取代理档(`BitmapLoader.ProxyTargetLongEdge` 由 ImageViewModel 下发);Caution 压力/恢复观察期投递即空跑。邻居位图解码完成后,若分析栏可见,顺手为该邻居 `AnalysisDataReader.ComputeFingerprintAsync` + `AnalysisComputer.Compute` 落进 `AnalysisResultCache` — 让前后切图变成纯 UI swap。 |
| [DecodeScheduler.cs](DecodeScheduler.cs) | 统一优先级调度器 | 静态类。P0 当前照片(立即独立执行 + 在途标志,`TrackP0` 供主图解码路径上报)/ P1 可见缩略图 / P2 预载 / P3 杂项;同 key 去重 + 高优先级请求可提升队列中项的优先级;后台 worker 按 `MaxBackgroundParallelism` 并发,P0 在途时暂停取新工作(已在跑的不打断)。收编缩略图加载与位图预取两条通道。 |
