# PhotoViewer.Mac — 原生壳

macOS 头工程只提供 AppKit + Metal 原生壳：Debug 与 Release 都从 `Program.cs` 直接进入原生启动，不再有 Avalonia 旧壳入口或构建通道分流；历史 `--native` 参数会被原生路径无害忽略。构建/运行仍走根 DEV.md 的 Tasks。

**共享源**：展示解码器、Metal 渲染核心、命令符号与手势映射在 `../PhotoViewer.Apple/`（纯源目录，由 csproj `<Compile Include="..\PhotoViewer.Apple\**\*.cs"/>` 链接编译，见 [其手册](../PhotoViewer.Apple/AGENTS.md)）；视口/主屏/胶片栏/控制栏/分析栏/相似面板/EXIF 表几何与命令表在 `../PhotoViewer.Shared/`（见 [其手册](../PhotoViewer.Shared/AGENTS.md)）。本壳只保留 AppKit 宿主：事件、命中测试、图层挂载、原生控件的 frame 落位与系统图标对象。改动共享源后必须复跑本壳八套 `--pv-native-*` 回归。

**发行版本**：显式 `PhotoViewerEdition=standard` 构建标准版 `PhotoViewer.app`，不编译相似面板、DINO 诊断与 ONNX 依赖；`ai` 构建 `PhotoViewer AI.app`（显示名含空格；分发包文件名仍用 `PhotoViewer-AI`），内置固定模型和 DINOv3 License。标准版保留 CV 分析、三瓦片 CV 诊断与独立「即时计算 CV」；AI 版保留 DINO/相似聚类，并分别提供「即时计算 DINO / CV」。下文 DINO、相似聚类及五瓦片诊断描述均指 AI 版。Bundle ID 分别为 `cc.xiaojh.PhotoViewer` / `cc.xiaojh.PhotoViewer.AI`，不使用 `.Mac` 后缀；两版可并存安装和同时运行，私有状态与激活目标各自独立，通用设置及可复用分析数据走显式产品族共享区。两版在 `bin/<standard|ai>/` 与 `obj/<standard|ai>/` 下完全隔离，引用的共享工程 `PhotoViewer/` 同规则（由根 `Directory.Build.props` 在默认 obj 之前求值决定），不要用 `dotnet publish -o` 掩盖输出目录共享；命令行构建、运行与发布都必须显式传 `-p:PhotoViewerEdition=standard|ai`，缺失时构建报错，而不是让共享工程落到另一套还原资产。构建只改写 `obj/<edition>/…/Info.plist` 副本（版本号、构建号、产品名、Bundle ID），`AppBundleManifest` 指向该副本，仓库源 `Info.plist` 不被构建改动，两版来回构建互不影响。`publish.sh --edition standard|ai|both` 显式发布两个变体，版本与构建号只取根 `Directory.Build.props`（兼容位置参数但与之一致才继续）；正式路径在 `artifacts/acceptance/mac-editions/<edition>-publish.json` 保存机器可读签名/公证证据并检查 notary status，DMG 只读挂载后核对卷内实际 `.app`；`--local` 只做 adhoc 构建、扫描与 DMG 装载验证，不签名 Developer ID、不公证、不写入 `release/packages`。`Tools/check-mac-package.py` 扫描实际 `.app`：包目录名与 `Info.plist` 身份（产品名、版本号、构建号、Bundle ID、可执行文件名）、主程序 arm64 可执行头、模型字节与 SHA-256、DINO 许可证、托管/原生推理资产，并拒绝标准版的模型、ORT、MathNet 与许可证残留以及两版互换 Bundle ID；版本号/构建号缺省取根 props，可显式传 `--version` / `--build-number`，`--self-test` 覆盖正反判定。签名前目标会清除 AI 版误带的 Windows ORT DLL，以及标准版增量构建残留的 DINO 资产，属防御性清理，不代替目录隔离。

| 文件/目录 | 职责 |
|---|---|
| Program.cs | 原生 AppKit 启动入口，直接交给 `MacNativeApplication.Run`。 |
| Core/MacHeifDecoder.cs / MacRawDecoder.cs | 缩略图与兼容解码路径，维持 8 位口径。HEIC/HEIF（不含 `.hif`）长边请求 ≤512 优先 ImageIO 内嵌小图，尺寸必须达到 `min(请求, 源长边)`，比例/显示朝向不符或失败即回退原图；更大请求和 RAW 复用 helper 默认保持 FromImageAlways。主图展示解码不走此入口。 |
| Core/MacMemoryBudgetProvider.cs | macOS 预算源：预算 = 物理内存 × 50%，可用 = 预算 − 进程驻留（`AppleMemoryFootprint` 的 phys_footprint，含 Metal/IOSurface），并把驻留量作为 `GetFootprintBytes` 供缓存推导有效容量；`GetSystemMemoryInfo` 给整机口径（总内存取 `NSProcessInfo.PhysicalMemory`，可用取内核 free + inactive 页估算并夹到总量，读不到页统计时可用量为 -1 表示未知，不拿进程预算或 `os_proc_available_memory` 冒充）。`MacNativeApplication` 注入它（Windows 仍用 `DefaultMemoryBudgetProvider`）。 |
| Core/MacOpenPaths.cs | 命令行、Finder/Dock/«打开方式»、窗口拖入的路径 → 共享 `LocalFileRef`/`LocalFolderRef`，再投递实例级 `OpenRequestChannel`；本地存储直接用共享 `LocalStorageRefs`，没有 Mac 专属存储引用或安全作用域书签。 |
| Core/MacPresentationEncodingPolicy.cs | Mac 展示编码策略：任何尺寸档与压力级别都返回 RGBA16F 扩展线性 sRGB（iPad 的 8 位 P3 路径只在 iOS 策略启用）。共享展示解码器对 HEIC/HEIF/HIF 的 ≥4MP F16 产物用 Core Image 转换，保留 ImageIO 缩解码与既有源尺寸/方向；JPEG、小图仍位图绘制。 |
| Native/MacNativeApplication.cs | AppKit 生命周期、ReactiveUI builder、平台门面（含 `MacMemoryBudgetProvider` 预算源）；设置仓库用 `AppleSettingsStore`（冒烟用隔离 `FileSettingsStore`），界面状态用 `AppleViewStateStore`；Finder/Dock/URL 经 `MacOpenPaths` 投递 `OpenRequestChannel`，由 `OpenCoordinator` 单消费者处理，`Main.Dispose` 参与关闭。 |
| Native/MetalPhotoView.cs | AppKit 宿主：把共享 `MetalPhotoRenderer.Layer` 作为视图图层，包原生事件（捏合/滚轮/拖动/按键）为共享 `PhotoViewport` 操作；照片平移只接受本视图未被标题栏接管的按下所启动的拖动，抬起结束，窗口拖动不得改变照片视口。并暴露物理倍率、导航图几何与 GPU 帧读回给窗口与验收。`SetImage(image, generation)` 用 `PhotoLoadSession.Generation` 与源尺寸/方向共同判定切图：代际变化一律走切图语义（STATE-01 缓存命中切图不经过空图，同机型连拍的身份完全相同），同代际下的身份变化是元数据纠正也走切图；同一实例 + 同代际只重绘、不重传纹理，同一实例 + 新代际不重传但按切图重新定位。线性层标签、F16 纹理、mipmap、GPU EXIF 方向与视口数学见 [PhotoViewer.Apple](../PhotoViewer.Apple/AGENTS.md)。 |
