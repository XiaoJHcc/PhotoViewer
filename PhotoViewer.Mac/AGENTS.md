# PhotoViewer.Mac — 原生壳

macOS 头工程只提供 AppKit + Metal 原生壳：Debug 与 Release 都从 `Program.cs` 直接进入原生启动，不再有 Avalonia 旧壳入口或构建通道分流；历史 `--native` 参数会被原生路径无害忽略。构建/运行仍走根 DEV.md 的 Tasks。

**共享源**：展示解码器、Metal 渲染核心、命令符号与手势映射在 `../PhotoViewer.Apple/`（纯源目录，由 csproj `<Compile Include="..\PhotoViewer.Apple\**\*.cs"/>` 链接编译，见 [其手册](../PhotoViewer.Apple/AGENTS.md)）；视口/主屏/胶片栏/控制栏/分析栏/相似面板/EXIF 表几何与命令表在 `../PhotoViewer.Shared/`（见 [其手册](../PhotoViewer.Shared/AGENTS.md)）。本壳只保留 AppKit 宿主：事件、命中测试、图层挂载、原生控件的 frame 落位与系统图标对象。颜色、圆角与字号一律取 `DesignTokens`（颜色经 `MacDesignColors.Argb` 转 AppKit 色），不在本壳手抄色值与尺寸常量。改动共享源后必须复跑本壳八套 `--pv-native-*` 回归。

**发行版本**：显式 `PhotoViewerEdition=standard` 构建标准版 `PhotoViewer.app`，不编译相似面板、DINO 诊断与 ONNX 依赖；`ai` 构建 `PhotoViewer AI.app`（显示名含空格；分发包文件名仍用 `PhotoViewer-AI`），内置固定模型和 DINOv3 License。标准版保留 CV 分析、三瓦片 CV 诊断与独立「即时计算 CV」；AI 版保留 DINO/相似聚类，并分别提供「即时计算 DINO / CV」。下文 DINO、相似聚类及五瓦片诊断描述均指 AI 版。Bundle ID 分别为 `cc.xiaojh.PhotoViewer` / `cc.xiaojh.PhotoViewer.AI`，不使用 `.Mac` 后缀；两版可并存安装和同时运行，私有状态与激活目标各自独立，通用设置及可复用分析数据走显式产品族共享区。两版在 `bin/<standard|ai>/` 与 `obj/<standard|ai>/` 下完全隔离，引用的共享工程 `PhotoViewer/` 同规则（由根 `Directory.Build.props` 在默认 obj 之前求值决定），不要用 `dotnet publish -o` 掩盖输出目录共享；命令行构建、运行与发布都必须显式传 `-p:PhotoViewerEdition=standard|ai`，缺失时构建报错，而不是让共享工程落到另一套还原资产。构建只改写 `obj/<edition>/…/Info.plist` 副本（版本号、构建号、产品名、Bundle ID），`AppBundleManifest` 指向该副本，仓库源 `Info.plist` 不被构建改动，两版来回构建互不影响。`publish.sh --edition standard|ai|both` 显式发布两个变体，版本与构建号只取根 `Directory.Build.props`（兼容位置参数但与之一致才继续）；正式路径在 `artifacts/acceptance/mac-editions/<edition>-publish.json` 保存机器可读签名/公证证据并检查 notary status，DMG 只读挂载后核对卷内实际 `.app`；`--local` 只做 adhoc 构建、扫描与 DMG 装载验证，不签名 Developer ID、不公证、不写入 `release/packages`。`Tools/check-mac-package.py` 扫描实际 `.app`：包目录名与 `Info.plist` 身份（产品名、版本号、构建号、Bundle ID、可执行文件名）、主程序 arm64 可执行头、模型字节与 SHA-256、DINO 许可证、托管/原生推理资产，并拒绝标准版的模型、ORT、MathNet 与许可证残留以及两版互换 Bundle ID；版本号/构建号缺省取根 props，可显式传 `--version` / `--build-number`，`--self-test` 覆盖正反判定。签名前目标会清除 AI 版误带的 Windows ORT DLL，以及标准版增量构建残留的 DINO 资产，属防御性清理，不代替目录隔离。

| Program.cs | 原生 AppKit 启动入口，直接交给 `MacNativeApplication.Run`。 |
| Core/MacHeifDecoder.cs / MacRawDecoder.cs | 缩略图与兼容解码路径，维持 8 位口径。HEIC/HEIF（不含 `.hif`）长边请求 ≤512 优先 ImageIO 内嵌小图，尺寸必须达到 `min(请求, 源长边)`，比例/显示朝向不符或失败即回退原图；更大请求和 RAW 复用 helper 默认保持 FromImageAlways。主图展示解码不走此入口。 |
| Core/MacMemoryBudgetProvider.cs | macOS 预算源：预算 = 物理内存 × 50%，可用 = 预算 − 进程驻留（`AppleMemoryFootprint` 的 phys_footprint，含 Metal/IOSurface），并把驻留量作为 `GetFootprintBytes` 供缓存推导有效容量；`GetSystemMemoryInfo` 给整机口径（总内存取 `NSProcessInfo.PhysicalMemory`，可用取内核 free + inactive 页估算并夹到总量，读不到页统计时可用量为 -1 表示未知，不拿进程预算或 `os_proc_available_memory` 冒充）。`MacNativeApplication` 注入它（Windows 仍用 `DefaultMemoryBudgetProvider`）。 |

- Metal 缓存验收：`--pv-native-smoke --pv-native-texture-cache`（无需打开素材）执行共享 `AppleTextureCacheChecks`，覆盖真实 GPU 像素、八方向、LRU/字节上限、失败保留旧图、空图、并发修剪与弱引用租约；报告 `native-texture-cache-checks.txt`。宿主的 `Trim` 只置标记并派主线程清理非当前纹理。
- 批量提取吞吐验收：AI 版 `--pv-native-smoke --pv-native-batch <自有 JPEG>` 执行共享 `AppleBatchThroughputChecks`，覆盖 Caution→Warning、8 组三路落库、进度、墙钟与内存峰值；报告 `native-batch-throughput.txt`，素材复制到隔离验收目录并在收尾删除。
- 解码优化对照：`--pv-decode-optimize <目录>` 在主窗口创建前执行共享 `AppleDecodeOptimizationProbe`，以独立设置/数据库运行，不把素材目录交给打开链路。报告在 `artifacts/acceptance/apple-decode-optimization/probe.txt`，完成按结果退出；源照片只读。追加 `--pv-perf-components-only` 可在同一隔离入口运行旧分段探针，报告 `perf-components.txt`，上传与纹理缓存命中分列，避免并行启动主窗口污染测量。
- 图片：共享 PhotoLoadSession 持租约，视图同步上传后只持 GPU 纹理。原生模式不创建 WriteableBitmap 副本；缓存/准入/预取复用 BitmapLoader。
- **索引路径生命周期（胶片栏/相似面板/工具表）**：`NSIndexPath` 由 Foundation 规范化，同一 (item, section) 每次创建都回同一个原生实例，.NET 运行时按句柄复用同一托管包装；`FromItemSection`/`FromRowSection` 的结果只作局部变量与调用参数，一律不 `Dispose`/不 `using`（释放会把 AppKit 回调参数与验收持有的同一包装一起清句柄，`GetItem`/`CellForItem` 等取句柄入口随后抛 `ObjectDisposedException`），也不手工 retain 或缓存（对象表已按句柄复用，包装交 GC）。胶片栏验收在重入布局前后核对调用方持有的包装句柄不变，作为该约束的回归点。
- 相对命令行路径用启动 PWD 解析，SDK 会改变工作目录；验收输出不能写进 .app，避免破坏签名。
- 冒烟套件共用 `artifacts/acceptance/native-p2-acceptance/settings-smoke.json`：`--pv-native-settings` 收尾会把倍率预设留在「剩 1 项」，下一次 `--pv-native-layout` 因此没有更低预设可跳。连跑多套前先删除该文件（或把 settings 放到 layout 之后），否则 layout/settings 都会误报失败。
- 从后台 shell 启动冒烟进程时 macOS 不给应用激活：`NSApplication.Activate()` 不生效、`KeyWindow` 为空。设置套件因此按窗口号经 `NSApplication.WindowWithWindowNumber` 取窗口并置前，不依赖应用激活（`NSApplication.Windows`/`IsActive` 在当前绑定不可用）。
- 构建基线：Debug 与 Release 均 0 错误。已知既有警告类别（不阻塞，清理需另立条目）：CS0414（`MacExifDetailView._measuredWidth` 未使用）、CS0114（`ExifTagCellView.Tag` 隐藏 `NSView.Tag`）、CS0672（`NSCollectionViewDataSource.GetNumberofItems` 过时重写）、CS8604（`MacUiServices` 的 `Path.Combine` 可空参数）、CS0618（`NSPasteboardTypeString` 过时）、IL2075（`NativeFaultAcceptance` 反射裁剪警告）；Release 另出现 IL2026 / IL2037 / IL2104 裁剪分析警告与 Swift `showsBaselineSeparator` 弃用，裁剪类来自 ReactiveUI/DI 的反射路径，只在 Release 链接启用时出现。
- 帧导出证明原生布局与 GPU 渲染，不等同于 WindowServer 跨屏色彩对拍。真实产品验收项目见 Plans/native-rebuild-phase-2-acceptance.md；未关闭项见该文首「作者验收结论」。
