# PhotoViewer.iOS — UIKit 原生壳

Debug 与 Release 都只启动 **UIKit 原生壳**（不创建旧壳对象）；历史启动参数 `--native` 不再参与壳选择，传入时按普通参数忽略。最低系统版本 **iOS 26**。执行清单与程序化证据见 [Plans/native-rebuild-phase-ipad.md](../Plans/native-rebuild-phase-ipad.md)，实现状态见 [Design/status.md](../Design/status.md)，作者手验步骤见 [Plans/native-rebuild-phase-ipad-acceptance.md](../Plans/native-rebuild-phase-ipad-acceptance.md)。

**工具链**：Xcode 27.1 + .NET SDK 10.0.402 + ios workload 27.0.10722；该 workload 的精确 Xcode 校验不认 27.1，两个 Apple head 的 csproj 设 `ValidateXcodeVersion=false`，见 [DEV.md](../DEV.md) iOS 节。**形态**：主屏按共享 `ScreenFormResolver` 分宽形态与手机形态（竖屏/横屏）——iPhone 设备、设置里的「手机」模式或任一只紧凑尺寸类别进入手机形态，其余为宽形态；外壳启动期置 `LayoutCapabilities.PhoneLayoutSupported = true`。**排障**：iPhone 的 USB-C 数据链路对 USB 3.0 线缆存在枚举失败，优先怀疑线材（换 USB 2.0 线）。

**原生 UI 约束**：优先采用 iOS 26 公开原生控件与布局区域，未经作者明确允许不得替换系统菜单或改变既有样式。原生路径不能满足交互时回退原状并记录缺口，不以自绘、替代弹层、私有视图或猜测系统安全区/圆角的阈值拟合绕过。

**发行版本**：构建、运行与发布必须显式传 `PhotoViewerEdition=standard|ai`；缺失或非法值直接报错，DINO 能力由 edition 派生。标准版 `PhotoViewer` 不编译相似聚类、DINO 提取及 ONNX 托管/静态原生依赖，保留 CV 分析、三瓦片「CV 诊断」与独立「即时计算 CV」；AI 版 `PhotoViewer AI`（显示名空格，分发 IPA 文件名前缀 `PhotoViewer-AI`）内置固定模型和 DINOv3 License，并提供独立「即时计算 DINO / CV」。下文 DINO、相似聚类及五瓦片诊断均指 AI 版。Bundle ID 分别为 `cc.xiaojh.PhotoViewer` / `cc.xiaojh.PhotoViewer.AI`，执行文件 `PhotoViewer.iOS` 与应用目录 `PhotoViewer.iOS.app` 保持既有约定；两版使用独立 App ID、描述文件、App Store Connect App 和 TestFlight/App Store 轨道，可同机并存，设置、数据库、缓存与日志各自位于独立沙盒，不提供产品内切换。头工程及共享工程的 `bin/<standard|ai>/`、`obj/<standard|ai>/` 隔离；构建从源模板生成中间目录 `Info.plist`（版本、构建号、产品名、Bundle ID），不改写仓库模板。发行能力与数据边界见 [EDITION](../Design/spec/editions.md)，开发和发布入口见 [DEV.md](../DEV.md)。

**启动参数来源**：iOS 不填充托管 `Main(string[] args)`（实测为空数组），一律读 `NSProcessInfo.ProcessInfo.Arguments`（`simctl launch <udid> <bundleId> <args…>` 会传入）。

**共享源**：`../PhotoViewer.Apple/` 纯源目录由 csproj `<Compile Include="..\PhotoViewer.Apple\**\*.cs"/>` 链接编译（展示解码器、Metal 渲染核心、验收判定、命令符号与手势映射），与 [PhotoViewer.Mac](../PhotoViewer.Mac/AGENTS.md) 共用同一份，见 [其手册](../PhotoViewer.Apple/AGENTS.md)；视口/主屏/胶片栏/控制栏/分析栏/相似面板/EXIF 表几何与命令表在 `../PhotoViewer.Shared/`。本壳只保留 UIKit 宿主。改共享源需同时复核 Mac 的 `--pv-native-*` 回归。

**主图 RAW 解码**：RAW 经 Core Image 的 RAW 引擎（共享 `ApplePresentationDecoder` 内的 `CIRawFilter` 路径）全分辨率解码，代理按视口长边缩渲染、Full 为原生尺寸；几何取传感器原生尺寸（Sony ARW 为 `7008×4672`），EXIF 方向只作为产物方向码交给 GPU，`NeedsFull` 因此能正常升级 Full。ImageIO 的 Sony ARW 内嵌预览（真机 `req=4532 → out=1616x1080`，`SourceWidth` 也读成 1616）只是 `CIRawFilter` 创建/渲染失败时的回退，回退时仍会因 `Width == SourceWidth` 停在预览档（`SCOPE-04@ios`）。缩略图兜底（`DecodeThumbnailAsync`）对 RAW 同样走新路径，出口为显示朝向的 sRGB8。

**主图链路**：`PhotoLoadSession` 只管代际/代理↔Full/租约、增强态；`iOSPhotoView` 把共享 `MetalPhotoRenderer` 挂成 `CAMetalLayer` 子层（绘制目标恒 RGBA16F 扩展线性 sRGB），视口数学取共享 `PhotoViewport`。**缩放/平移采用 UIKit 标准照片缩放模式，滚动视图是唯一交互真源**：`UIScrollView` 内有一个透明缩放内容视图（`ViewForZoomingInScrollView` 返回它承载捏合），其尺寸**只在 `zoomScale=1` 时**写成适应态显示尺寸；视口变换在每个 `DidZoom`/`Scrolled` 回调里由 `zoomScale`/`contentOffset`/`contentInset` 反算（`PullViewportFromScroll`），居中由等量 `contentInset` 给出（`DidZoom` 先更新内边距再派生视口）。程序化缩放（双击、键盘比例/预设缩放、分析栏细节预览定位）一律表达成滚动视图操作（`ZoomToRect`/`SetZoomScale`；锚点用"目标内容矩形中心 + (视图中心 − 触点)/zoom"修正，使触点下的图像点保持不动），不再先写视口再回写滚动视图。**代理↔Full 热替换只换纹理**（同一张照片 ImageSize 恒定：`PhotoViewport.ApplyTexture`，滚动状态一律不动；同一产物引用重复上屏只重绘、不重传纹理）；只有切图（代际变化，或同代际下身份/逻辑尺寸/方向变化；STATE-01 缓存命中切图不经过空图）才 `SetZoomScale(1)` → 写缩放内容视图 frame → 设缩放范围/内边距 → 回适应态。布局/旋转按"同一图像点留在视口中心 + 同一相对缩放"重建基准。**适应区内边距**：`SetFitInsets(UIEdgeInsets)` 把窗口减去栏位与裸按钮后的四边避让交给共享视口与滚动视图——滚动视图仍铺满 `Bounds`，`contentInset` = 避让 + 适应区内的居中补偿（`CenteringInsets`），适应态照片只放进适应区、放大后的平移边界取适应区边缘；值变化时走同一条"布局/旋转"重建路径（适应态重新适应，放大态保持适应区中心下的图像点与相对缩放），程序化缩放与视口中心语义一律取适应区中心（`FitCenter`）；内边距为零时与引入适应区之前逐位一致，`internal FitInsets`/`FitRect` 供外壳与验收读取。**不得回到的三种写法**：① 对带缩放变换的缩放内容视图写 `Frame`——`contentSize` 会崩掉、偏移被钳向 (0,0)，真机表现为"放大后照片被拽到左上角"（增强开关/升 Full 同样会触发）；② 先 `SetZoomScale` 再 `SetContentOffset`——两者互相取消，程序化缩放只用单条 `ZoomToRect`；③ 增强/换档与缩放共用同一条重排路径。**导航图（缩放指示器）**：非适应态且设置开启时显示在主图区右下角（安全区内、避让控制栏/分析栏），`color.nav.background` 0.6 不透明度圆角 6 宿主 + GPU 小目标渲染的缩略图（长边 150、按显示朝向比例）+ 白色 1 点可见框（`PhotoViewport.NavigationViewport`）+ 物理缩放百分比（与 Mac 同口径）；小图只在展示图引用变化时重出。指示器的显示/隐藏、宿主位置与白框几何都在关闭隐式动作的 `CATransaction` 内一次写完（先几何后显示），因此不会出现首次从左上角飞入或白框缓慢位移的过渡；只作用于指示器子树，不改全局动画开关，滚动视图的缩放动画照常播放。**导航图白框可拖动定位（IMAGE-06，四端一致）**：按下框内保留抓取偏移、按在缩略图其他位置先移框心，均经 `CenterOnNormalizedPoint` 落到滚动偏移。**增强计算反馈**：主图区底部中央显示 `计算中…` 药丸，绑共享 `PhotoLoadSession.IsEnhancingVisible`（500ms 门槛），增强图上屏/失败/取消后收起。**状态提示（STATE-01/STATE-03/IMAGE-03）**：加载提示绑 `PhotoLoadSession.IsLoadingVisible`（300ms 延迟态）；评分写回失败、Full 升级失败、内存自动关闭增强与打开失败（STATE-02）共用主图区底部 `iOSStatusToast`（令牌宽/色/圆角、`motion.status.toast.duration` 自动消失、新替旧、不拦手势；与「计算中」药丸同时可见时整体上移到药丸上方）；屏上有代理时 Full 失败只走提示条，不覆盖「无法打开该图片」。**编码协商**：`iOSPresentationEncodingPolicy` 给代理档 RGBA16F、Full 档 8 位 Display P3、压力 ≥ Warning 时代理档也降 8 位 P3；准入估算与纹理记账按实际编码的每像素字节（Full 档 4 字节）。**启动顺序硬要求**：必须先上报有效视口再 `SetFile`（`iOSNativeRootViewController.StartSession` + `PhotoLoadSession.UpdateViewport` 的零尺寸守卫），布局前的文件变化只更新当前文件，避免代理目标尚未建立时直接解 Full、随后又被首轮布局取消重解。

**切图 / Fit / 双击**：语义一律由共享 `PhotoViewport` 决定，宿主只把结果表达成滚动视图操作。
- **双击**：`PhotoViewport.ToggleFit(触点)` —— 适应态以触点为中心到物理 100%，放大态回适应（与原 Avalonia 壳 `ToggleFit(center)` 同一语义）；动画用一条 `ZoomToRect`。
- **Fit 命令（控制栏按钮 / 热键）**：`PhotoViewport.ToggleFit(null)` —— 适应态优先以照片的 Sony 对焦点为中心到物理 100% 并开启跟随，**无对焦点才取视口中心**；已放大时回适应。不得写成无条件 `FitToView`：适应态按 Fit 必须切到物理 100%，已放大回适应。
- **切图保持位置**：`iOSPhotoView.SetImage(image, generation)` 在加载代际变化（含 STATE-01 缓存命中切图）或同代际的照片身份/方向/尺寸变化时不再重置到适应态，而是 `BeginImageChange` + `ApplyImage`（适应态重新适应；`FollowsFocus` 时保持倍率并居中到新照片对焦点；否则保持倍率与同一归一化中心点），再按视口状态重建滚动基准。代理↔Full 仍是 `ApplyTexture`（滚动状态一律不动）；几何基准恒为全分辨率 `SourceWidth/Height`，所以放大态切图后的新照片先代理后 Full 不会跳。
- **100% 口径**：1 源像素对 1 屏幕物理像素；素材本身小于视口物理像素（例如 RAW 回退到 iOS 内嵌预览时的 `1616×1080`，在 iPad 上适应态已 ≥ 100%）时没有向上余量，双击/Fit 会**夹回适应态**（`SyncScrollFromViewport` 显式夹取，避免视口比滚动视图更小）。
- **视口通知**：程序化改视口（Fit/双击/预设/细节定位）后 `SyncScrollFromViewport` 必须显式 `ViewportChanged`——滚动视图派生出的状态可能与目标一致（`Pull` 判定"无变化"），不通知会漏掉导航指示器刷新与 Full 升级（Fit 后 `NeedsFull` 由 true 变 false 也必须上报）。
- **滚动基准补建**：首图上屏早于视图布局时 `SyncScrollFromViewport` 写不出 `contentSize`/缩放范围，标记 `_scrollGeometryValid=false` 并由下一次 `LayoutSubviews` 补建（直接返回会让 `MaximumZoomScale` 停在 1，双击/捏合几乎不动）；推迟期记一条 `[Native] 照片上屏时视口尚未布局…` 日志。

**主屏布局**：主图分区与 `iOSPhotoView` 恒为整个根视图，栏位与按钮作为浮层压在主图上，根视图背景取 `color.viewer.background`；栏背景一律是系统深色模糊材质（`UIBlurEffectStyle.SystemMaterialDark`），不手调透明度、圆角或阴影，旧控制栏文档与分析面板本身透明。**形态判定**每个布局都走共享 `ScreenFormResolver.Resolve`（两轴尺寸类别、窗口宽高、是否 iPhone 惯用法、设置里的布局模式与平台能力），并登记 `UITraitHorizontalSizeClass` / `UITraitVerticalSizeClass` 变化触发重排；旋转、分屏与台前调度靠尺寸变化与现有 `ViewDidLayoutSubviews` 覆盖。形态与手机槽位（`ScreenForm`、`PhoneLayout`、其输入与刘海左右）留在根控制器供验收读取，`AvoidanceTuningOverride` 只替换行内间距令牌；`FitInsetsOverride` 供适应区演练固定内边距。**宽形态**沿用共享 `MainScreenLayout` + `iOSMainScreenLayout` 的两向分区（上下/左右/自动），主图按分区 `Photo` 矩形设适应区四边避让。上下布局的栏位内容收在安全区内，横屏统一不扣底部手势条；左右布局的内容纵贯窗口上下缘——只有左上角筛选/更多浮动组按自身列位置的窗口控件带向下让位，胶片条从窗口顶边通到底（首张靠内容留白停在筛选带下方，滚动时从按钮下经过，边缘效果交给系统），右侧控制栏与分析栏不扣上下安全区、EXIF 开关关闭时筛选与更多上移进刘海/灵动岛两旁的耳区）、横屏刘海侧列（有胶片栏时筛选更多合体在列顶端，胶片栏关闭让出整列后拆成刘海上下两旁的独立圆按钮）；胶片栏开关管胶片条（横屏另含刘海侧列下端的上下张），控制栏开关管竖屏底行（上下张合体 / 星级控件 / 缩放适应+雾天增强合体）与横屏控制栏，手机 EXIF 开关管 EXIF（竖屏单独决定，横屏还须控制栏可见）。横屏下巴侧是桌面式控制栏：自上而下 EXIF 列（无衬底、只按整项显示放得下的前几项）、星级控件（先保住紧凑态最短长度）、缩放适应/雾天增强竖排合体；三者同轴，整组在原生圆角适应区内纵向居中，星级槽位不超过展开态固有长度，不把按钮固定推到底部；按钮外缘距窗口缘 `shell.phone.edgeMargin`、不避让系统对称安全内缩，右侧栏背景（`slots.TrailingBar`，单个连续材质视图）在有分析栏或实际可见 EXIF 时从最内侧栏缘铺到窗口外缘，只有单独显示不带 EXIF 的控制栏时透明。**安全区按带探测**：系统安全区先按方向归一（所有横屏去掉底部手势条，竖屏不变）再交给共享几何，另用舞台上的安全区与独立圆角两块不可见探针，按元素实际位置逐带读取 iOS 26 `UIViewLayoutRegion`：安全区区域保留刘海与窗口控件，边距区域在不继承祖先边距、不从安全区补边距、显式边距为零时提供独立圆角适应；横屏底缘直接用后者，不比较或扣除 Home 基线，并换算成绝对窗口缘距离——竖屏顶行在 `PhoneScreenLayout.TopRowY` 给出的行位置**分左右两半**探测（整条横带会跨过灵动岛），竖屏底行、横屏 `LeadStripWidth` 刘海侧列与横屏 `ControlStripWidth` 下巴侧控制栏各探自己那一条、互不沿用；其余各边取系统安全区。日志 `[Native] 手机形态安全区 …` 打印系统安全区与两条带。刘海在左为 `LandscapeRight`，其余按在左（右向整体镜像）。胶片条轴向只由形态决定（竖屏横向、横屏纵向），换向仍显式定位当前项。空态/加载/错误提示、计算中药丸、STATE-03 **索引路径生命周期（全部 UIKit 代码）**：`NSIndexPath` 由 Foundation/UIKit 规范化——同一 (item, section) 每次创建都返回同一个原生实例，.NET 运行时按句柄复用同一个托管包装；任何一处 `Dispose()`/`using` 都会把 UIKit 回调参数、布局属性与其他持有者的包装一起作废（句柄清零），随后 `CellForItem`/`ScrollToItem` 等取句柄的入口抛 `ObjectDisposedException`（object name `Foundation.NSIndexPath`）。索引路径只作局部变量与调用参数：`FromItemSection`/`FromRowSection` 的结果一律不释放、不手工 retain、不做全局缓存（运行时对象表已按句柄复用，包装交给 GC 回收）。布局验收在滚动/布局前后核对调用方持有的包装句柄不变，作为该约束的回归点。

## 分析栏、相似聚类、工具页与增强预览（共用 Mac 的 presenter）

- **分析栏**：`iOSAnalysisHost` 实现共享 `IAnalysisHost`，`iOSAnalysisPanel` 消费 `AnalysisPresenter`（只读库快路径 / 增强联动 / 未提取回退全部复用，不复制编排）。宿主分别提供 `ImmediateCompute`（DINO）与 `ImmediateCvCompute`（CV），各自读独立设置并响应对应属性通知；标准版只读取/派生 CV，现算只进内存、不写特征库，不读取 DINO patch。瓦片是 UIKit 版 `iOSDiagnosticTile`（外框 `#222`/`#444` 1 点/圆角 6、内层圆角 5 裁切、AspectRatio letterbox、主图图层最近邻放大、背景 alpha 0.30、药丸角标、底部说明、占位、准星、叠加槽位）与 `iOSDetailPreview`（指针 hover 与直接触控 Down/Move/Up/Cancel 进入同一个活动目标状态机；按下立即点亮、滑入另一细节瓦片切换、移出/抬起/取消立即清除，不使用延迟长按或定格；双击独立定位裁剪中心到物理 100%）。`iOSAnalysisPanel` 以输入所有者标识隔离过期事件，保持最多一张活动瓦片；直接触控按住期间hover不得抢占，抬起/取消清除，后续新的hover事件才可重新建立活动目标；换图、隐藏、应用失活清空活动目标，辅助技术提供显示/清除动作。`iOSDiagnosticTile.HitTest` 使用 UIKit 本地坐标并由瓦片自身接收触摸，装饰/叠加子视图不截事件；诊断内容点按落共享准星，角标/letterbox/边框清准星，直方图吞掉点按而不改准星。**自绘瓦片必须 `ContentMode = Redraw`，装饰层必须 `Opaque = false`**（否则首帧以 1×1 内容被拉伸、装饰层以黑色盖住图像）。几何取共享 `AnalysisPanelGeometry`；细节裁剪按 `DisplayCrop` 从展示会话取源，F16 代理与 8 位 P3 Full 都转成显示朝向 sRGB8。分析栏可见时视口上报 `NeedsFull`，主图升 Full。
- **增强预览**：控制栏命令/主图菜单走 `PhotoLoadSession.ToggleEnhanced()`，跨切图持续生效；算法只在 8 位口径有定义——会话把展示产物转 sRGB8 **副本后就地**做 CLHE（`ImageEnhancer.EnhanceInPlace`：两遍逐像素阶段按行并行、直方图分区统计后整数合并，输出与旧串行实现逐字节一致），再回到源展示编码：**8 位 Full 档回 8 位 Display P3**（不再扩大成 F16，24MP 省约 96MB 与一次整图转换），F16 线性表面（Mac 全档、iPad 代理）仍回 F16 线性 scRGB；失败不静默回退（记日志、`IsEnhancing` 归 false、提示收起）。`PhotoLoadSession.IsEnhancingVisible`（500ms 门槛）驱动主图上的 `计算中…` 药丸。**验收必须比较增强前后的 GPU 帧像素**（`EnhancementAcceptance`：确定性低对比度 JPEG + 平均绝对差 ≥6、最大差 ≥30，关闭后还原）——只断言 `EnhancedDisplay` 无法区分「增强未上屏」与「高对比素材视觉差异小」。**方向断言**：EXIF 6/8 真实夹具与一张 4000×3000 的 EXIF 6 素材（走 8 位 P3 Full）都必须保持增强前后"方向 + 源尺寸 + 导航帧四角颜色分类"一致（方向丢失时画面会转 90°）；`--pv-native-gesture-check` 另断言增强开关前后滚动状态与视口变换逐项不变。**性能**：csproj 为 `MtouchInterpreter=-all`（全部程序集 AOT，解释器只作动态代码回退）。真机 Release 实测数据与提速门见 [性能专项](../Plans/apple-performance-memory-plan-1.md)，不以模拟器结果替代。
- **相似聚类**：`iOSSimilarityPanel` 复用 `iOSFilmstripLayout` + `iOSThumbnailCard`（第二行 `NN%` + 75% 起柱状条，选中取 `IsCurrentImage`），空态/动作区/进度/未提取计数/错误文本全部读共享 `SimilarityPanelViewModel`（列表态错误显示在停靠动作区，SIM-10）；行布局按共享 `SimilarityPanelGeometry.RowWidth` 从胶片栏右侧切出，宽度 = 卡片数 × 96 + 列表内边距 + 描边 + 停靠区自然宽（`DockMeasureWidth()`，只在该动作区实际显示时计入），**相似项增减或停靠区内容（未提取计数 / 动作区 / 错误文案）变化后必须重排主屏**，否则面板停在 106 点、列表被停靠动作区挤成零宽；列布局扩宽文件栏；`提取全部/补齐全部` 走共享批量索引（iOS 上 DINO 走 CPU）。
- **工具页**：`iOSNativeToolsPresenter` 与设置复用半屏 `PageSheet` 配置（medium/large detents、grabber、圆角与滚动扩展策略），以 `UINavigationController` + `InsetGrouped` 原生分组列表承载 EXIF 详情 / DINO 诊断（非 Windows 不建照片统计）。主图菜单初次打开与关闭后重开显示分组工具列表，不为展示列表启动推理；控制栏 EXIF 信息块每次打开都直达 EXIF 详情：已展示 DINO 等其他页时也切换，无可用 EXIF 时回退列表；主图菜单与关闭后重开展示分组工具列表，已展示时只前置并保留当前页（TOOLBAR-06 / TOOLS-01）。工具子页内容按安全区排布，不延伸到导航栏下方，文件名/格式头不被栏材质覆盖；深色取应用级固定深色（导航控制器再显式声明），背景与设置子页同口径（根视图动态 `SystemGroupedBackground`、内部滚动/表格/文档视图透明、卡片 `SecondarySystemGroupedBackground`）。EXIF 用 `InsetGrouped UITableView` + 共享 `ExifTableGeometry` 保持 7 列，原生 configuration 格式按钮与只读可选 `UITextView` 支持长按复制；AI 版 DINO 保持 3+2 瓦片与第六格留空，标准版「CV 诊断」为原图 / 锐度 / 抖动三瓦片同一行；均在网格下方保留整宽原生刚体拟合文本。原生页面按版本消费共享 `DinoDiagnosticPresenter` / `CvDiagnosticPresenter`。导航状态写共享 `ToolsViewModel`；展示写 `IsPresented=true`，关闭（含下滑 `DidDismiss`）写 false 并 `Deactivate()` 取消在途诊断，页面对象保留可重开。

## 星级控件与星级弹窗（RATING-07 / RATING-04）

- **一个控件三处用**：`iOSRatingControl` 常驻在手机竖屏底行、手机横屏控制列与宽形态控制栏评分组（`iOSToolbarView.RatingControl`），根控制器一次接线（写回 `OnControlCommit`、开弹窗 `OpenControlPopup`、共用同一个 `iOSRatingPopup`）；评分、冲突与来源变化只调 `UpdateRatingControls()` 刷新显示值，不重建控制栏。形态、胶囊矩形、格子与紧凑星簇偏移全部取共享 `RatingControlGeometry`，手势判定取共享 `RatingGesture`（一次手势最多提交一次）。手机形态关闭「显示评分」时控件隐藏、槽位保留。
- **展开态**（槽位主轴不小于固有长度 224）：交互式玻璃胶囊内容区里的 `iOSRatingRow`（与紧凑态一样随玻璃按压放大、高亮并与相邻玻璃融合），零时长长按识别器（`CancelsTouchesInView = false`）驱动 `TrackBegan/TrackMoved/TrackEnded/TrackCancelled` 接缝，按下即预览、拖动跟随、交叉轴越出 `rating.gesture.cancelSlop` 即取消；识别器先于滚动视图的平移开始，控制栏滚动容器里拖星不会滚动。逐格 `UIPointerInteraction` 高亮，读屏为可调节元素。
- **紧凑态**：交互式玻璃胶囊内容区里的 `iOSRatingCluster`（五颗星沿胶囊均匀分布、胶囊短时叠压，叠压次序冲突三角最上、1 号星其次、5 号星最下，下层被上层轮廓盖住的部分减淡羽化；放在 `ContentView` 才会随交互式玻璃的按压一起缩放）；按下即请宿主打开弹窗，同一手势转给弹窗单条目星排（延迟预览，取消带取胶囊与面板交叉轴并集），点按保持弹窗、越界抬手收起。冲突时只开来源条目，不转发滑动。
- **冲突**：组级冲突只信共享 `ImageFile.HasRatingConflict`，壳层不另建判定。控件 0 号与卡片 0 号槽位换 `exclamationmark.triangle.fill` + `color.star.conflict`，几何与命中区不变；落在三角上只打开来源条目，不写值、不切主图；控件上落在 1–5 照常整组写入（同值也写，以消解冲突）。
- **弹窗** `iOSRatingPopup`：根视图上的 `UIGlassEffect` 面板 + 全窗透明拦截层（吞掉外部点按并关闭），不用 `UIPopoverPresentationController`——系统浮窗展示期间无法把起手触摸延续到弹窗星排。排版取共享 `RatingPopupLayout`，落位取 `RatingControlGeometry.PlacePopup`（方向 `PopupDirection` 一律朝主图内侧，边界为根视图安全区内缩 `popup.ratingSources.edgeMargin`）。数据与关闭由共享 `RatingSourcesViewModel` 驱动：打开即 `ShowRatingSources`，写入走 `RatingSources.SetRatingAsync`（根控制器 `CommitPopupAsync`），成功且冲突解除时 VM 关闭、弹窗随之收起，失败保留并按真值刷新。另在切图、布局模式或栏位显隐变化、入口移动或隐藏（`Layout()` 末尾 `RevalidateAnchor`）、卡片列表滚动或重载、控制栏滚动与 Esc（`HandleEscapeKey`，`PressesBegan` 共用）时关闭。减少动态效果时只淡入淡出。
- **卡片入口**：胶片栏与相似面板卡片的冲突三角经 `RatingPopupRequested`（锚点为整张卡片）打开来源条目。
- **写回计数与失败**：控件、弹窗与键盘 `SetRatingN` 的每次提交在落盘前触发根控制器 `RatingCommitted`（验收据此计数）；写回失败统一由共享 `RatingWriteFailed` 驱动 STATE-03 提示条，控件回到真值。
- **设置通知按影响范围分流**：根控制器只订阅共享 `SettingsViewModel.PresentationChanged`（`SettingsChangeImpact` 位），诊断/文本属性在共享层即映射为 `None`，壳内不再维护属性名排除名单；`Commands`/`InputBindings` 才作废按住键并重建控制栏，`Rating`/`FileProjection` 才重载胶片卡片，`Layout` 才刷新筛选条与分区几何，`Navigator`/`Analysis`/`Similarity` 只重排几何；控制栏重建前再比对输入摘要，内容未变即就地保留按钮实例、星级控件与控制栏滚动位置。 方向、关闭与写回规则统一见 [RATING-04 / RATING-07](../Design/spec/rating.md)，原生差异见 [platforms](../Design/platforms.md#rating)。

## 验收线索

- **构建基线**：Debug `iossimulator-arm64` 与 Release `ios-arm64` 均 0 错误。已知既有警告类别（不阻塞）：Debug 侧为 CS8601/CS8604 等 nullable 警告；Release 另出现 IL2026 / IL2037 / IL2104 裁剪分析警告，裁剪类来自 ReactiveUI/DI 反射与链接器，只在 Release 链接启用时出现。增量 0 不等于全 clean，新增告警仍需处理。
- **验收范围**：photo / layout / input / analysis / similarity / tools / gesture / faults 分别覆盖展示、布局、输入与失败路径；结果与设备边界见 [Design/status.md](../Design/status.md) 及对应计划。input 套件自行创建并打开 `input-fixtures`，不与指向其它目录的 `--pv-open` 同时运行，避免启动打开请求晚到后覆盖工作副本。
- 原生：`xcrun simctl launch --console <udid> <实际BundleID> [--pv-open <路径>] [--pv-layout-mode row|col|auto|phone] [--pv-analysis-open] [--pv-native-photo-check <目录>] [--pv-native-gesture-check <目录>] [--pv-native-layout-check <目录>] [--pv-native-input-check <目录>] [--pv-native-analysis-check <目录>] [--pv-native-similarity-check <目录>] [--pv-native-tools-check <目录>] [--pv-native-sheet-shots <目录>] [--pv-native-faults-check <目录>] [--pv-dino-check <文件>] [--pv-perf-probe <目录>]`，其中标准版为 `cc.xiaojh.PhotoViewer`、AI 版为 `cc.xiaojh.PhotoViewer.AI`；截图 `xcrun simctl io <udid> screenshot`，日志 `Documents/PhotoViewer/ios-crash.log`（BootTrace marks）+ 控制台；验收报告 `Documents/PhotoViewer/native-{photo,gesture,layout,input,analysis,similarity,tools,fault}-checks.txt`、`native-sheet-shots.txt`、`dino-check.txt` 与性能探针 `perf-probe.txt`。`--pv-analysis-open` 仅用于压测"分析栏可见"条件（启动即展开，测试专用）。历史参数 `--native` 可继续传入，但不参与壳选择。
- 形态验收：`xcrun simctl launch --console <udid> <BundleID> --pv-open form-fixtures --pv-native-form-check form-fixtures --pv-native-ui-snapshots`，另开 `bash PhotoViewer.iOS/form-check-shots.sh <udid> <BundleID> <输出目录>` 轮询阶段文件并按阶段名截图（遇到 `done` 退出）；夹具只需 `Fixtures/jpeg/*.jpg` 拷进 `Documents/form-fixtures`，报告 `Documents/PhotoViewer/native-form-checks.txt`。
- 星级控件验收：`xcrun simctl launch --console <udid> <BundleID> --pv-open rating-control-fixtures --pv-native-rating-control-check rating-control-fixtures --pv-native-ui-snapshots`，需先启动 `form-check-shots.sh`（脚本开头会清掉阶段文件）；夹具同形态验收，`Fixtures/jpeg/*.jpg` 拷进 `Documents/rating-control-fixtures`，报告 `Documents/PhotoViewer/native-rating-control-checks.txt`。
- Metal 缓存验收：`--pv-native-texture-cache-check`（无需素材）执行共享 `AppleTextureCacheChecks`，报告 `Documents/PhotoViewer/native-texture-cache-checks.txt`，核对真实 GPU 像素、方向、LRU/字节上限、失败保留、并发修剪和弱引用租约；宿主 `Trim` 只置标记并派主线程释放非当前纹理。
- 解码优化对照：`--pv-decode-optimize <目录>` 执行共享 `AppleDecodeOptimizationProbe`；追加 `--pv-decode-full` 仅测 JPEG/HEIF 真实 Full 8 位 P3 的串行基线/默认产品/独立行带路径，并额外逐像素校验 P2 两带路径（不计入测速）。相对路径按 Documents 解析，报告在 `Documents/PhotoViewer/decode-optimization.txt`，结尾 `completed=1` 与 `SUMMARY PASS|FAIL`；使用现有验收隔离设置，素材只读，不自动退出。
- RAW 调度验收：`--pv-native-raw-scheduling-check` 无需素材，检查单路、取消、前台优先、票面提升、幂等释放、RAW 提前窗口与 Full 需求下的预取档位，报告 `Documents/PhotoViewer/native-raw-scheduling-checks.txt`。
- 发布验包：`bash PhotoViewer.iOS/publish.sh --edition standard|ai|both [--local]` 走完整 `dotnet publish`，扫描实际 `.app` 与 IPA 内载荷，核对签名、身份、模型契约及 ORT/AOT 符号。本地直装 IPA 只移出顶层 `Symbols/`，不 strip、不改 AOT；符号材料保留在各变体 `publish/`。`--local` 不写 `release/`；正式本地发布的稳定安装源位于 `release/ios-stable/<edition>/PhotoViewer.iOS.app`。
- TestFlight 自动验收：`bash PhotoViewer.iOS/publish-testflight.sh --edition standard|ai --archive-only` 仅本机分发签名归档与校验，不上传；去掉 `--archive-only` 才按本机导出配置上传。一次只归档一个产品，各 App 内构建号独立单调递增且拒绝重复，两个产品可使用相同构建号；归档在 `release/testflight/<edition>/` 各保留最新一份，先 staging 验证、再置换旧归档，失败保留上一份。`validate-testflight-archive.sh [归档路径] --edition standard|ai` 检查实际 Bundle ID 与产物；`check-testflight-device.sh <设备名或 UDID> [次数] --edition standard|ai` 按 edition 核对安装身份、显示名/版本、连续冷启动与新增崩溃报告。设备巡检不代替照片/布局/输入等程序化套件和人工手感验收。
- 布局验收素材：将 `Fixtures/jpeg/*.jpg` 做成至少 24 张独立文件名的自有副本，拷进 app 容器 `Documents/layout-fixtures`，保证大窗口下的端点滚动位移足以区分动画/直接定位；照片检查另用 `photo-fixtures` 并加入 `Fixtures/jpeg-large/color-p3-large.jpg`。布局/input 使用不含同名 RAW/JPG 伴侣的独立夹具目录，避免影响其计数前提；analysis/gesture 另需把 `Fixtures/raw/A7C01489.ARW` 改名为 `focus-src.ARW` 放进对应目录（analysis 据此覆盖两张细节瓦片间滑动）（检查会自建 `gesture-fixtures-work` 工作副本并改写 0x2027 对焦点，输入目录只读）。夹具只放自有素材，评分写回只发生在容器副本内。**两向验收不依赖系统旋转**：iPadOS 拒绝 `requestGeometryUpdate` 改方向（见执行清单发现清单），故用显式 `--pv-layout-mode row|col|auto|phone` + 与真实尺寸/安全区一致的布局数学核对；手机横屏同样由程序化旋转（后续阶段）或真机手验覆盖。
- 真机（devicectl）：`xcrun devicectl device install app --device <设备> <app>`；`xcrun devicectl device process launch --device <设备> --console --terminate-existing <实际BundleID> <参数…>`（`--console` 会等进程退出，脚本里用后台进程 + 轮询报告文件，读完后 kill 包装进程即可，杀它会顺带终止 app）；素材 `xcrun devicectl device copy to --device <设备> --domain-type appDataContainer --domain-identifier <实际BundleID> --source <本地> --destination Documents/<子目录>`（目录内容直接落到目标目录，5.8GB/500 文件约 15s），日志 `… copy from … --source Documents/PhotoViewer/<文件> --destination <本地>` 取回（`stress-flip.jsonl` / `memory-events.jsonl` / `ios-crash.log`）。设备需解锁才能挂载 DDI（锁屏报 `kAMDMobileImageMounterDeviceLocked`）；`devicectl device info lockState` 先确认，`systemCrashLogs` 域可查 .ips（本机挂载点写法见 handoff §3 行）。
