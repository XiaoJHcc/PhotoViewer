# PhotoViewer.iOS — 原生壳（I1 基座 + I2 主图 + I3 主屏布局 + I4 输入 + I5 P3 功能）

Debug 与 Release 都只启动 **UIKit 原生壳**（不创建旧壳对象）；历史启动参数 `--native` 不再参与壳选择，传入时按普通参数忽略。最低系统版本 **iOS 17**。执行清单见 [Plans/native-rebuild-phase-ipad.md](../Plans/native-rebuild-phase-ipad.md)，程序化验收状态与其 §7 一致，作者手验步骤见 [Plans/native-rebuild-phase-ipad-acceptance.md](../Plans/native-rebuild-phase-ipad-acceptance.md)；I1 基座、I2 主图（Metal + `UIScrollView` 手势 + 编码协商）、I3 主屏布局（文件栏/胶片栏/筛选条/控制栏、安全区、两向与自动布局）、I4 输入（上下文菜单、硬件键盘、滚轮、轻扫翻页、拖入、设置写回刷新）与 **I5 P3 功能（分析栏 / 相似聚类 / 工具页 / 增强预览）** 已落地：控制栏与主图菜单的 P3 入口按 SCOPE-01 解禁，分析栏按共享几何真正参与分区。

**真机覆盖（2026-10-18）**：iPhone 17（iOS 27.0.1）与 iPad mini（iOS 26.6）均已验证可安装并以原生壳启动（iPhone 启动日志 `window visible 402×874`）。工具链为 **Xcode 27.1 + .NET SDK 10.0.402 + ios workload 27.0.10722**；该 workload 的精确 Xcode 校验不认 27.1，两个 Apple head 的 csproj 设 `ValidateXcodeVersion=false`，见 [DEV.md](../DEV.md) iOS 节。**主屏分区仍按 iPad 调校**：iPhone 竖屏走列布局（文件栏 116 点 + 主图），尚未做 iPhone 专用适配；iPhone 的 USB-C 数据链路对 USB 3.0 线缆存在枚举失败（实测换 USB 2.0 线后正常），排查时优先怀疑线材。

**启动参数来源**：iOS 不填充托管 `Main(string[] args)`（实测为空数组），一律读 `NSProcessInfo.ProcessInfo.Arguments`（`simctl launch <udid> <bundleId> <args…>` 会传入）。

**共享源**：`../PhotoViewer.Apple/` 纯源目录由 csproj `<Compile Include="..\PhotoViewer.Apple\**\*.cs"/>` 链接编译（展示解码器、Metal 渲染核心、验收判定、命令符号与手势映射），与 [PhotoViewer.Mac](../PhotoViewer.Mac/AGENTS.md) 共用同一份，见 [其手册](../PhotoViewer.Apple/AGENTS.md)；视口/主屏/胶片栏/控制栏/分析栏/相似面板/EXIF 表几何与命令表在 `../PhotoViewer.Shared/`。本壳只保留 UIKit 宿主。改共享源需同时复核 Mac 的 `--pv-native-*` 回归。

**I2 主图 RAW 解码**：RAW 经 Core Image 的 RAW 引擎（共享 `ApplePresentationDecoder` 内的 `CIRawFilter` 路径）全分辨率解码，代理按视口长边缩渲染、Full 为原生尺寸；几何取传感器原生尺寸（Sony ARW 为 `7008×4672`），EXIF 方向只作为产物方向码交给 GPU，`NeedsFull` 因此能正常升级 Full。ImageIO 的 Sony ARW 内嵌预览（真机实测 `req=4532 → out=1616x1080`，`SourceWidth` 也读成 1616）现在只是 `CIRawFilter` 创建/渲染失败时的回退，回退时仍会因 `Width == SourceWidth` 停在预览档；该回退列在 `SCOPE-04@ios` 名下，正常路径已不再受限。缩略图兜底（`DecodeThumbnailAsync`）对 RAW 同样走新路径，出口为显示朝向的 sRGB8。

**主图链路（I2，2026-10-17 重做缩放架构）**：`PhotoLoadSession` 只管代际/代理↔Full/租约、增强态；`iOSPhotoView` 把共享 `MetalPhotoRenderer` 挂成 `CAMetalLayer` 子层（绘制目标恒 RGBA16F 扩展线性 sRGB），视口数学取共享 `PhotoViewport`。**缩放/平移采用 UIKit 标准照片缩放模式，滚动视图是唯一交互真源**：`UIScrollView` 内有一个透明缩放内容视图（`ViewForZoomingInScrollView` 返回它承载捏合），其尺寸**只在 `zoomScale=1` 时**写成适应态显示尺寸；视口变换在每个 `DidZoom`/`Scrolled` 回调里由 `zoomScale`/`contentOffset`/`contentInset` 反算（`PullViewportFromScroll`），居中由等量 `contentInset` 给出（`DidZoom` 先更新内边距再派生视口）。程序化缩放（双击、键盘比例/预设缩放、分析栏细节预览定位）一律表达成滚动视图操作（`ZoomToRect`/`SetZoomScale`；锚点用"目标内容矩形中心 + (视图中心 − 触点)/zoom"修正，使触点下的图像点保持不动），不再先写视口再回写滚动视图。**代理↔Full 热替换只换纹理**（同一张照片 ImageSize 恒定：`PhotoViewport.ApplyTexture`，滚动状态一律不动；同一产物引用重复上屏只重绘、不重传纹理）；只有切图（代际变化，或同代际下身份/逻辑尺寸/方向变化；STATE-01 缓存命中切图不经过空图）才 `SetZoomScale(1)` → 写缩放内容视图 frame → 设缩放范围/内边距 → 回适应态。布局/旋转按"同一图像点留在视口中心 + 同一相对缩放"重建基准。**旧实现的三处根因已移除**：① 每次 `SetImage` 都对带缩放变换的缩放内容视图写 `Frame`，`contentSize` 崩掉、偏移被钳向 (0,0)——真机表现为"放大后照片被拽到左上角"，增强开关/升 Full 同样触发；② 先 `SetZoomScale` 再 `SetContentOffset` 会互相取消（改为单条 `ZoomToRect` 动画）；③ 增强/换档与缩放共用同一条重排路径。**导航图（缩放指示器）**：非适应态且设置开启时显示在主图区右下角（安全区内、避让控制栏/分析栏），`color.nav.background` 0.6 不透明度圆角 6 宿主 + GPU 小目标渲染的缩略图（长边 150、按显示朝向比例）+ 白色 1 点可见框（`PhotoViewport.NavigationViewport`）+ 物理缩放百分比（与 Mac 同口径）；小图只在展示图引用变化时重出。**导航图白框可拖动定位（IMAGE-06，四端一致）**：按下框内保留抓取偏移、按在缩略图其他位置先移框心，均经 `CenterOnNormalizedPoint` 落到滚动偏移。**增强计算反馈**：主图区底部中央显示 `计算中…` 药丸，绑共享 `PhotoLoadSession.IsEnhancingVisible`（500ms 门槛），增强图上屏/失败/取消后收起。**状态提示（STATE-01/STATE-03/IMAGE-03）**：加载提示绑 `PhotoLoadSession.IsLoadingVisible`（300ms 延迟态）；评分写回失败、Full 升级失败、内存自动关闭增强与打开失败（STATE-02）共用主图区底部 `iOSStatusToast`（令牌宽/色/圆角、`motion.status.toast.duration` 自动消失、新替旧、不拦手势；与「计算中」药丸同时可见时整体上移到药丸上方）；屏上有代理时 Full 失败只走提示条，不覆盖「无法打开该图片」。**编码协商**：`iOSPresentationEncodingPolicy` 给代理档 RGBA16F、Full 档 8 位 Display P3、压力 ≥ Warning 时代理档也降 8 位 P3；准入估算与纹理记账按实际编码的每像素字节（Full 档 4 字节）。**启动顺序硬要求**：必须先上报有效视口再 `SetFile`（`iOSNativeRootViewController.StartSession` + `PhotoLoadSession.UpdateViewport` 的零尺寸守卫），否则代理目标会被钳成 1 像素、解码出 1×1 的"合格代理"且永不重载。

**切图 / Fit / 双击（2026-10-17 作者手验反馈）**：语义一律由共享 `PhotoViewport` 决定，宿主只把结果表达成滚动视图操作。
- **双击**：`PhotoViewport.ToggleFit(触点)` —— 适应态以触点为中心到物理 100%，放大态回适应（与原 Avalonia 壳 `ToggleFit(center)` 同一语义）；动画用一条 `ZoomToRect`。
- **Fit 命令（控制栏按钮 / 热键）**：`PhotoViewport.ToggleFit(null)` —— 适应态优先以照片的 Sony 对焦点为中心到物理 100% 并开启跟随，**无对焦点才取视口中心**；已放大时回适应。早期实现把它写成"无条件 `FitToView`"，所以在适应态按 Fit 看起来"没反应"（与原 Avalonia 壳的切换语义不一致）。
- **切图保持位置**：`iOSPhotoView.SetImage(image, generation)` 在加载代际变化（含 STATE-01 缓存命中切图）或同代际的照片身份/方向/尺寸变化时不再重置到适应态，而是 `BeginImageChange` + `ApplyImage`（适应态重新适应；`FollowsFocus` 时保持倍率并居中到新照片对焦点；否则保持倍率与同一归一化中心点），再按视口状态重建滚动基准。代理↔Full 仍是 `ApplyTexture`（滚动状态一律不动）；几何基准恒为全分辨率 `SourceWidth/Height`，所以放大态切图后的新照片先代理后 Full 不会跳。
- **100% 口径**：1 源像素对 1 屏幕物理像素；素材本身小于视口物理像素（例如 RAW 回退到 iOS 内嵌预览时的 `1616×1080`，在 iPad 上适应态已 ≥ 100%）时没有向上余量，双击/Fit 会**夹回适应态**（`SyncScrollFromViewport` 显式夹取，避免视口比滚动视图更小）。
- **视口通知**：程序化改视口（Fit/双击/预设/细节定位）后 `SyncScrollFromViewport` 必须显式 `ViewportChanged`——滚动视图派生出的状态可能与目标一致（`Pull` 判定"无变化"），不通知会漏掉导航指示器刷新与 Full 升级（Fit 后 `NeedsFull` 由 true 变 false 也必须上报）。
- **滚动基准补建**：首图上屏早于视图布局时 `SyncScrollFromViewport` 写不出 `contentSize`/缩放范围，标记 `_scrollGeometryValid=false` 并由下一次 `LayoutSubviews` 补建（旧实现直接返回，`MaximumZoomScale` 停在 1，双击/捏合只能"几乎不动"）；推迟期记一条 `[Native] 照片上屏时视口尚未布局…` 日志。

**主屏布局（I3）**：分区几何取共享 `MainScreenLayout`（与 Mac 原生壳同一份数学），安全区口径在 `iOSMainScreenLayout` 叠加——栏位**背景**铺满屏幕边缘、栏位**内容**（筛选条/胶片栏/控制栏/分析栏）收在真实 `SafeAreaInsets` 内、主图满幅；根控制器显式 `PrefersStatusBarHidden() => true`（`UIViewControllerBasedStatusBarAppearance = true` 时 `Info.plist` 的 `UIStatusBarHidden` 被忽略，不显式声明会让状态栏漂在贴顶内容上），故实测 `safe.Top = 0`（如将来显示状态栏，布局按真实 insets 自动让位）。**行布局筛选条五项整组在安全内容区内水平居中、交叉轴居中**（共享 `FilterBarFrames` 默认口径），列布局保持 116 栏内居中/纵向节距；系统 `UIButtonConfiguration` 统一管理按钮背景与正常/按下/菜单返回状态，不叠手工 layer 描边。两向只看窗口尺寸（行=上下、列=左右、自动=窗口方向），隐藏栏位把空间让给主图；**分析栏**参与分区：行布局在主图下方、列布局在主图右侧，交叉轴 = 瓦片边长 + 20，行布局瓦片从安全区左内边距起排、列布局从安全区顶内边距起排。**胶片栏**是 `UICollectionView` + 自定义 `UICollectionViewLayout`（几何全部来自共享 `FilmstripGeometry`，含 FILM-02 的居中偏移），卡片 `iOSThumbnailCard` 按 FILM-05 绘制（当前项蓝框取 `IsCurrent`、Full 缓存细边、80 方形照片区、文件名尾部截断、第二行拍摄时间、6 个星级、抖动徽标、占位/加载状态）；点选走独立覆盖按钮（星级按钮命中优先，点星不切图），显式定位用 `CADisplayLink` 驱动的 350ms 三次缓出、用户触摸/拖动即接管、减少动态效果直接到终点、重新显示与换向定位当前项。**筛选条**是 `UIButton`+`UIMenu` 下拉（`ShowsMenuAsPrimaryAction`）+ 计数 + 相似聚类 toggle（90×27，选中态取 `color.filter.toggle.*` 深蓝底/浅蓝字、未选中字 #AAA）。**控制栏**复用共享 `ControlBarLayout` 的分组/换行/居中，命令显隐与顺序来自共享设置（分析栏/增强预览等命令按用户设置生成，EXIF 信息块点击打开工具页）；块底取 `color.toolbar.block.background`、命令按钮取 `color.toolbar.command.*`，重建后显式写滚动内容尺寸并夹取偏移。主图区保留**空态/加载提示**（点击打开文件夹，与 Mac 空首屏同义）。

**输入（I4）**：主图区挂 `UIContextMenuInteraction`（手指长按 / 触控板与鼠标辅助点按），项与 Mac 原生右键菜单同序——打开文件夹…、胶片栏（勾选）、分析栏（勾选）、控制栏（勾选）、增强（勾选）、工具…、设置…；勾选态每次弹出读共享状态（`iOSContextMenus`），无照片时「增强」置灰、「工具…」仍可打开空态（MENU-07）。**主图菜单的 `GetPreviewForHighlightingMenu` / `GetPreviewForDismissingMenu` 返回触点处 1 点透明定向预览**：菜单以手指为锚点，照片不抬升、不缩小、不位移（系统默认的整视图预览会把主图抬起来缩到一边）；卡片菜单保留系统默认抬升（不移动列表布局）。胶片栏卡片同样挂上下文菜单：菜单标题为完整文件名 + 拍摄时间（FILM-05 的触屏 tooltip 等价物），功能为"评分 0–5"（勾选当前星级），写回走共享评分路径且**不改变当前主图**（FILM-06 暂留由共享列表负责）。**硬件键盘**：`PressesBegan` 取 `UIKey.KeyCode`（HID usage），经共享 `AppleInputMapping.FromHidUsage` → `AppGesture` → `InputCommandMap.CommandForGesture`（与 Mac 同一张命令表与苹果键盘映射口径），再由 `InputCommandMap.IsCommandKnown`（唯一来源 `SettingsCatalog.Commands`，SF Symbols 只负责 UI）与 `iOSControlBar.IsCommandAvailable` 判定可执行；数字键盘 `+`/`−` 与主行 `=`/`−` 同键（命中默认预设缩放），Enter 与 Return 都是 Return。只有 `InputCommandMap.IsRepeatable` 的命令（上一张/下一张/预设缩放）进入固定节奏计时器重复（`image.keyRepeat.delay` 350ms / `image.keyRepeat.interval` 60ms，iOS 无读取系统键盘重复速率的公开接口），其余命令按住不重复，系统重复事件被去重。INPUT-01 守卫：输入控件获焦（`UITextField`/`UITextView` 编辑通知）或展示模态（设置页、文档选择器等）期间不派发。**触控板/鼠标滚轮**：只接收离散滚动（`UIPanGestureRecognizer.AllowedScrollTypesMask = Discrete`）并查用户鼠标绑定（与 Mac 非精确滚轮口径一致），触控板连续滚动与捏合仍归 `UIScrollView`。**适应态横向轻扫**＝上一张/下一张：单指、水平 24 点阈值且需明显大于纵向位移，走共享 Previous/Next 因而触发显式定位；放大态横向拖动仍是平移，双指捏合起手不翻页。**拖入**：根视图 `UIDropInteraction` 接收"文件"里的文件/文件夹 URL，经 `iOSExternalOpenBridge` 投递共享 `OpenRequestChannel`（与 openURL 同一条路径），安全作用域由打开会话的 `iOSStorageAccessSessionFactory` 按次持有（引用保留系统交回的原 `NSUrl`，租约用同一实例成对 Start/Stop；存在性探测也在作用域内完成）。**设置写回**：从主图菜单打开原生设置页，关闭（下拉触发 `DidDismiss` 或关闭按钮）经工作副本一次性回写，主屏即时刷新布局模式、控制栏命令显隐/顺序、快捷键重绑、EXIF/评分分组与文件格式筛选。**I5 目视补充（2026-10-17）**：主图长按菜单含全部分析栏/增强/工具入口；相似聚类 toggle 真实点击展开、`提取全部` 真实点击后卡片出分数与柱状条；分析栏经菜单打开、诊断瓦片点击落准星、细节预览点按定格绿框、点主图空白解除；工具菜单打开 sheet 并进入 EXIF/DINO 页。

## P3 功能（I5，共用 Mac 的 presenter）

- **分析栏**：`iOSAnalysisHost` 实现共享 `IAnalysisHost`，`iOSAnalysisPanel` 消费 `AnalysisPresenter`（只读库快路径 / 增强联动 / 未提取回退全部复用，不复制编排）。瓦片是 UIKit 版 `iOSDiagnosticTile`（外框 `#222`/`#444` 1 点/圆角 6、内层圆角 5 裁切、AspectRatio letterbox、主图图层最近邻放大、背景 alpha 0.30、药丸角标、底部说明、占位、准星、叠加槽位）与 `iOSDetailPreview`（指针 hover 与直接触控 Down/Move/Up/Cancel 进入同一个活动目标状态机；按下立即点亮、滑入另一细节瓦片切换、移出/抬起/取消立即清除，不使用延迟长按或定格；双击独立定位裁剪中心到物理 100%）。`iOSAnalysisPanel` 以输入所有者标识隔离过期事件，保持最多一张活动瓦片；直接触控按住期间hover不得抢占，抬起/取消清除，后续新的hover事件才可重新建立活动目标；换图、隐藏、应用失活清空活动目标，辅助技术提供显示/清除动作。`iOSDiagnosticTile.HitTest` 使用 UIKit 本地坐标并由瓦片自身接收触摸，装饰/叠加子视图不截事件；诊断内容点按落共享准星，角标/letterbox/边框清准星，直方图吞掉点按而不改准星。**自绘瓦片必须 `ContentMode = Redraw`，装饰层必须 `Opaque = false`**（否则首次 1×1 内容被拉伸、装饰层以黑色盖住图像——I5 回归发现）。几何取共享 `AnalysisPanelGeometry`；细节裁剪按 `DisplayCrop` 从展示会话取源，F16 代理与 8 位 P3 Full 都转成显示朝向 sRGB8。分析栏可见时视口上报 `NeedsFull`，主图升 Full。
- **增强预览**：控制栏命令/主图菜单走 `PhotoLoadSession.ToggleEnhanced()`，跨切图持续生效；算法只在 8 位口径有定义——会话把展示产物转 sRGB8 **副本后就地**做 CLHE（`ImageEnhancer.EnhanceInPlace`：两遍逐像素阶段按行并行、直方图分区统计后整数合并，输出与旧串行实现逐字节一致），再回到源展示编码：**8 位 Full 档回 8 位 Display P3**（不再扩大成 F16，24MP 省约 96MB 与一次整图转换），F16 线性表面（Mac 全档、iPad 代理）仍回 F16 线性 scRGB；失败不静默回退（记日志、`IsEnhancing` 归 false、提示收起）。`PhotoLoadSession.IsEnhancingVisible`（500ms 门槛）驱动主图上的 `计算中…` 药丸。**验收必须比较增强前后的 GPU 帧像素**（`EnhancementAcceptance`：确定性低对比度 JPEG + 平均绝对差 ≥6、最大差 ≥30，关闭后还原）——只断言 `EnhancedDisplay` 无法区分"增强未上屏"与"高对比素材视觉差异小"（2026-10-17 补齐）。**方向断言**：EXIF 6/8 真实夹具与一张 4000×3000 的 EXIF 6 素材（走 8 位 P3 Full）都必须保持增强前后"方向 + 源尺寸 + 导航帧四角颜色分类"一致（方向丢失时画面会转 90°）；`--pv-native-gesture-check` 另断言增强开关前后滚动状态与视口变换逐项不变。**性能（真机 Release，历史数字取自解释器模式）**：24MP Full 1.8 s（转 sRGB 238 / 均衡 1378 / 回 P3 201 ms）、13.7MP F16 代理 0.9 s（96 / 764 / 55 ms）；同一算法在 Mac（JIT）为 104 / 45 ms。csproj 现为 `MtouchInterpreter=-all`（全部程序集 AOT，解释器只作动态代码回退），上述数字保留为改造前基线；真机复测与提速门见 [性能专项](../Plans/apple-performance-memory-plan-1.md)，未用模拟器结果替代。
- **相似聚类**：`iOSSimilarityPanel` 复用 `iOSFilmstripLayout` + `iOSThumbnailCard`（第二行 `NN%` + 75% 起柱状条，选中取 `IsCurrentImage`），空态/动作区/进度/未提取计数/错误文本全部读共享 `SimilarityPanelViewModel`（列表态错误显示在停靠动作区，SIM-10）；行布局按共享 `SimilarityPanelGeometry.RowWidth` 从胶片栏右侧切出，宽度 = 卡片数 × 96 + 列表内边距 + 描边 + 停靠区自然宽（`DockMeasureWidth()`，只在该动作区实际显示时计入），**相似项增减或停靠区内容（未提取计数 / 动作区 / 错误文案）变化后必须重排主屏**，否则面板停在 106 点、列表被停靠动作区挤成零宽（I5 回归发现）；列布局扩宽文件栏；`提取全部/补齐全部` 走共享批量索引（iOS 上 DINO 走 CPU）。
- **工具页**：`iOSNativeToolsPresenter` 与设置复用半屏 `PageSheet` 配置（medium/large detents、grabber、圆角与滚动扩展策略），以 `UINavigationController` + `InsetGrouped` 原生分组列表承载 EXIF 详情 / DINO 诊断（非 Windows 不建照片统计）。初次打开与关闭后重开均显示分组工具列表，不自动进入EXIF或DINO、不为展示列表启动推理；已展示只前置并保留当前页。工具子页内容按安全区排布，不延伸到导航栏下方，文件名/格式头不被栏材质覆盖；深色取应用级固定深色（导航控制器再显式声明），背景与设置子页同口径（根视图动态 `SystemGroupedBackground`、内部滚动/表格/文档视图透明、卡片 `SecondarySystemGroupedBackground`）。EXIF 用 `InsetGrouped UITableView` + 共享 `ExifTableGeometry` 保持 7 列，原生 configuration 格式按钮与只读可选 `UITextView` 支持长按复制；DINO 保持 3+2 瓦片与第六格留空、网格下方整宽原生文本块，复用同一 `DinoDiagnosticPresenter` 与页面。导航状态写共享 `ToolsViewModel`；展示写 `IsPresented=true`，关闭（含下滑 `DidDismiss`）写 false 并 `Deactivate()` 取消在途 DINO，页面对象保留可重开。

## 评分冲突指示（RATING-04）

- 组级冲突只信共享 `ImageFile.HasRatingConflict`（`PhotoGroupMap` 按组内全部实际来源判定：取值不同、任一 Missing/Invalid/Conflict），壳层不另建判定；`HasRatingConflict` / `RatingSources` 变化时卡片刷新、控制栏由根控制器重建。
- 胶片栏卡片与控制栏评分组 0 号槽位在同一状态下换 `exclamationmark.triangle.fill` + `DesignTokens.ColorStarConflict`，几何与命中区不变（卡片仍 `film.card.star.*` 槽位、控制栏仍 30×30）；三角只作指示，点击不写值、不切主图。非冲突仍是 `xmark`、点击写 0。
- 来源浮窗尚未移植到 iOS（macOS 已实现，设计约束见 [RATING-04](../Design/spec/rating.md) 与 [platforms](../Design/platforms.md#rating)）；本阶段点击三角不打开任何界面。
