# PhotoViewer.Android — Android 原生壳

Debug 与 Release 均只启动原生壳，无旧壳入口。壳内容：原生主图（`TextureView` + `SurfaceTexture` + EGL14/GLES，8 位 P3/sRGB；所有 API 单一 `TextureView` 宿主，SHELL-12@android 的照片层取样源）、主屏布局（文件栏/胶片栏/控制栏/导航图/insets）、SAF 存储、硬件键盘/滚轮/长按菜单/返回、半屏设置（五分类 + 关闭回写）。实现与验收状态见 [Design/status.md](../Design/status.md)，计划、验收矩阵与色域结论见 [Plans/native-rebuild-phase-android.md](../Plans/native-rebuild-phase-android.md)。

**发行版本**：构建、运行与发布必须显式传 `PhotoViewerEdition=standard|ai`；缺失或非法值直接报错，DINO 能力由 edition 派生。标准版 `PhotoViewer` 不编译相似面板、DINO 诊断及 ONNX 托管/原生依赖，保留 CV 分析、三瓦片「CV 诊断」与独立「即时计算 CV」；AI 版 `PhotoViewer AI`（显示名空格，分发 APK 文件名前缀 `PhotoViewer-AI`）内置固定模型和 DINOv3 License，并提供独立「即时计算 DINO / CV」。下文 DINO、相似聚类及五瓦片诊断均指 AI 版。ApplicationId 分别为 `cc.xiaojh.PhotoViewer` / `cc.xiaojh.PhotoViewer.AI`，两版可同机并存，设置、数据库、缓存和日志各自位于独立沙盒，不提供产品内切换。头工程及共享工程的 `bin/<standard|ai>/`、`obj/<standard|ai>/` 隔离；只构建 arm64-v8a，清单从源模板生成中间目录副本并写入版本显示名与实际包名，不改写仓库模板。发行能力与数据边界见 [EDITION](../Design/spec/editions.md)，开发和发布入口见 [DEV.md](../DEV.md)。

## 主图提交与后台生命周期

- 生产主图经 `AndroidPhotoView.Presentation.cs` 的 `PresentImage` 提交：同色域与纹理缓存命中保持即时路径；跨色域转换在单路线程池准备，按实际 EGL 表面捕获目标。切图和 Surface 重建使旧请求失效，取消传入 `ColorEngine` 行带，旧结果不得提交。`SetImageForChecks` 与 `RecreateSurfaceForChecks` 仅供同步对照验收，不接产品入口。
- 请求源、正在展示的源及在途转换各持独立像素租约；替换、取消和释放分别归还，避免会话回收后 Surface 重建读取空像素。GPU 缓存仍只按原源实例弱引用标识，准备产物提交后即释放。准备失败经共享 `StatusMessages.PresentationFailed` 提示，不回落到忽略色彩的上传。
- 手势、动画与布局的绘制请求经下一动画帧合并，视口和 Full 需求仍同步上报；布局补帧也进入同一通道。`RenderedFrames` 只计成功交换，不把无表面或 EGL 失败的调用算上屏。
- 最近纹理和空纹理合计另受 `clamp(应用预算 / 12, 16MiB, 384MiB)` 字节限制，预算未知取 64MiB；当前纹理不受此淘汰限制。最近张数仍至多 2，压力修剪规则不变。字节限制是估算预算，不是驱动真实分配上界。
- `AndroidRawReadLease` 在同一 `IFileRef` 对象的活跃解码/内嵌预览之间共享文件字节，最后消费者释放即撤登记，无常驻文件缓存。取消只退出自己的等待，最后消费者撤销才中止读取；文件字节和原生工作缓冲均进入准入账，P0 放行但记账，后台拒绝即跳过。不缓存 RAW 开发源、不强制代理直接 Full。
- Activity `OnStop` 暂停预取并取消该活跃代际，`OnStart` 恢复并重排邻居与当前 Full 预热；`OnPause` 不暂停，避免系统选择器/浮层导致误切换。同一入口每次都同步 `BatchAnalysisContext.SetApplicationActive`（即使预取状态未变）：进后台取消当前应用代际，显式批量提取随之终止、已入库部分保留；回前台换新代际但不自动续跑提取，用户再次提取只补缺失。`UiHidden` 不伪报内存 Warning；真实内存压力回调和周期探测仍负责修剪。
- `pv-check perf` 使用隔离设置，覆盖同步/后台色彩准备、GPU 像素、旧请求/表面重建/租约、绘制合帧、纹理字节预算、后台预取与 RAW 共享读取；真实 ARW 放 `files/pv-check-raw/`。`pv-check background` 可单跑预取活跃闸，真实 HOME→返回的生命周期另由 ADB 操作核对。

## 程序化检查

`storage` / `rating-perf` 依赖验收 Provider，构建时额外传 `-p:PhotoViewerAndroidStorageChecks=true`（SDK 选择同构建一节）：产物与中间目录落在 `bin/<edition>/checks/`、`obj/<edition>/checks/`，日常 Debug 包不受影响；普通 Debug 与 Release 构建都不含这两个 Provider，跑这两个模式只报一条未注册 FAIL。Release 传该开关直接构建失败。

```bash
# 标准版；AI 版改为 cc.xiaojh.PhotoViewer.AI
PKG=cc.xiaojh.PhotoViewer

# 夹具：adb push 到 /data/local/tmp，再 run-as 复制到应用内部 files/pv-fixtures
adb push <本地夹具目录> /data/local/tmp/pv-fixtures
adb shell run-as "$PKG" cp -r /data/local/tmp/pv-fixtures files/pv-fixtures

# 启动检查：组件前半段是 ApplicationId，后半段 Java 类名不随 edition 改变
adb shell am start -n "$PKG/cc.xiaojh.PhotoViewer.AndroidBootstrapActivity" \
  --es pv-open @files/pv-fixtures --es pv-check main

# 报告：files/PhotoViewer/android-checks-<mode>-<standard|ai>.txt
adb exec-out run-as "$PKG" cat files/PhotoViewer/android-checks-main-standard.txt
```

入口统一是 `--es pv-check <mode>`：报告写 App 内部 `files/PhotoViewer/android-checks-<mode>-<standard|ai>.txt`，首行是 `PASS n / FAIL m`，其后逐条 `PASS/FAIL 名称 — 实际值`。每次运行前 `am force-stop`，避免旧进程/旧报告冒充。检查期间根视图置 `KeepScreenOn` 防休眠（表面重建与回读要屏幕保持点亮），结束无论成败都复位；设备需已解锁且屏幕可见。

**基线模式**（覆盖范围）：

- `rating-perf`：评分写回耗时基线（真机 SAF 上的「连续改星慢」定位入口）。输入夹具推 App 内部 `files/pv-rating-fixtures/`（推送方式同上节的 `pv-fixtures`）：真实相机的 `<stem>.HIF` + `<stem>.ARW` 与可选同名 `<stem>.xmp`（一组三来源）；只取文件最多的一组，按 `rp-01/rp-02/rp-03` 复制进 `DebugTestDocumentsProvider` 的 `writable/rating-perf` 测试树，之后所有读写都走真实 `content://`（输入夹具与用户照片只读，绝不写入；目录缺失时用 App 内部合成 JPEG + 同名 `.xmp` 兜底并在报告注明）。流程：打开真实 SAF 文件夹走 `MainViewModel` → 把每组统一写到一致基线 → 逐成员整文件 `OpenReadAsync`/属性重查/`FindFileAsync` 的读取吞吐基线 → 真实触摸改星（展开态点槽位，紧凑态起手星级弹窗落到目标格）与共享 `SetRatingWithResultAsync` 两条入口各连续改星 → 转场到新图首写 → 不同组并行写。每个采样报告「入口触发→VM 收敛」「逐来源重新读盘」两段墙钟、写入窗口内的 `Rating`/`RatingSources`/`HasRatingConflict` 通知数与「冲突为真」次数（假冲突指针）、逐来源磁盘真值；同一组重复采样至少 3 次。判定只看写入是否收敛、是否出现假冲突，**不设速度门槛**；至少两组才能测并行。`DebugTestDocumentsProvider` 只随 `-p:PhotoViewerAndroidStorageChecks=true` 的 Debug 验收构建注册；普通 Debug 与 Release 跑该模式只报一条未注册 FAIL。
- `glass`：液态玻璃验收（独立模式，不并入 `all`）。`--es pv-glass-stage host|product|sample|layers|all`，缺省 `all` = `host` + `product`。`host` 核对主图宿主（EGL 物理缓冲、整窗 P3 与色块、物理 100% 严格逐像素、输入→swap/界面层取用与 250ms 心跳）；`product` 是正式产品材质验收（`AndroidNativeChecks.Glass.Product.cs`），跑在主屏现有照片层与玻璃控件层上核对三层结构、6 个栏底与带衬底 EXIF 的结构/配方/分级、控件锚点/呈现矩形/配方令牌/按压形变与回弹/悬停/焦点/禁用/减少动态效果，并做真实像素证明（黑/灰/白衬底、1px 条纹低通、阶跃边缘展开）与切图/缩放跟随；`sample`/`layers` 是阶段 0 的迁移层机制检查（legacy），只在点名时运行、不作为产品验收证据。`--es pv-glass-host-step capability|quadrants|physical|input|hide|all`（缺省 `all`）只跑所选宿主步骤，供定位污染来源（`hide` 只做「移出场景层非照片子视图与玻璃绘制层→按原位放回」这一最小动作），缺省行为不变。`--ez pv-glass-f16 true` 是同一模式下的诊断开关：只在 `pv-check=glass` 且 API 26+ 时、于 `OnCreate` 建立根视图与窗口表面前把窗口像素格式请求成 `RGBA_F16`（运行期新 Intent 不改窗口格式），缺省启动完全不经过该分支。这只是**请求**：系统是否接受由运行期实际缓冲决定，8 位 P3 还是 F16 只能用整窗回读的位深读数与差异、外加 `dumpsys SurfaceFlinger` 的实测格式对照判定，日志与报告不得据此声称已生效。
- `zoom`：26MP 合成图（含方向 6）及真实 HIF 的 2496 代理→6192 Full 升级，计时同步纹理提交、动画间断与真实加载会话 UI 心跳；回读 GPU 的首尾、原分块边界两侧与行中像素，逐通道对照源字节，另验额外行距与纹理缓存；顶点缓冲检查覆盖八方向实际绘制、非对称四象限 GPU 回读、缩放平移更新及同一 renderer 两轮 EGL 重建后缓冲身份与分配次数保持。真实 HIF 副本放 `files/pv-check-zoom/` 或 `GetExternalFilesDir(null)/pv-check-zoom/`，缺失如实 FAIL。`zoom` / `input` / `perf` / `background` / `rating-perf` 使用隔离设置档（`rating-perf` 用独立档 `rating-perf`，其余共用 `input-checks`），`zoom` / `input` / `rating-perf` 另将逐条报告写入 `PhotoViewerChecks` Logcat 标签，正式签名非 debuggable 包也可读取；`input` 另覆盖积压 Down、Down 后真实阻塞主线程再送积压 Move/Up、候选过期后恢复正常长按，以及动画中途触摸接管。像素回读、日志与合成素材仅检查模式执行，不进入普通浏览路径。

**矩阵维度**：fontScale、density、竖屏/横屏及回竖屏分别验证；当前结果与未覆盖边界见 [Design/status.md](../Design/status.md) 及对应计划。验收读取用的访问器（`AndroidNativeRootView.ScreenLayer`/`SceneLayer`/`PhotoLayer`/`GlassControlLayer`、`AndroidGlassControlLayer.ControlsForChecks`/`TryGetControlForChecks`/`SetHoverForChecks`、`AndroidGlassButton.DrawContentForChecks`/`IconSlotForChecks`/`IconForChecks`、`AndroidGlyphDrawable.SlotPx`/`FontSizePx`/`DigitFontSizePx`/`SolidGlyph`、`AndroidGlyphView.SlotPx`/`FontSizePx`、`AndroidCommandIconView.SlotSizeDp`/`SlotPx`/`DigitTextSizePx`、`AndroidGlyphProbe.Capture`/`Reference`/`Compare`、`StatusTextForChecks`、`StatusVisibleForChecks`、`ResetStatusForChecks`、`ControlBar.NodesForChecks`、`ControlBar.RatingConflictForChecks`、`ControlBar.TryGetRatingSlotScreenRect`、`ThumbnailCard.ShowsRatingConflict`/`StarSlotRectPx`/`ActivateSlot`、`RatingPopup`（`IsOpen`/`ModeForChecks`/`AnchorKindForChecks`/`DirectionForChecks`/`AnchorRectForChecks`/`SlotRectPx`/`ContentViewForChecks`/`WidthPxForChecks`/`HeightPxForChecks`/`PitchDpForChecks`）、`ThumbnailCard.ScreenRect`、`SimilarityPane.DockError*ForChecks`、`FilterScrollableForChecks`、`FilterScrollOffsetForChecks`、`AnalysisHostForChecks`、`FilterBar`（`IsDropdownOpen`/`DropdownInstanceForChecks`/`DropdownKindForChecks`/`DropdownAnchorForChecks`/`DropdownContentViewForChecks`/`DropdownRowsForChecks`）、`FilterScrollHostForChecks`、`AndroidFilePicker.BeginFileRequestForChecks`/`FileRequestCode`、`AndroidSettingsSheetView`（`FileInfoLabelsForChecks`/`LevelColorForChecks`））都是 `internal` 且注释标「验收用」，产品路径不引用；`faults` 另用反射改 `BitmapLoader` 私有静态解码器字段与 `SimilarityPanelViewModel` 私有 setter，退出前一律还原。

### 启动与 UI 长尾排障

- Debug 保持 `EmbedAssembliesIntoApk=true` 并保留 Debug 符号。Release 双版本和 AI Debug 使用 `AndroidUseAssemblyStore=true`，避开运行时 36.1.53 的逐程序集 DSO 首次并发映射竞态（可在首图懒加载时触发原生崩溃，见[专项方案](../Plans/android-performance-memory-plan-2.md)）。标准 Debug 保留逐程序集 DSO，以避开该构建组合的 Assembly Store 启动等待。以 Release 双版本冷启动及系统选择器授权、首图上屏核对发布包。
- `AndroidApp` 将进程域与 Android 未处理异常写到 `PhotoViewerCrash`，只记录、不标记已处理。原生 SIGSEGV / SIGABRT / `EXIT_SELF 255` 分别保留当次 Logcat 和 `dumpsys activity exit-info <应用ID>`，不能因时间接近就合并根因；没有托管钩子日志也不单独证明故障属于原生。
- Android 启动时将 `YuvImageConverter.MaxDegreeOfParallelism` 配为 `max(1, CPU 核数 - 1)`，并将 `ConversionTaskScheduler` 注入同等并发上限的进程级 `ConcurrentExclusiveSchedulerPair.ConcurrentScheduler`。多幅 YUV 转换共用执行槽，单图可用完整转换预算，不按图像上限静态均分；图像上限另不超过 `max(1, CPU 核数 - 1)`。这是 CPU 并发策略，不改变像素算法、Full 请求时机或精度；未配置的平台保持原行为。
- `zoom` 的真实 HIF 放大段开启 `AndroidFrameStats` 固定容量内存采样，平时关闭。报告区分 DrawFrame 等锁/MakeCurrent/GL 命令/Swap、根视图布局/会话/视口、调度回调与 Looper 分发，按最大心跳间隙的时间区间匹配样本，另记该间隙的 GC 增量与 UI 线程 CPU 时间；各类存在嵌套，不跨类相加。消息日志仅检查期间安装，结束清除；它自身有 JNI/字符串开销。上传墙钟不包含 Draw/Swap，不能单凭上传快就排除渲染阻塞。`zoom` 另按所有有效像素逐行对照有界并行与串行 Full，核对色彩、几何与方向不变。
- 独立模式的 `[NativeCheck] 独立模式开始/<步骤>` 日志用于区分启动与检查内失败；当前复现、验证范围与历史尚未归因的异常见 [Android 性能与内存专项方案 2](../Plans/android-performance-memory-plan-2.md)。

### 压测与性能探针

入口在 `AndroidNativeShell`：Intent extras 映射到共享 `StressFlipDriver` / `AndroidPerfProbe`，报告与 pv-check 同目录（内部 `files/PhotoViewer/`）。素材只读，不写回照片文件夹。

| Extra | 作用 |
|---|---|
| `pv-stress=<文件夹>`（`@files/` 解析同 `pv-open`） | 顺序翻页压测，写 `stress-flip.jsonl` |
| `pv-stress-count=N` | 翻页上限；缺省翻完整个文件夹 |
| `pv-stress-mode=ab` | 最近两张对比切换（缺省 sequential） |
| `pv-perf-probe-target=N`（`--ei`） | 探针代理长边；缺省为屏幕物理长边 × 2，实际主图代理长边见压测 `up_last` |
| `pv-memory-probe` | 内存上限探针：前台按 128MB 逐步分配并逐页写入，每步把占用与系统水位写入 `memory-ceiling.txt`，到 14GB 或分配失败停止（会挤掉后台应用，只在验收时用） |
| `pv-memory-probe-report` | 把系统记录的最近 5 次进程退出原因写入 `exit-reasons.txt` 后结束进程 |
| `pv-settings-page=<files\|preview\|control\|exif\|ai>` | 与 `pv-settings` 合用，设置 sheet 直接落到指定分类页（真机禁用输入注入时核对页面内容） |
| `pv-perf-probe=<文件夹>` | 分段计时探针，独占一轮，写 `perf-probe.txt` 后结束进程 |

```bash
# 标准版；AI 版改为 cc.xiaojh.PhotoViewer.AI
PKG=cc.xiaojh.PhotoViewer

# 探针：HIF/ARW/JPG 各取前 6 张（首张预热），代理长边 = 屏幕物理长边 × 2
adb shell am start -n "$PKG/cc.xiaojh.PhotoViewer.AndroidBootstrapActivity" \
  --es pv-perf-probe @files/pv-perf
adb exec-out run-as "$PKG" cat files/PhotoViewer/perf-probe.txt

# 压测：顺序 60 翻 / 对比 60 翻
adb shell am start -n "$PKG/cc.xiaojh.PhotoViewer.AndroidBootstrapActivity" \
  --es pv-stress @files/pv-stress-hif --ei pv-stress-count 60 --es pv-stress-mode ab
adb exec-out run-as "$PKG" cat files/PhotoViewer/stress-flip.jsonl
```

- 压测切到隔离设置档 `cc.xiaojh.PhotoViewer.Settings.stress`，每轮从默认值起跑且不覆盖用户设置；该名称只是各沙盒内的设置档名，不是跨产品共享身份。`done` 行 `extra` 含 GL 上传统计（`up_*`）、`/proc/self/status` 的 `rssAnonMB`/`swapMB`/`peakRssMB` 与 GC 次数。
- 压测与探针结束都结束进程（对齐 Windows 的 `Environment.Exit`），下一轮从干净进程起跑。
- 探针解码走壳注入的展示解码器实例（换 HEIF/RAW 解码器后无需改探针），GL 上传无 EGL 上下文时不测；解码返回 null 记作 `null result`，不吞成 0 ms。
- Release 包非 debuggable，`run-as` 不可用：模拟器 `adb root` 后从 `/data/data/<实际ApplicationId>/files/PhotoViewer/` 取报告。真机（不可 root）验收要可调试的 Release：复制 `Properties/AndroidManifest.xml` 加 `android:debuggable="true"`，以相对 csproj 的路径传 `/p:AndroidManifest=…`（绝对路径会报 XA1018），签名参数同 `publish-android-apk.sh`。
- 真机素材推到 `/sdcard/Android/data/<实际ApplicationId>/files/<目录>`，以 `@external/<目录>` 打开；`adb push` 建的目录是 `shell:ext_data_rw 2770`，应用无权遍历，推完须 `adb shell chmod -R 777 <目录>`。
- 小米部分系统版本限制 `input` 注入或 `svc power stayon`；触控验收须确认系统事件已送达实际窗口，若设备拒绝注入则使用程序化检查与 `screencap`，或人工点按。

## 工程约束与排障要点

- APK 打包前从 `FrameworkNativeLibrary` 移除 `runtimes/linux-arm64/native/*.so`（csproj `_PvRemoveLinuxOnnxFromApk`），只保留 AAR 的 bionic `libonnxruntime.so`。
- `AndroidAsset` 落在 `assets/…`；资源提供器解析 `avares://PhotoViewer/Assets/...` 前去掉 `Assets/` 前缀。
- 邻居 Full 预取须跟随实际需求并受预算准入（适应态只取代理，放大或分析栏可见才取 ±1 Full）；无约束地并发解 Full 会原生崩溃。
- 导航图缩略图取当前展示产物抽样，不做 GPU 回读，也不单独走 `BitmapFactory`（HIF 也可出图）。
- 模拟器（ANGLE）EGL P3 协商总回退 sRGB；P3 结论只能在广色域真机上得出。
- `EGL_GL_COLORSPACE_DISPLAY_P3_EXT` 是 `0x3363`（`0x30BF` 会 `EGL_BAD_ATTRIBUTE`）；窗口须 `android:colorMode="wideColorGamut"` + `Window.ColorMode`；P3 表面上着色器是否先线性化按帧缓冲实际编码决定，避免重复编码。
- `Bitmap.GetPixels` 返回 sRGB 打包值；读 P3 像素须 JNI 原始存储直读并按实际色域规范。
- `IMenu.Add(title)` 的 itemId 恒为 0；菜单项必须显式唯一 id 并共用单一点击处理。
- 列布局的 `FileContent` 从窗口顶边开始，筛选控件的首控件让位取该列位置的顶部遮挡（`_insets.Top`）加一份 `filter.margin`；行布局的内容区已含 `safe.Top`，只传 `filter.margin`。
- 胶片卡片两档外框：大档 96×144（带厚横向 159 / 纵向 116），小档 64×76（带厚横向 92 / 纵向 80）；宽形态列布局文件栏内容宽 116，相似面板列布局交叉轴用 `PanelWidth(106)`。
- 主图长按菜单、筛选下拉与星级弹窗都在根视图最上层的窗口内弹层呈现，按屏幕坐标计算后统一换算为窗口坐标（夹取在屏内，超高可滚），不使用 `PopupWindow` / `PopupMenu`。
- `TextureView` 尺寸变化会先交一帧旧尺寸缓冲：`OnSizeChanged` 保留 `CenterUV`，显式同步 `SurfaceTexture` 物理缓冲尺寸并补帧重绘；`Surface` 在 EGL 销毁后显式 `Release()` + `Dispose()`，`SurfaceTexture` 仍归 `TextureView` 释放。
- 控制栏必须在 `OnDraw` 内补齐 `Arrange`（dirty/空分组时只 `Rebuild` 会画出空容器）。
- `ApplyFilter` 须把被同名合并隐藏的 `CurrentFile` 映射回组代表。
- HIF 缩略图：优先容器 JPEG/`thmb` 项；不同缩略项存储方向可能不同，按「原始横竖 vs 显示横竖」决定是否旋转；元数据尚未给出方向时从文件头 `irot` 兜底；`OutputPreRotated` 必须如实。
- `KeyEvent` 主行数字 `Num0–Num9` 须映射到 `D0–D9`（`Enum.TryParse("Num3")` 失败）。
- 窄屏筛选条由可滚动宿主承载，控件宽度不压缩。
- 主屏栏底与带衬底 EXIF 已按 SHELL-12@android 交付真实照片层材质：API 31 及以上取样模糊，API 24–30 不取样、保留色层，所有 API 使用同一 `TextureView` 宿主。产品路径仍不截屏、不用 `PixelCopy`、不做离屏拷贝；`glass` 检查里的 `PixelCopy` 与整窗回读只在检查期间执行，不是产品材质实现。按钮、合体、星级胶囊与 AI 相似开关已接入完整玻璃（按压、高光、折射、G2 形状、弹簧与分级回退）；小型弹出菜单统一使用窗口内玻璃面板，取屏幕层最终画面。
- Android 竖屏保留系统状态栏：无 EXIF 块时顶行与分析栏整体下移到状态栏下缘，不占用状态栏图标所在的耳区（iOS 隐藏状态栏，耳区无系统图标）。
- 模拟器的 `RoundedCorner` 半径可能非零也可能为 0（如 13.3dp / 0），验收与几何都按实际读数，不写死实测值。
- 非整格滚轮增量按精确滚动平移，不累积成命令。
