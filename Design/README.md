# PhotoViewer 设计规范总则

本目录是四端（Windows / macOS / iOS·iPadOS / Android）UI 与交互的唯一设计基准。Avalonia 旧壳退役后，对标不再以任何一个平台的实现为准：先改设计，再分别在四端执行。

> 迁移期说明：`spec/`、`tokens.json`、`platforms.md`、`status.md` 由 [ui-contract.md](ui-contract.md) 拆分建立（见 [Phase 6 清单](../Plans/native-rebuild-phase-6.md) 6B）。拆分完成前 ui-contract.md 继续有效；完成后它只保留跳转说明。

## 1. 组成

| 位置 | 层 | 内容 |
|---|---|---|
| `spec/` | L0–L2 | 原则、分区、行为规则（按模块分文件） |
| `tokens.json` | L3 | 尺寸、间距、动效、颜色语义、字号层级等数值的唯一来源；生成 `PhotoViewer.Shared/DesignTokens.g.cs` 与样机数据 |
| `platforms.md` | L4 | 各平台控件选型、实现入口与已登记的平台差异 |
| `status.md` | — | 按设计 ID 记录四端实现与验收状态；规则正文不写状态 |
| `prototype/` | — | 主窗口 HTML 样机，读 tokens，可导出几何 JSON 供各平台比对 |
| `baseline/avalonia/` | — | 冻结的旧壳几何与截图，只读，仅供追溯 |
| [architecture.md](architecture.md) | — | 非 UI 的跨模块架构与流程（不在本规范分层内） |

## 2. 分层

- **L0 原则**：产品目标与不可违背的体验原则，例如键盘优先、空间优先给主图、选片进度不丢失、画质红线。
- **L1 分区**：屏幕与窗口的分区及各自职责（窗口外壳、文件栏、筛选条、胶片栏、主图、分析栏、控制栏、相似面板；设置窗口、工具窗口）。
- **L2 行为规则**：每条一个设计 ID，写清意图、触发条件、不触发的操作、边界、并发与中断、无障碍、持久化和错误状态。只比较截图不算规则。
- **L3 设计令牌**：规则里出现的数值写成令牌名，可附当前值，如 `motion.film.scroll.duration`（现 350ms）；两处不一致时以 `tokens.json` 为准。
- **L4 平台实现**：同一规则在各平台用什么控件、入口在哪个文件、哪里有登记过的差异。

## 3. 规范等级与对标强度

条款用三个等级：**必须**（四端一致，偏离即缺口）、**应当**（默认如此，偏离须登记为平台差异）、**可以**（平台自定）。

| 范围 | 对标强度 |
|---|---|
| 主窗口分区结构、几何、占位、边距、方形约束、动效参数 | 必须对齐 tokens 与样机 |
| 主窗口内的小型控件（下拉、菜单、按钮外观、tooltip、滚动条） | 功能与操作必须一致；外观可以原生 |
| 设置窗口、工具窗口 | 分类、项目、行为与持久化必须一致；视觉应当遵循各平台规范（macOS 系统设置、Win11 设置、iOS 设置、Material 3） |
| 色彩、画质、物理 100% | 必须一致，由验收素材与色卡判定，不由样机判定 |

## 4. 编号

- **设计 ID**：`<模块>-<两位序号>`，如 `FILM-03`。ID 永不复用；废弃时标"已退役"并指向替代条目。条款内的细项不另编号，需要单独引用时拆成新 ID。
- **平台差异**：`<ID>@<平台>`，平台取 `win` / `mac` / `ios` / `android`，如 `FILM-04@mac`。
- **令牌名**：点分 `域.元素.属性`，段内 lowerCamelCase，如 `film.card.width`、`nav.longEdge`。域：`shell` `filter` `film` `image` `nav` `analysis` `toolbar` `sim` `status` `exiftable` `tools` `motion` `color`。设置项的取值范围与默认值属于设置模型，不进令牌。
- **阶段号**（`P1-M4`、`I5`、`A3`、`W-M7` 等）只出现在 `Plans/` 与提交信息里，不进 `Design/` 与代码注释。
- **代码注释**：在实现某条规则的关键分支、或偏离通常写法的地方写 `// FILM-03：<为什么>`；验收断言名与报告同样引用 ID。不必逐行标注。
- 不使用 `P` 字头前缀，避免与解码优先级 `P0`–`P3`、Display P3 色域混淆。

模块前缀登记（新增前缀先在此登记）：

| 前缀 | 范围 |
|---|---|

| `FILM` | 胶片栏 |
| `IMAGE` | 主图显示、缩放、导航图 |

| `SIM` | 相似聚类面板 |

## 5. 权威顺序

作者最新决定 > `spec/` > `tokens.json` > 样机 > 冻结基线 > 各平台实现。平台实现与上层不一致即为缺口，除非已登记为 `@平台` 差异。macOS 原生壳是已通过作者验收的交互参考实现，但不是规范来源。

## 6. 变更流程

1. 改规则：在 `spec/` 新增或修订条目；数值改 `tokens.json`；影响主窗口视觉的同步样机。
2. 在 `status.md` 把该 ID 四端置为"待实现"。
3. 各平台实现，注释与验收引用 ID，完成后回填状态。
4. 实现中发现规则不可行：回到 `spec/` 修订或登记 `@平台` 差异，不在代码里悄悄偏离。

规则与实现可以在同一提交，但规则先写。

## 7. 验收状态

`代码核对` / `程序化通过` / `作者手验通过` / `待核验` / `缺口` / `延期` / `不适用`。构建通过不提升交互验收状态；每条状态注明 OS、设备、素材与证据路径；不能把一个平台的结果复制给另一个平台。

## 8. 样机与基线

- 样机只覆盖主窗口：行/列/自动布局、三档窗口尺寸、栏位显隐、胶片栏定位动画与减少动态效果。设置、菜单等原生控件不做样机。纯 HTML/CSS/JS，不引入框架。
- 样机导出的几何 JSON 与各平台验收程序导出的格式一致，用脚本比对，不需要两台机器同时运行。
- `baseline/avalonia/` 冻结后不再更新，不作为验收标准；样机校准完成后，基线只用于追溯原设计意图。
