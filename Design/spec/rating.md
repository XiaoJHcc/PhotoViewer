# 星级来源与写回（RATING）

**意图**：星级是用户对一张照片的编辑结果，必须写在照片自己身上，并让相机、外部编辑器与四端读到同一个值。同名组里每个实际存在的来源都是独立的评分事实：不排优先级、不互相遮蔽；sidecar 不存在时不创建，存在时必须一起写。写不进去要说清是哪个来源、失败在哪一步，绝不拿部分成功冒充整组成功。

数值令牌：`color.star.*`、`icon.warning`（见 [tokens.json](../tokens.json)）。平台实现与差异见 [platforms.md](../platforms.md#rating)，验收状态见 [status.md](../status.md#rating)，本轮实施与挂账见 [评分存储纠正计划](../../Plans/rating-storage-correction-plan-1.md)。

## RATING-01 来源模型：每个实际来源独立 · 必须

- 一次评分作用于同名合并成组后的一张照片。该组的评分来源是**全部实际来源**：
  1. 组内每个文件的内嵌 XMP 位置各算一个来源（有 canonical 包则读，没有记为 `缺失`；按 RATING-06，不为无包来源新建容器结构）；
  2. 每个实际存在的 `<stem>.xmp` 各算一个来源。
- 来源是否存在只看磁盘：不按"该格式通常该不该有 sidecar"推断，也不为缺席的 sidecar 预留来源。sidecar 不存在时，任何读写路径都不得创建它；已存在时必须参与读取与写入。
- 来源之间**没有读取优先级，也没有写入优先级**：不因 sidecar 存在就把它当唯一权威，也不用代表文件的值覆盖其它来源。某个来源缺 Rating 只表示它自己缺，不继承别的来源。
- 代表文件的内嵌 Rating 只用于两种口径：胶片栏与控制栏的星级显示、[FILTER-03](filter.md) 的数字与"以上"筛选。它不用于遮蔽、合并或替代其它来源。
- 来源级状态：

| 状态 | 含义 |
|---|---|
| 缺失 | 来源存在，但没有 XMP 包或包内没有 `xap:Rating` |
| 已评分 | 0–5 |
| 已拒绝 | -1（由外部写入产生） |
| 无效 | 非整数、越界或包无法按语义解析 |
| 冲突 | 同一文件内多份 canonical XMP 的 Rating 不一致 |
| 不可读 | 容器结构不识别、包损坏或读取被拒 |

- 组级 `星级冲突`：任一文件内多份 canonical XMP 的 Rating 不同，即为冲突。存在两个及以上实际来源时，任一来源缺失、无效或不可读，或可读来源取值不同，也为冲突。单个来源仅为 `缺失`（全组没有任何 Rating）不构成冲突；单来源自身 `无效` 或 `不可读` 仍算冲突，因为它无法作为可信评分。该状态驱动 [FILTER-03](filter.md) 的"星级冲突"，不得挑一个"看起来正常"的值显示为一致。
- 已拒绝（-1）是独立状态：不并入 0 星，也不当作"缺失"。

## RATING-02 安全写入：结构化定位与最小区间 · 必须

- 只改 canonical XMP 包内的 `xap:Rating`：已有值在原位改写，缺失时按 RATING-06 在包内插入；定位必须**按结构**：容器由格式适配器解析（JPEG APP1 段、HEIF `mime`/`iloc` 项、TIFF IFD0 tag 700、WebP `XMP ` chunk、sidecar 文件本体；PNG 写入本轮挂账），包内按 XML/RDF 结构定位属性或元素。
- **禁止启发式定位**：不得用正则、字符串搜索、全文扫描或"第一次出现"来定位 XMP 包与 Rating；同一结构出现多份且无法唯一确定目标时，按不支持处理。
- 写入区间取**最小**：只覆盖 Rating 值字节、紧邻的合法 XML 空白与必须同步的容器记账字段（段长、RIFF 长度、tag 的 count/offset、`iloc` 偏移与长度）。不重排、不规范化、不重写整个包，其它字节保持原样。
- 长度优先等长。**唯一允许的变长是 Rating 附近的局部空白吸收**（例如 `-1` 与 `0`–`5` 互换时的位数差）：只在这段局部范围内吞吐空白，不移动远端内容；远端 padding 移位、受控追加、整文件重写/原子替换本轮都不支持，按 `Unsupported` 处理。
- 安全模式在写入前比对目标字节与修订（revision）；被外部修改则放弃本次写入。
- 写入后回读 `xap:Rating` 做语义校验，并核对容器记账字段；校验失败按回执恢复原内容。
- **无法证明非目标数据安全**（结构不唯一、偏移不能证明、校验无法维护、需要移动远端内容或扩容）时返回 `Unsupported`，整组在首次修改前失败。
- **区分"无包"与"有包缺 Rating"**：无 canonical XMP 包（含 JPEG 无 APP1、TIFF/ARW 无 tag 700、HEIF 无 XMP mime 项、PNG/WebP 无 XMP chunk）时不新建或插入容器结构，按 `Unsupported` 处理；已有 canonical 包但缺 `xap:Rating` 时，仅在包结构唯一且空白足够容纳插入值时于包内插入 `xap:Rating`，否则同样 `Unsupported`。都不以"写 sidecar 成功"代替。

## RATING-03 全来源事务：先预检，后写入 · 必须

- **预检全部来源**：读取与解析、状态判定、写入区间定位、容器能力（等长 / Rating 附近局部空白吸收）、安全模式字节与修订比对、目标是否可写。任一来源不能安全完成，就在**首次修改前**整组失败，不产生半写。
- 写入顺序固定：代表文件内嵌 → 其余文件内嵌（按文件格式优先级）→ 每个实际存在的 sidecar。顺序只用于确定性与补偿，不代表任何来源更权威。
- 写入中失败：
  - 安全模式开启：按逆序用回执补偿已写来源，补偿后逐来源回读校验；
  - 安全模式关闭：停止后续写入，已写来源保持磁盘真值，不假装整组一致。
- 结果：`Applied` / `NoChange` / `Superseded` / `RolledBack` / `Partial` / `Canceled`。
  - `Applied`：全部来源写入并通过校验；`NoChange`：全部来源本来已是目标值，未发生任何物理修改。两者都算成功（`IsApplied`），都可回填内存、刷新筛选与更新数据库副本。
  - `Partial`：补偿未全部成功，必须逐来源重读磁盘真值并按 RATING-01 的冲突口径展示。
- **不承诺跨文件断电原子**：一次评分在断电、强杀或卷断开后可能留下来源不一致；重启后按磁盘真值呈现冲突，并在下次评分时由全来源写入收敛。
- 同组写入串行。快速连按只让尚未开始物理写入的旧请求作废（latest-wins）；已经开始写入的请求不中途取消，完整走完或回滚。取消只在首次物理修改前生效。
- 全部来源已是目标值时返回 `NoChange`，不做任何物理写入：不创建 sidecar、不重写文件、不改变文件长度。

## RATING-05 状态投影、筛选与训练快照 · 必须

- 星级显示取代表文件内嵌 Rating 的点亮星数（FILM-05、TOOLBAR-03）。已拒绝（-1）不点亮任何星，也不提供 -1 的设置入口；清零叉写 0，不写 -1。-1 的专用呈现属挂账项（见下方"边界"），不借用 0 星语义。
- [FILTER-03](filter.md) 的星级筛选共 13 项。数字档（无星级 / 一星–五星）与"以上"档按代表文件内嵌 Rating 命中：
  - 代表为 -1 时命中"已拒绝"，不命中"无星级"；
  - 代表无 Rating 时按 0 星口径命中"无星级"（与卡片显示一致）；
  - 代表为 `无效` 或 `不可读` 时不命中任何数字档，只命中"星级冲突"。
- "星级冲突"独立于数字档：冲突组可以同时命中某个数字档与"星级冲突"；数字档命中不消除冲突指示，冲突指示也不改写数字结果。
- 训练快照：DatasetBuilder 只消费实际选用的文件，不读代表值、不读不参与训练的伴侣或 sidecar。
  - 该文件内部 Rating 为 `冲突` 或 `无效`（含不可读）时**不写 Rating 快照**，保持缺失，不任选一个值；
  - 文件内部一致时按该值写入，不因其它伴侣或 sidecar 的冲突伪造、覆盖或清零。
- 数据库副本只在 `Applied` 或 `NoChange` 后用代表文件指纹更新（[architecture](../architecture.md) §5.3）；它不是产品行为真源。

**边界（挂账）**：-1 的专用图标/文案、按来源逐项设置不同值、浮窗内的来源排序与可访问性细节，本轮不定义，实现时不自行发明。

## RATING-06 支持边界 · 必须

本轮承诺真实可用的范围：

| 范围 | 内容 |
|---|---|
| sidecar | 实际存在的 `<stem>.xmp`（canonical 包可解析）读写；不存在不创建 |
| JPEG | 标准单份 canonical APP1 XMP（已有包） |
| HEIF 家族 | HEIC / HEIF / HIF / AVIF 的标准 `mime` XMP 项、单 extent、`iloc` 可定位 |
| TIFF 家族 | TIFF / ARW / DNG 的 IFD0 tag 700 canonical 包 |
| 包内缺 Rating | 已有 canonical XMP 但缺 `xap:Rating`：结构唯一且空白足够时于包内插入；否则 `Unsupported` |
| 写入方式 | 等长原位、Rating 附近局部空白吸收；远端 padding 移位、受控追加、整文件重写本轮挂账 |

以下结构本轮**挂账**，遇到时返回 `Unsupported`，整组在首次修改前失败：

- 无 canonical XMP 包（JPEG 无 APP1、TIFF/ARW 无 tag 700、HEIF 无 XMP mime 项、PNG/WebP 无 XMP chunk）：不新建或插入容器结构，不写 sidecar 顶替。
- JPEG：非标准 APP1、多份 canonical APP1、EXIF/Photoshop/extended XMP 混用导致目标不唯一。
- HEIF：`idat`、多 extent、多个 XML/RDF 项、无 XMP mime 项、长度不定或无法证明范围。
- TIFF：tag 700 不在 IFD0、位于子 IFD、重复 tag 700、BigTIFF、无 tag 700 需新增条目。
- PNG：写入整体挂账（含标准 `iTXt`；必须维护容器级 CRC 事务），本轮 `Unsupported`；`tEXt`/`zTXt`、压缩或多 `iTXt` 同属挂账。
- WebP：多个 `XMP ` chunk、需要新建 chunk 的非标准布局。
- CR3 等以 HEIF 容器承载但结构超出上表的 RAW。
- 其它专有 RAW（CR2 / NEF / RAF / ORF / RW2 / SRW）的容器差异未逐一实测：按实际结构预检，不能证明即失败，不按扩展名假定可写。
- 文件系统与存储能力：符号链接/硬链接形态、跨卷替换、云 Provider 不可定位句柄、写中断电恢复。按平台能力如实失败，不假成功（见 [platforms](../platforms.md)）。

不支持时不提供"尽力写一部分"：这些来源若在组内实际存在，整组按预检失败处理，不跳过该来源只写其它来源；不写任何来源、不建 sidecar、不用别的来源的成功掩盖失败，按 STATE-03 说明对象与原因。
