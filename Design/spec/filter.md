# 筛选条（FILTER）

**意图**：用排序键、方向与星级三个选择把当前文件集收窄到可快速翻看的一组，并随时知道还剩多少张；筛选只改变列表内容与顺序，不改变主图、不抢列表位置、不隐式触发计算。

数值令牌：`filter.*`（见 [tokens.json](../tokens.json)）。平台实现与差异见 [platforms.md](../platforms.md#filter)，验收状态见 [status.md](../status.md#filter)。

## FILTER-01 组成与统一业务语义 · 必须

筛选条位于文件栏顶部：列布局纵向排列，行布局独占文件栏顶部一整行、胶片带在其下方。固定由五项组成，顺序与含义四端一致：

| 顺序 | 控件 | 含义 |
|---|---|---|
| 1 | 排序方式 | 名称 / 拍摄时间 / 文件大小 |
| 2 | 排序方向 | 升序 ↑ / 降序 ↓ |
| 3 | 星级筛选 | 12 个取值，见 FILTER-03 |
| 4 | 筛选后计数 | 只读文本，见 FILTER-04 |
| 5 | 相似聚类开关 | 面板显隐，见 FILTER-06 |

- 控件外观用平台原生下拉/按钮；没有原生下拉的平台按 FILTER-08 的自绘外观。选项名称、业务取值、默认值与应用时机必须相同。
- 选择菜单项立即写入共享筛选状态并重算列表；没有“应用”按钮，也没有二次确认。
- 任何平台不得增删选项、改变控件顺序，或把计数做成可点击控件。
- 筛选条随文件栏整体显示/隐藏，没有独立的筛选条显隐开关（见 [shell](shell.md)）。
- 列表为空或只有一项时控件保持可用，不做“无作用”禁用态。

## FILTER-02 排序键与方向 · 必须

- 三种键：名称（文件名，含扩展名）、拍摄时间（共享照片日期，EXIF 缺失时回退文件修改时间）、文件大小（字节）。
- 不提供按评分排序；不得以星级、相似度或抖动状态暗自改变默认顺序。
- 方向只作用于当前键：换键保留方向，换方向保留键；默认名称 + 升序。
- 同键值的项保持原文件顺序（稳定排序），四端结果一致，不因平台排序 API 或异步加载打乱。
- 名称比较使用同一序数规则（忽略大小写、不随系统区域设置变化），保证四端同序；不得按显示名（同名合并后的“名称(RAW)”后缀）或本地化日期/大小文本比较。
- 排序只重排当前筛选结果：不改变成员与计数、不切换当前照片、不滚动列表（[FILM-01](film.md)）。
- 排序可在缩略图、EXIF 加载过程中执行；只换位置，不重新解码、不清空已加载内容。
- 排序不区分同名合并组的内部格式；组始终显示代表卡片，按文件大小排序取代表文件的大小。
- 合并显示名 = 代表文件名 + `(` + 隐藏伴侣的格式名按格式优先级以 `/` 连接 + `)`，如 `DSC01234.JPG(RAW)`、`DSC01234.JPG(RAW/HEIF)`。

## FILTER-03 星级筛选取值 · 必须

| 取值 | 命中条件 |
|---|---|
| 全部（默认） | 所有卡片 |
| 无星级 | 0 星 |
| 一星 / 二星 / 三星 / 四星 / 五星 | 恰好等于该星级 |
| 一星以上 / 二星以上 / 三星以上 / 四星以上 | 大于等于该星级 |
| 星级冲突 | 同名合并开启，且代表文件与任一隐藏伴侣星级不同 |

- 合并卡片的精确档与“以上”档按代表文件星级判定。

- 命中基于当前内存星级；写回成功后才改变结果，写回失败不改星级、不筛掉（[FILM-06](film.md)、[state](state.md)）。
- 筛选不修改任何评分，也不切换当前照片。
- “星级冲突”始终出现在菜单；同名合并关闭时不可能命中（结果为空），不报错、不再改成禁用项。
- 当前照片因改星落出筛选时按 FILM-06 暂留；因用户改筛选而落出时见 FILTER-05。
- **应当**：“显示评分”设置只影响评分控件与星级渲染，不隐藏或禁用星级筛选。

## FILTER-04 计数 · 必须

- 计数 = 当前筛选结果中的卡片数：已应用文件格式启用、同名合并（一组算一张）与星级筛选之后的数量；当前照片因改星暂留时，暂留项计入计数，列表与文本一致。
- 文本为 `共 N 张`，字号 `filter.count.fontSize`（12），按平台字体自然宽度占位；N=0 也照常显示，不隐藏计数、不改写成“无结果”。不加千分位，不显示“第几张”。
- 更新时机：筛选变化、文件夹重载/增删、评分写回且筛选非“全部”、文件格式或同名合并设置变化。排序不改变计数。
- 计数与列表在同一次刷新提交，不得先显示旧数字再追平；同一帧内列表与文本一致。
- 计数不受相似聚类开关、显示评分设置影响。
- 平台差异：窄屏可用紧凑文案 `N 张` 与较窄控件，见 platforms.md（FILTER-01@android）。

## FILTER-05 筛选/排序与当前照片、列表位置 · 必须

- 任何筛选或排序操作都不改变主图身份、不触发切图、不主动滚动胶片栏（[FILM-01](film.md)）。
- 重算列表保留用户滚动偏移，只夹到新的合法范围；不得回到顶部。
- 当前照片被新筛选排除时：主图继续显示它，胶片栏没有当前项高亮；此后“上一张/下一张”以当前照片在重算前列表中的索引为参照，落到新列表中最近的前/后项，不得从列表首尾重新开始。
- 当前照片仍在结果中时，只按 FILTER-02 改变其列表位置，主图与缩放状态不变。
- 同名合并后当前项若是隐藏伴侣，映射到同组代表卡片；仍视为同一张照片，不算筛选改变照片。
- 筛选重算不取消当前照片的加载/解码，不触发 AI 或 CV 计算（[SCOPE-01](scope.md)）。

## FILTER-06 相似聚类开关 · 必须

- 开关位于筛选条末位：打开即展开相似面板，关闭即收起；状态写入设置并在下次启动恢复（FILTER-09）。
- 打开时按当前照片计算相似项，关闭时取消在途计算；开关本身不改变排序、星级筛选、当前照片或列表顺序。
- 面板只在“开关打开且文件栏可见”时工作；文件栏隐藏时开关不可达、面板不显示也不计算，开关状态保留。
- 初次呈现（启动恢复、文件栏重新显示、布局重建）时开关勾选态与面板状态一致：开关打开且文件栏可见即显示面板并按当前照片计算一次；开关关闭即不显示、不计算。文件栏隐藏时只保留逻辑开关值，不显示、不计算、不排队。
- 相似候选集合取自当前筛选结果；排序不改变候选集合，筛选变化会触发重算（[similarity](similarity.md)、[SCOPE-01](scope.md)）。
- 开关只由筛选条控件触发，没有默认快捷键；不抢占主图手势或滚轮。
- 开关必须清楚表达选中与未选中。占位取 `filter.toggle.*`；原生按钮可按 TOOLBAR-10 使用系统状态外观，由同一控件配置管理背景、轮廓与高亮。自绘药丸四态取 `color.filter.toggle.*`：未勾选常态透明底 + 描边 / 未勾选悬停 `hover` 底、`hover.border`、`hover.foreground` / 勾选 `checked.*` / 勾选悬停 `checked.hover.*`。

## FILTER-07 布局与显隐 · 必须

令牌：`filter.control.width`（90）、`filter.control.height`（32）、`filter.gap`（5）、`filter.count.height`（17）、`filter.toggle.height`（27）、`filter.margin`（10）。

- 列布局：文件栏内容宽 116，三个下拉各 90×32 纵向排列，间距 5，整组水平居中；计数居中于其下，开关 90×27 紧随计数（间距 5）；首控件顶部让位取 `shell.filter.leadingInset`（34，仅 macOS 列布局的交通灯让位；Windows 沿用自身原生排布）。
- 行布局：三个下拉与计数、开关同排，间距 5，交叉轴居中；整组占高 `filter.bar.row.height`（52）。
- 组内不换行、不压缩控件宽度、不因计数变长改变下拉宽度；窄屏紧凑宽度属平台差异，见 platforms.md（FILTER-01@android）。
- 行布局默认五项整组在安全内容区内居中；iPad 同样整组居中，不做前导对齐。Android 手机行布局可从前导安全边 + `filter.margin` 起排，作为已登记的平台差异（FILTER-07@android）。
- 文件栏隐藏时筛选条与计数全部消失，空间还给主图；重新显示时恢复原选择，不重建状态。
- 行/列切换、窗口缩放只重排控件：不重算筛选、不清空菜单、不改变当前照片。
- 计数按自然文本宽度占位，不设固定宽；其宽度变化只影响整组居中，不影响控件顺序。

## FILTER-08 菜单交互 · 应当

- 自绘下拉（无原生下拉的平台）：按钮 90×32、圆角 `dropdown.cornerRadius`、底 `color.dropdown.background`（悬停 `.hover`、按下 `.pressed`）、1 点描边 `color.dropdown.border`（悬停 `.hover`）、文字 `dropdown.fontSize` 左内边距 `dropdown.paddingLeft`、右侧 `icon.chevronDown` 边长 `dropdown.chevron.size`、距右 `dropdown.chevron.rightInset`、色 `color.dropdown.chevron`。弹层贴在按钮正下方并以按钮水平居中（最小宽 = 按钮宽，越界向内夹取，下方不足翻到上方），外观同 MENU-03 自绘弹层；项左右内边距 `dropdown.item.paddingX`，当前项整行底 `color.dropdown.item.selected`（悬停 `.selected.hover`），不画勾号。

- 下拉显示当前选项；打开时当前项带勾选/选中态；选中即应用并关闭；点外部、返回键或取消不改变状态。
- 桌面支持键盘打开、上下选择、回车确认、Esc 取消，焦点回到原控件；触屏用平台菜单手势。
- 筛选条控件的悬停、按下、禁用与焦点状态不得引起布局抖动、残留旧态或裁切；原生下拉/菜单可用系统状态色与轻量状态动效（L4），自绘控件按 `dropdown.*` / `color.filter.toggle.*` 令牌。
- 菜单项与顺序固定（FILTER-03 表），不按使用频率重排，也不隐藏当前不可能命中的项。
- 每个下拉显示当前值（排序方式/排序方向/星级筛选），计数作为静态文本显示；开关的展开/收起状态以可见外观表达。
- 控件命中区不小于其可见几何；触控下拉的可点区 90×32，低于 44 点时登记为输入方式差异（FILTER-08@ios、FILTER-08@android），不得因此改变视觉占位与间距。
- 菜单打开期间照片快捷键不生效（[INPUT-01](input.md)）。

## FILTER-09 持久化与作用域 · 应当

- 相似聚类开关持久化到设置并跨启动恢复；这是筛选条唯一的持久化状态。
- 排序键、方向与星级筛选属于当前会话：切换文件夹或进入单图模式保留；重启回到名称 / 升序 / 全部。不写入设置、不新增 JSON 字段。
- 设置中影响列表成员的项（文件格式启用、同名合并）在关闭设置后立即重算列表与计数，不重置排序与星级筛选。
- 筛选条没有独立的宽度或几何持久化，几何完全由布局与令牌决定。

## FILTER-10 空结果与刷新 · 必须

- 结果为空：计数 `共 0 张`，胶片栏留空（[FILM-05](film.md)），筛选控件保持可用并显示用户选择，不自动放宽条件、不自动改星级。
- 文件夹为空、格式全部禁用与筛选无命中共用同一空状态；不弹模态，不报错误提示。
- 文件夹重载、外部打开与批量写库后，筛选与排序照旧生效；当前照片的落出/映射按 FILTER-05 处理。
- 重算不产生重复卡片、不短暂显示旧列表；解码失败的文件仍参与筛选（按已知星级与文件名），不会仅因解码失败被隐藏。
- 筛选本身没有错误态；文件或目录不可访问属于 [open](open.md) 与 [state](state.md)。
