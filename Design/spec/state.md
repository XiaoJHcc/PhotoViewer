# 加载、空与失败状态（STATE）

**意图**：任何时候用户都知道主图和列表处于什么状态：在加载、为空、失败还是操作未成功；状态提示不挡操作，失败不伪装成功。

数值令牌：`image.hint.*`、`status.*`、`motion.status.*`（见 [tokens.json](../tokens.json)）。平台实现与差异见 [platforms.md](../platforms.md)，验收状态见 [status.md](../status.md)。

## STATE-01 加载提示与延迟 · 必须
- 无照片：主图区居中显示短标题（桌面「点击打开文件 或 拖拽图片到此处」，触屏「点击打开文件夹」）与可选副提示；标题 `image.hint.title.fontSize`（16）、副文 `image.hint.detail.fontSize`（11）、最大宽 `image.hint.maxWidth`（500）、间距 `image.hint.detail.gap`（28 = 标题行高 20 + 间距 8）；提示块（标题 + 副文自然高）整体垂直居中，左右各留 ≥ `image.hint.inset`（10）；提示层不挡空态点击与拖入。
- 切图（照片身份变化）到新图上屏之间的延迟只允许下列三种呈现，按延迟能否预知选择，不得用运行时计时临时等待：

| 方案 | 适用 | 表现 |
|---|---|---|
| 保留前一张 | 稳定短于 `status.loading.holdMax`（100ms）的延迟：所需档位已在内存缓存，只剩纹理上传 | 上一张留在屏上直到新图上屏，中间不插入黑帧、不显示加载提示；新图与新几何同一帧生效 |
| 黑屏加载 | 超过 `status.loading.holdMax` 或随机型、素材而波动的延迟：需要解码；缓存里只有低于所需档位的产物（如需要 Full 时只有代理）同样按此处理 | 切图即清旧图（主图区只剩 `color.viewer.background`），不让上一张冒充当前照片；加载提示延迟 `status.loading.delay`（300ms）后出现，图一到即撤下，快速翻页在延迟内完成时不显示提示 |
| 低分辨率顶替 | **默认禁用**，只在作者登记的范围内可用；已登记范围：RAW 初次解码（可以） | 先上屏低于所需分辨率的同一张照片（如 RAW 内嵌预览），全分辨率到达后原地替换；几何基准恒为全分辨率源尺寸（IMAGE-01），顶替图在屏期间不宣称已具备全分辨率细节，细节预览与绿框不以它为源 |

- 同一张照片的代理→Full、雾天增强计算等后台工作不属于切图，不用阻塞式加载（IMAGE-03、IMAGE-07）；缩略图、EXIF、缓存状态异步补齐，不阻塞列表与主图。
- 方案选择与延迟态由共享加载会话统一给出，四端只绑定同一状态。

## STATE-02 空、失败与不可解码 · 必须
- 解码失败：主图显示标题与详情（文件名或解码器原因），不显示伪造或残留图像；该卡片仍可选中、可评分。
- 空筛选结果：胶片栏留空（不写占位文字，计数 `共 0 张` 已说明），筛选控件与条件保留、不自动放宽；主图保持原照片，没有原照片时给空提示。
- 空文件夹显示空列表（胶片栏留空、计数 `共 0 张`）；无 EXIF/无评分显示「--」占位，不隐藏控件、不弹错误；错误不升级为模态，模态只用于二次确认。
- 打开失败（文件夹无法读取、授权失效、选择器或外部打开出错）：共享打开会话保留失败前的照片与列表（首次打开则空态），或按 OPEN-03 回退为单图；存储访问租约随会话释放。同时用 STATE-03 提示条说明对象与原因要点（如「无法读取文件夹：<名称>」「无法打开：<名称>」），不得只写日志，也不得弹模态。失败文案由共享层统一给出，四端只负责显示。

## STATE-03 操作结果提示条 · 必须
- 操作结果（评分写回失败等）用主图区底部提示条：单行或自动换行，最大宽 `status.toast.maxWidth`（500），距底 `status.toast.bottomMargin`（24），字号 `status.toast.fontSize`（12），内边距 12/6，圆角 6。
- `motion.status.toast.duration`（4000）后自动消失，新提示替换旧提示并重置计时，不抢焦点、不阻断手势。
- 与「计算中」药丸（IMAGE-07）同时可见时不得重叠：药丸位置不变，提示条整体上移到药丸上方，底边距主图区底 = `image.busy.bottomOffset` + `image.busy.height` + `status.toast.stackGap`（24 + 28 + 8 = 60）；药丸收起后提示条回到 `status.toast.bottomMargin`。
- 失败不显示虚假成功：星级保持原值（FILM-06），文案含操作对象与原因要点。文案统一为 `动作：对象（原因）`，原因不可得时省略括号。

| 场景 | 文案 |
|---|---|
| 评分写回失败 | `无法写入星级：<文件名>（<原因>）` |
| 部分来源写入失败（补偿未完成） | `星级写入不完整：<文件名>（<原因>，部分来源可能不一致）` |
| 全分辨率升级失败（屏上有代理） | `无法载入全分辨率：<文件名>` |
| 打开文件夹失败 | `无法读取文件夹：<名称>（<原因>）` |
| 打开文件失败 | `无法打开：<名称>（<原因>）` |
| 内存压力关闭雾天增强 | `内存不足，已关闭雾天增强` |

提示条是唯一形式：不得用模态对话框，也不得以「只写日志」代替。评分写回失败的判定、补偿与逐来源刷新以 [RATING-03](rating.md) 为准，冲突指示与来源浮窗的保留以 [RATING-04](rating.md) 为准；提示条只说明对象与原因要点，不把部分成功写成成功。

## STATE-04 模型、推理与数据库不可用 · 应当
- DINO 模型缺失或推理失败：不做隐式计算、不弹全局错误；相似聚类在面板内显示可读失败文案，DINO 诊断页显示状态文本与空瓦片。
- 清库需二次确认，执行后徽标、分析栏、相似面板立即失效并在下次可见时重算；存储/权限/写回错误走同一提示路径（STATE-03），可继续的浏览与评分不被阻断。
- 单张失败不阻断整批：批量提取跳过失败组继续，结束时报告失败。
