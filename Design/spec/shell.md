# 窗口外壳（SHELL）

**意图**：主图优先占据空间，栏位只在用户要求时让位；窗口装饰、拖动区与栏位显隐不得夺走照片、筛选或列表的操作。

数值令牌：`shell.*`、`film.band.height`、`motion.*`（见 [tokens.json](../tokens.json)）。平台实现与差异见 [platforms.md](../platforms.md)，验收状态见 [status.md](../status.md)。

## SHELL-01 布局模式、分区与栏位显隐 · 必须
- 四种布局模式：行布局（文件栏在上、控制栏在下）、列布局（文件栏在左、控制栏在右）、自动、手机。行与列以宽形态的分区排布；自动按窗口与设备判定形态（SHELL-07），两轴都常规时在宽形态内按窗口内容区宽高比取行或列（宽 > 高取列布局），随尺寸与旋转重算，不依据照片横竖；手机模式进入手机形态。手动模式不因尺寸改变，窗口比例如与模式不符仍按所选模式排布。
- 宽形态的分区与几何：

| 分区 | 列布局 | 行布局 | 显隐 |
|---|---|---|---|
| 文件栏 | 左列，内容宽 `shell.filebar.content.width`（116）+ `shell.divider.thickness`（1）分隔线 | 顶行：筛选条 + 胶片栏带 `film.band.height`（159）+ `shell.divider.thickness`（1）分隔线 | 可隐藏 |
| 相似面板 | 扩宽文件栏 | 从胶片栏右侧切出 | 随筛选条开关 |
| 主图 | 剩余空间 | 剩余空间 | 恒显示 |
| 分析栏 | 主图右侧 | 主图下方 | 菜单/命令 |
| 控制栏 | 右列，按内容测量 | 底行，按内容测量 | 可隐藏 |

- 分析栏与控制栏相邻时组成一个工具区（SHELL-12）。
- iPad 宽形态左右布局的内容不避让顶部与底部系统安全区，列表与控制栏纵贯窗口；只有左上角筛选/更多浮动组按自身列位置的系统窗口控件避让区向下让位，不把这份让位套到胶片栏、列表或右侧工具区。左列整体靠主图侧对齐：筛选/更多合体、胶片卡片外框与相似聚类开关共用同一条内容末端锚点，列宽由避让后的列表占用与入口占用取较大值（FILTER-07、FILM-07）。上下布局继续使用顶部安全区；所有横屏主屏均不为底部手势条保留安全区，竖屏仍按原规则避让。刘海、屏幕圆角、窗口控件与非手势导航系统栏的避让不受此规则影响。
- 分区表里的主图矩形就是主图的**适应区**（SHELL-11）；主图视图本身始终铺满窗口，照片在适应区内适应，放大后可以越过栏缘铺到栏位与按钮下方。
- 文件栏与控制栏可独立显隐，分析栏由菜单/命令开关；隐藏即主轴归零、分隔线消失，腾出的空间全部并入适应区，不留最小占位；适应区不得被任何栏位压到零。手机形态另有只作用于该形态的 EXIF 开关（SHELL-08、SHELL-09），宽形态控制栏的 EXIF 块仍随 EXIF 显示项出现。
- 显隐与换向不改变当前照片、筛选条件、列表位置与缩放状态；重新显示胶片栏或换向时显式定位当前项（FILM-04）；布局切换只重排，不重建视图、不重载照片。
- 切换布局或换向会废弃正在播放的胶片栏定位并取消排队请求，下一次显式定位按新几何重算（FILM-03）；切换本身不播放布局过渡动画。
- 相似面板在列布局扩宽文件栏、行布局从胶片栏右侧切出；116 仍是无遮挡时文件栏内容宽基准，筛选条不因面板出现而改变筛选控件的占位与末端对齐。
- 方形元素（照片区、方形按钮、瓦片）不因原生控件或文字长度拉长（PRIN-03）；栏位隐藏时其命令仍可用，恢复后回到原状态。

## SHELL-02 标题栏、拖动区与标题栏双击 · 必须
- 除下述行布局窄宽度回退外，桌面主窗口内容延伸至窗口顶边；标题栏是浮在内容之上的覆盖层，不占布局高度，高 `shell.titlebar.height`（32）。指针进入顶边热区 `shell.titlebar.hotzone.height`（50）才显示，移出热区、离开窗口、窗口失焦或应用切换即收起；不可见时零命中区域、顶部不可拖动。显隐不播放过渡动画（SHELL-06）。
- 标题栏由标题文字、拖动区与窗口按钮组成。标题文字单行、不参与命中（属于拖动区），放不下时尾部截断，可用宽度不足时隐藏；字体与颜色取平台标题栏文字样式（Windows `CaptionTextBlockStyle`，macOS `titleBarFont`）。Windows 标题格式为 `文件夹名 - 文件名 - PhotoViewer`；无文件时只显示 `PhotoViewer`，文件夹段与文件段同名时不重复，应用名固定保留在末段；macOS 显示窗口标题（当前文件名，无文件为 `PhotoViewer`）。标题文字同时写入系统窗口标题，供任务栏、窗口菜单与调度中心读取。
- 跨度、显隐与背景随布局：

| 状态 | Windows | macOS |
|---|---|---|
| 列布局，文件栏可见 | 全窗口宽，盖住文件栏；深色亚克力 | 全窗口宽，盖住文件栏；毛玻璃 |
| 行布局，文件栏可见且宽度足够 | 全窗口宽悬停覆盖层，无背景；中间挖空筛选条可点控件的水平范围（全标题栏高），其余部位都是拖动区 | 同左 |
| 行布局，文件栏可见且宽度不足 | 窗口顶边独立通栏，常态显示并占 32 点布局高度；文件栏整体下移；深色亚克力，不挖空 | 窗口顶边独立通栏，常态显示并占 32 点布局高度；文件栏整体下移；毛玻璃，不挖空 |
| 文件栏隐藏（任一布局，含行布局关闭顶部胶片栏） | 全窗口宽悬停覆盖层；深色亚克力，不挖空 | 全窗口宽悬停覆盖层；毛玻璃，不挖空 |

- 文件栏隐藏时筛选条也随容器隐藏，因此不再有筛选挖空；两种桌面平台都必须显示完整的全宽材质标题栏，macOS 不得沿用行布局文件栏可见时的无背景分段形态。
- 行布局窄宽度回退按实际几何判定，不设固定窗口宽度阈值：取得筛选条全部可点控件的联合水平范围，以及平台窗口控制器的实际占用范围（Windows 四个自绘按钮、macOS 系统交通灯）；任一窗口控制器若无法在不覆盖筛选挖空的情况下落位，即进入回退。不得压缩筛选控件、缩小或移动窗口控制器，也不得让二者重叠；标题文字先按既有规则截断或隐藏，不参与回退判定。
- 回退时标题栏位于整个文件栏上方，筛选条、胶片栏与行布局相似面板保持原有尺寸和相对顺序并整体下移，主图让出这 32 点高度。标题栏不依赖顶边热区，指针移出、离开窗口或窗口失焦后仍保持可见与可拖动；不再设置筛选挖空，除窗口控制器外的完整通栏均为拖动区。宽度恢复到控制器与筛选挖空不再相交时，回到悬停覆盖层并释放布局高度；形态切换不播放过渡动画，不改变当前照片、筛选条件、列表位置与缩放状态。全屏时不保留该常驻布局行，仍按各平台既有全屏标题栏规则处理。
- 背景材质只用平台原生定义（Windows 应用内亚克力、macOS 标题栏毛玻璃，均为深色）；材质覆盖层必须位于窗口内容之上，真实模糊其下的照片、栏底与控件，不得退化为回退纯色；标题文字与窗口按钮位于材质之上，不参与模糊。不建附属窗口或表层模拟：独立弹层窗口会盖住系统窗口描边与圆角，拖动、最大化动画也不跟随。材质选型与 Windows 窗口内合成实现见 platforms.md（SHELL-02@win）。
- 标题文字位置：Windows 左缘距标题栏左缘 `shell.titlebar.title.leftInset`（12），垂直居中；macOS 左缘距最右一个交通灯右缘 12，垂直中线对齐交通灯中线。行布局悬停覆盖层的标题文字止于筛选挖空左缘前 12；窄宽度常驻栏没有筛选挖空，Windows 标题文字止于窗口按钮组前 12，macOS 止于窗口右缘前 12。
- 需要自绘窗口按钮的平台（Windows）去掉系统标题栏，保留系统边框、缩放边缘与圆角；右上角按钮从左到右为全屏、最小化、最大化、关闭，紧贴窗口顶边与右缘、按钮间无间距，外框 `shell.titlebar.button.width`（46）× 标题栏高、无圆角，字形 `shell.titlebar.button.glyphSize`（10）；关闭按钮悬停/按下取 `color.titlebar.close.hover` / `color.titlebar.close.pressed` 且字形转白。字形、提示与读屏名随窗口态切换：最大化 ↔ 还原（最大化态）、全屏 ↔ 退出全屏（全屏态）。行布局无背景时按钮同样只画字形与状态底。字形码位与状态画刷见 platforms.md（SHELL-02@win）。
- Windows 拖动区登记为系统 caption 非客户区，只在标题栏可见时登记，排除窗口按钮与筛选挖空；拖动、双击、拖到屏幕边缘贴靠均由系统处理，不手动发 `HTCAPTION`、不自绘拖动。全屏态标题栏照常悬停显示以便退出全屏，但不登记拖动区，双击留给主图。自绘最大化按钮不提供系统贴靠布局浮层（SHELL-02@win）。
- macOS 交通灯保持系统位置、外观与常显行为，不移动、不重绘；进入系统全屏后自绘标题栏不显示，顶部交给系统。Windows 与 macOS 的列布局文件栏筛选控件避开标题栏，首控件顶边按 `shell.filter.leadingInset`（42 = 标题栏高 32 + `filter.margin` 10）让位；文件栏底材质仍延伸至窗口顶边。
- 拖动区不得覆盖筛选控件、栏位开关、窗口按钮、交通灯或照片/胶片栏手势；拖动区本身不拦截滚轮、右键与键盘。
- macOS 拖动区内双击按系统“双击标题栏”偏好执行：系统取值为最大化（Zoom/Fill）、最小化、不动作，缺省最大化/缩放；执行后吞掉事件，不落到主图；偏好改变即时生效。判定按落点是否在拖动区内，不依赖鼠标先悬停预热。Windows 双击由系统 caption 处理。
- 全屏无拖动区时不接管双击，留给主图。
- 系统窗口命中优先于内容：系统标题栏、交通灯、拖动区、缩放边缘与系统 resize 区域先于主图空态点击处理；壳不得用任意固定边缘像素猜测系统缩放区，主图只响应自身实际视口内未被这些区域占用的有效点击（INPUT-03、INPUT-10）。
- 触屏平台无窗口装饰与标题栏双击。iOS / iPadOS 与 Android 主界面统一按方向处理底部系统手势条：横屏请求系统自动隐藏，不为手势条保留安全区（SHELL-01）；系统仍可临时显示手势条，不改变主界面布局；竖屏交还系统默认显示并保留安全区。Android 三键导航保持显示和避让。顶部状态栏规则独立：iOS 始终隐藏；Android 横屏隐藏、竖屏显示，隐藏后释放对应安全区。设置与栏位显隐由主图长按菜单承担；两端按真实系统栏与刘海 insets 布局。见 platforms.md（SHELL-02@ios、SHELL-02@android）。

## SHELL-03 全屏、窗口尺寸与最小尺寸 · 必须
- 桌面提供系统全屏（系统按钮、菜单或自绘全屏按钮）；进出全屏沿用当前布局与栏位显隐，不重建视图、不重载照片，不改变当前照片、缩放与列表位置；退出回到进入前的窗口帧，不落在最大化态。
- 桌面默认窗口 `shell.window.default.width`（1200）×`shell.window.default.height`（850），最小 `shell.window.min.width`（560）×`shell.window.min.height`（480）；最小尺寸按逻辑点，不随系统文字缩放放大（文字缩放只影响内容排版，溢出按 TOOLBAR-08 滚动）。最小尺寸下布局仍合法，主图不小于 1 点，栏位可继续隐藏。
- 触屏平台不设固定默认/最小窗口尺寸，由系统窗口、分屏或 Stage Manager 决定；不提供全屏入口，系统栏隐藏由平台负责；布局按实际尺寸计算，不套用桌面最小值。
- 最大化、还原、全屏、退出全屏往返后，栏位比例、当前照片、缩放与列表位置不变；最大化不是全屏，全屏不是最大化。
- 设置与工具窗口使用各自的窗口形态与最小尺寸，不受主窗口尺寸规则约束（见 SETTINGS、TOOLS）；主窗口关闭时先关闭这些窗口。

## SHELL-04 窗口与栏位状态持久化 · 应当
- 应当跨会话恢复：布局模式、桌面窗口位置与尺寸、全屏态、文件栏/控制栏显隐；实现手机形态的平台另恢复手机形态的 EXIF 开关；恢复时把窗口帧夹到当前可用屏幕，屏幕移除、分辨率或缩放变化后不得落在屏幕外。
- 恢复顺序：先应用布局模式与栏位显隐，再恢复窗口帧，最后恢复全屏；避免启动后二次布局与可见闪烁。
- 不持久化：排序与星级筛选、当前照片、列表滚动位置、缩放与雾天增强开关（均为会话状态）。相似聚类面板展开状态属于 AI 版私有视图状态，经 `IViewStateStore` 跨会话保留，不进设置文档（SIM-01）；标准版不读取、写入或恢复该状态（EDITION-06）。
- 首次启动、存储损坏或越界值：回退默认尺寸与全显示，不阻塞启动、不覆盖用户设置、不写回损坏值。

| 状态 | 持久化 | 说明 |
|---|---|---|
| 布局模式 | 是 | 设置 JSON |
| 窗口帧 / 全屏 | 桌面应当 | 平台偏好存储 |
| 文件栏 / 控制栏显隐 | 是 | 平台偏好存储（四端） |
| 手机形态 EXIF 显隐 | 是 | 平台偏好存储（实现手机形态的平台，默认开） |
| 相似聚类面板展开 | 是 | `IViewStateStore`（视图状态，不进设置 JSON） |
| 排序 / 星级筛选 | 否 | 会话状态 |
| 当前照片 / 列表滚动位置 | 否 | 会话状态 |
| 缩放 / 雾天增强开关 | 否 | 会话状态 |

- 四端都把文件栏/控制栏显隐写入平台偏好存储（键名沿用 `PhotoViewer.Native.ShowFilm` / `ShowControls`，不进设置 JSON）；实现手机形态的平台另把手机形态 EXIF 开关写入同一存储（`PhotoViewer.Native.ShowExif`，默认开，同样不进设置 JSON）。分析栏仍为会话态。窗口帧：macOS 用 frame autosave，其余平台能恢复则恢复，不能则按上一条夹取后使用默认帧。见 platforms.md（SHELL-04@mac、SHELL-04@ios）。

## SHELL-05 跨屏与显示环境变化 · 应当
- 窗口移到不同缩放的显示器、系统缩放变化、旋转或分屏尺寸变化时，重算逻辑尺寸与物理倍率；按 IMAGE-03 保持同一图像点居中与同一相对倍率，不重读文件、不回到适应态。
- 显示色域、显示器配置文件或系统色彩管理状态变化时，保持源工作空间与图像缓存不变，只更新输出转换与表面标签，不重新解码。系统负责显示器转换时不再叠加应用端显示器 ICC；系统未管理时按当前显示器配置文件转换，无可用配置文件则按 sRGB 回退。主图、导航图、缩略图与细节预览必须各自具有明确的色彩解释，不把原色编码值直接重贴另一色域标签。观片环境保持深色（PRIN-09），不随系统亮/暗切换。本条只约束主窗口；设置与工具窗口的外观归 SETTINGS-03 / TOOLS-01。
- 跨屏或系统缩放引起的窗口尺寸变化属于普通 resize：胶片栏只把偏移约束到合法范围，不重新定位当前项（FILM-01）；主图按 IMAGE-03 重建，正在播放的定位/缩放动画按新视口收敛或取消，不让旧坐标继续推进。
- 平台无法提供真实物理倍率或广色域表面时如实降级并登记，不把逻辑点 100% 冒充物理 100%，也不宣称已管理色彩（SCOPE-02）。

## SHELL-06 窗口级输入边界 · 应当
- 自绘窗口按钮（最小化、最大化/还原、全屏、关闭）必须能用指针、触屏与键盘触发，并有悬停提示；拖动区只负责拖动窗口，不承载命令，也不截获窗口级按钮的点击。
- 布局切换、全屏切换与拖动区显隐本身不新增过渡动画；系统开启减少动态效果时同样直接到位，布局数学与命中区域不变。
- 触屏上用长按菜单承担窗口级入口，不要求用户点中隐藏热区；可点击的窗口级控件触控目标不小于 44 pt，纯展示的标题文本不参与命中。
- 窗口帧恢复失败不阻塞主流程：按 SHELL-04 把帧夹到当前可用屏幕并保持可用布局，不弹模态；不新增「全屏失败」提示（系统全屏接口无失败回报）。

## SHELL-07 主屏形态与判定 · 必须

主屏只有两种形态：**宽形态**（SHELL-01 的上下 / 左右 / 自动分区）与**手机形态**（竖屏、横屏两种排布，SHELL-08、SHELL-09）。判定依据只有平台原生尺寸类别、设备类型与用户选定的布局模式（SETTINGS-08），与照片横竖无关；下表自上而下取第一条命中：

| 条件 | 形态 |
|---|---|
| 平台没有手机形态 | 宽形态 |
| 设备本身是手机 | 手机形态，忽略用户选定的模式 |
| 用户模式「手机」 | 手机形态 |
| 用户模式「自动」，且任一轴为平台原生紧凑尺寸类别 | 手机形态 |
| 用户模式「自动」，两轴都是平台原生常规尺寸类别 | 宽形态 |
| 用户模式「行」或「列」 | 宽形态 |

- 手机形态内，窗口宽大于高用横屏排布，否则用竖屏排布。
- 形态切换与旋转保持当前照片、缩放中心与相对倍率（IMAGE-03），胶片栏定位遵守 FILM-01–FILM-04。手机形态的胶片栏轴向只由形态决定（竖屏横向、横屏纵向），不沿用此前行/列布局留下的方向。
- 平台是否支持手机形态由能力开关决定，未支持平台的模式列表不出现「手机」、读到该值按自动处理（SETTINGS-08）。

## SHELL-08 手机竖屏槽位 · 必须

竖屏自上而下为顶部行、顶部栏体、主图、底部栏体、底部行：

| 区域 | 前端（左） | 中间 | 末端（右） | 栏背景 |
|---|---|---|---|---|
| 顶部行 | 筛选控件 | EXIF 块（手机形态 EXIF 开关打开且有显示项时） | 更多 | 显示分析栏时才有 |
| 顶部栏体 | 分析栏（出现时） | — | — | 同上 |
| 主图 | 主图 | — | — | — |
| 底部栏体 | 胶片栏（出现时） | — | — | 显示胶片栏时才有 |
| 底部行 | 上一张/下一张合体 | 星级控件，占满剩余宽度 | 可选命令合体（最多三段） | 同上 |

- 筛选控件与更多常驻，不随胶片栏、控制栏或 EXIF 开关隐藏；EXIF 块只由手机形态 EXIF 开关与 EXIF 显示项决定（SHELL-12）。
- 顶部行有两种位置：带 EXIF 块时三者同行，行上缘贴灵动岛/刘海安全区下缘（无遮挡时距窗口缘 `shell.phone.rowInset`）；不带 EXIF 块时筛选与更多上移到灵动岛/刘海两旁的显示区——按钮内缘贴安全区、下缘贴安全区上缘、上缘距窗口缘不少于 `shell.phone.edgeMargin`（16），且不低于带 EXIF 时的位置（无遮挡的窗口两者重合）。整行宽度不够时 EXIF 按 TOOLBAR-05 等分压缩，压到零宽仍按带 EXIF 的位置排，不在同一帧里改切耳区。
- 行内元素高 `shell.glass.button.size`（44）；可选命令的触控边长取 `shell.phone.command.size`（44），同一行元素居中对齐；两端距该行所在带的避让线（SHELL-10）`shell.phone.edgeMargin`（16）；组与组之间 `shell.glass.group.gap`（8）。
- 贴灵动岛与刘海的边直接贴系统安全区边，不叠加 `shell.phone.rowInset`；没有实物遮挡的边（如 iPad 手机模式的顶边）至少留一份 `shell.phone.rowInset`。
- 底部行按产品规则压进 Home 指示条的安全区：最多压入一份 `shell.phone.rowInset`，且不比本行两端更贴窗口缘。
- 关闭「显示上下张按钮」（SETTINGS-17）后不显示上一张/下一张合体，让出的横向空间并入星级控件；该合体还要求「控制栏」开关打开（它属于底部行）。
- 开关各管各的栏：「胶片栏」显隐收起胶片条；「控制栏」显隐收起底部行（上一张/下一张、星级控件、可选命令）；EXIF 开关只收起 EXIF 块。转回竖屏时 EXIF 由该开关单独决定。
- 可选命令组宽度随生效项数变化，无命令时不留槽位或组间距；若底行没有内容，适应区和胶片栏不预留按钮行。
- 栏背景与控件材质见 SHELL-12，图区与避让见 SHELL-10、SHELL-11。

## SHELL-09 手机横屏槽位 · 必须

横屏自左向右为刘海侧列、主图、分析栏（出现时）、控制栏；下表以刘海在左、下巴在右为例，刘海在另一边时整体水平镜像：

| 列 | 内容 |
|---|---|
| 刘海侧列 | 上：筛选/更多合体；中：胶片栏，不被刘海遮挡；下：上一张/下一张合体，横向排列（胶片栏开关与「显示上下张按钮」同时满足时显示） |
| 主图 | 主图 |
| 分析栏 | 分析栏（出现时），竖向一列 |
| 控制栏 | 自上而下：EXIF 块（无衬底纵排，手机形态 EXIF 开关打开且有显示项时）、星级控件、可选命令竖排合体（最多三段）；工具区的间距与居中见 SHELL-12 |

- 筛选与更多常驻且始终是同一个合体：位于刘海侧列顶端，胶片栏开关不改变它的位置与列宽；关闭胶片栏只收起列表、上下张与刘海侧栏背景，合体裸浮，主图避让仍到同一条列缘。横屏不把两者拆到刘海上下两旁的耳区（竖屏无 EXIF 时的耳区不受影响）。
- 刘海侧列整体靠主图侧右对齐（刘海在右时水平镜像）：筛选/更多合体、胶片卡片外框与可见的上一张/下一张合体共用同一条内容末端锚点；锚点 = max(列表避让刘海后的末端, `filter.margin` + 入口宽)，列宽 = 锚点 + 一份卡片尾侧内边距。
- 列表在刘海所在的中段独立避让：每档列表保留自身交叉轴内边距，靠刘海一侧的卡片内边距让进安全区；顶部与底部入口不整体扣刘海宽，可伸进刘海上下两侧的显示区，但不越过窗口缘。列表全高贯穿窗口，首卡停在入口合体末端后一份 `filter.margin`，末卡停在上下张上缘前同一份间距（无上下张时距底边同样一份）；入口合体与上下张按该列自身位置的原生圆角/窗口控件带加同一份 `filter.margin`。列表仍从入口合体下方滚过，边缘模糊交给系统滚动边缘效果。
- 上一张/下一张合体只在「胶片栏」可见且「显示上下张按钮」打开时出现；显隐不改变入口合体的位置与列宽。刘海侧栏背景只在胶片栏可见时铺满该列。
- 控制栏取 SHELL-12 的共同工具区几何，下巴侧对称安全内缩不参与落位。独立上一张、下一张只在组合开关关闭时可以按 SETTINGS-08 进入可选命令组。
- 开关各管各的栏：「控制栏」显隐收起整列（EXIF 块、星级控件、可选命令）；「胶片栏」显隐收起胶片条与上一张/下一张合体；EXIF 开关只收起 EXIF 块，且在横屏须控制栏可见才出现。筛选与更多不随任何开关隐藏。
- 长度不足时星级控件先保住紧凑态最短长度 `rating.compact.minLength`（88）；EXIF 只按整项显示、裁掉末尾项，被裁的项仍可点 EXIF 块进入详情查看（TOOLBAR-05、TOOLBAR-06）。一项都放不下时 EXIF 不出现，星级长度封顶展开态固有长度（224），整组两端均分剩余空间；右侧工具区的背景仍由分析栏或实际可见 EXIF 决定。
- 右端自内向外依次是分析栏、控制栏，保持单列且不滚动；工具区材质与外边界见 SHELL-12。控制栏关闭时分析栏直接贴窗口外缘。
- 评分显隐对控制槽位的影响统一见 TOOLBAR-03。

## SHELL-10 手机形态安全区与贴角避让 · 必须

- 系统安全区与屏幕圆角是两种独立的避让：系统安全区是状态栏、刘海、导航条等矩形遮挡，先按屏幕方向归一（横屏不为底部手势条留位，竖屏不变），再参与几何；屏幕圆角与窗口控件只约束贴到窗口角的元素带（竖屏顶部行、竖屏底部行、横屏刘海侧列、横屏控制栏），避让量取**该带元素实际位置与实际外形**上的圆角适应值，且只在带的方向上生效——竖屏两行水平让位，横屏两列垂直让位；其余元素、胶片栏与主图不避让圆角与窗口控件。同一条边上两者取较大者作为该带的避让线，带的边距（`shell.phone.edgeMargin`、`filter.margin`、`toolbar.padding`）从避让线量起，不把两者相加。
- 贴灵动岛与刘海的元素直接贴系统安全区边，不叠加 `shell.phone.rowInset`。没有实物遮挡的边（如 iPad 手机模式的顶边）至少留一份 `shell.phone.rowInset`。竖屏底部行按产品规则压进 Home 指示条安全区（SHELL-08）。横屏下巴侧的系统对称安全内缩不参与控制栏落位（SHELL-09）。
- 探针按元素实际位置取：竖屏顶部行在顶行的行位置按左右两半探测，竖屏底部行在底行位置探测；横屏刘海侧列在筛选/更多入口合体的实际范围（88 宽 × 全高）上探测，下巴侧控制栏在控制内容列（44 宽 × 全高）上探测。每条带只取自身方向的适应值，其他方向由系统安全区给出。
- 例：iPad 的窗口控件只把竖屏顶部行向右推、把横屏刘海侧列向下推，宽形态左右布局只把左上角筛选组向下推，不让整窗、其他行、胶片栏、列表或工具区跟着让位。
- 栏背景铺到窗口边缘，不参与避让。
- 横屏底部手势条不作为遮挡；贴角带仍保留独立的圆角与窗口控件避让。其余控件都落在上述归一后的安全区内，只有两处例外：横屏刘海侧列的顶端合体与末端上下张可伸进刘海上下两侧的显示区（横向位置由内容末端锚点决定，不按刘海整宽扣除），以及横屏控制栏贴下巴一侧（下巴侧的系统对称安全内缩不是实物遮挡，控制栏按 SHELL-09 的桌面列布局落位）。
- 命中区不小于 44×44。

## SHELL-11 主图适应区与图区避让 · 必须

- 主图视图在所有形态下都铺满整个窗口；适应态的照片落在**适应区**内，放大后的内容可以越过栏缘、铺到栏位与按钮下方直到窗口边缘，平移边界让照片边缘贴到适应区边缘。
- **透明边栏**：每一行/列元素都视作一条边栏，栏缘 = 元素内缘 + 该栏按所属区域确定的尾侧内边距，有没有背景都一样；手机普通行、宽形态文件列与工具区分别取 SHELL-08/SHELL-09、FILTER-07、SHELL-12 的几何。适应区的边就是这条栏缘。只有一个按钮的行（例如只剩「更多」）也按整条栏处理，不做异形避让。
- 手机横屏左缘取整列栏缘：列表隐藏后入口合体仍可见，主图仍让到同一条列缘（SHELL-09），不因胶片栏关闭而放松。宽形态关闭文件栏时筛选控件、相似开关与胶片栏一起隐藏，适应区接管腾出的空间。
- 竖屏没有 EXIF 块时筛选与更多上移到灵动岛/刘海两旁（SHELL-08），适应区仍让到按钮内缘 + `shell.phone.rowInset`，不比只避让灵动岛更贴边。
- 没有边栏的边只避让真正遮挡画面的刘海/灵动岛（竖屏顶边、横屏刘海侧）；Home 指示条与下巴侧的系统对称安全内缩不参与避让。
- 宽形态：适应区就是 SHELL-01 分区表里的主图矩形。
- 导航图、状态提示条、加载提示、计算中药丸与空态文字都相对适应区落位。

## SHELL-12 栏位材质与原生控件 · 必须

- **共同几何**：分析栏与控制栏相邻时（手机横屏右侧、宽形态左右布局的主图右侧、宽形态上下布局的主图下方）合成一个**工具区**；外边距 `toolbar.padding`（10），分析内容与控制内容之间唯一接缝 `shell.toolRegion.spacing`（8），组与组之间 `toolbar.group.spacing`（10）。独立分析栏的交叉轴 = 瓦片边长 + 2 × `analysis.panel.padding`（20）；相邻时改为瓦片边长 + 朝主图一侧的 `toolbar.padding` + 接缝，靠控制栏一侧不再叠加面板内边距；手机竖屏分析栏取瓦片边长 + 2 × `shell.phone.rowInset`（16）。独立控制栏按单列排布时内容宽 `shell.glass.button.size`（44）、两侧各 10（列宽 64），与分析栏相邻时省略靠分析栏一侧的 10、只保留窗口侧 10；宽形态控制栏可整组换列，列宽随实际配置测量。纵列内容在该列自身位置的系统圆角可用区内上下各留 `toolbar.padding`（10）后同轴居中。
- **材质与边界**：iOS 的系统深色模糊材质是栏底颜色参照。macOS 与 Web 用窗口内背景模糊加一层半透明中性深灰，Android 按 API 级别分级取样（见下一条），Windows 保留应用内亚克力，仅降低主窗口亚克力的亮度层不透明度，让栏底随照片明暗变化；与标题栏使用相同配方。独立色层取平台对应的 `color.bar.overlay` 与 `shell.bar.overlay.opacity`；每端使用一组固定值，使纯黑、50% 灰（sRGB `#808080`）、纯白照片衬底上的栏底尽量接近 iOS。工具区由一个连续的材质宿主承载，只在朝主图的外边界画一条 `shell.divider.thickness`（1）分隔线，内部不画实体分隔线；宿主按所在栏位的完整范围铺满（列布局为整列全高，行布局为整段全宽），覆盖实际可见的分析栏与/或控制栏内容，隐藏区域占位为零，背景不参与几何。
- **Android 栏底与带衬底 EXIF**：主图在所有 API 级别统一由 `TextureView` 承载，照片层就是取样源；产品路径不截屏、不用 `PixelCopy` 或离屏拷贝模拟模糊。API 31 及以上从真实照片层取样，配方依次为 vibrancy（`shell.glass.android.bar.vibrancy.saturation`，饱和度 1.5）→ blur（`shell.bar.blur.radius@android`，80dp）→ 既有色层 `color.bar.overlay@android` × `shell.bar.overlay.opacity@android`；API 33 及以上在模糊前另按 `shell.glass.android.bar.tone.gamma` 做统一 sRGB 响应校准，API 31/32 保持线性回退。栏底在自身边界使用 Clamp，不把透明外扩层参与模糊，屏幕边缘不得因此逐渐清晰。有衬底的 EXIF 块使用同一照片层与同一模糊配方、不应用栏底 gamma，其上叠 `color.toolbar.block.background` × `shell.glass.android.exif.tint.opacity@android`；无衬底变体（TOOLBAR-05）保持透明，不取样也不叠色层。API 24–30 不取样，保留同一色层外观。
- **Android 玻璃控件**：手机形态的圆按钮、筛选/更多合体、星级胶囊，宽形态的筛选合体、命令圆按钮、星级胶囊与 AI 版相似聚类开关，都使用同一套主屏按钮组件，正常显示时透出其下的照片、栏底与栏内容；胶片列表从筛选控件下方滚过时，卡片经玻璃折射可见。API 33 及以上为完整液态玻璃（取样、饱和度、模糊、G2 形状、折射、高光与投影）；API 31–32 只有饱和度、模糊与表面色，无折射与着色器高光；API 24–30 不取样，使用正式色层外观。所有版本的版式、锚点、命中区、触摸、滚动、读屏与焦点一致，只有材质按系统版本分级（TOOLBAR-10）。
- **Android 玻璃弹出层**：星级弹窗、筛选下拉、主图长按菜单与「更多」菜单都在主窗口内的玻璃面板上呈现，面板透出其下的照片、栏位与玻璃按钮。面板出现时铺一层覆盖全窗的透明拦截层：点面板外只关闭面板，该次点按不穿透到底层；返回键按既有顺序先关闭面板；读屏把面板当作模态，背景内容对读屏隐藏且不可交互。键盘焦点移入面板，关闭时归还仍有效的入口；触摸操作保持触摸模式，关闭后入口不显示焦点描边。出入场只做淡入淡出，时长取系统 `config_shortAnimTime`；减少动态效果时直接显示与收起。面板的位置、尺寸、内容、方向、菜单勾选与触摸转交仍按 RATING-04/07、FILTER-08、MENU-01/03/06。材质按上述版本分级：API 33 及以上完整，API 31–32 为饱和度、模糊与表面色，API 24–30 为正式色层外观，所有版本都在主窗口内呈现。
- **校准方法**：只在深色常态下截取实际产品画面。三种衬底必须是真正铺进栏位背后的主图——纯色 sRGB `#000000`、`#808080`、`#FFFFFF` 满窗显示，不用适应态留黑或空态代替。采样取同一栏底与同类栏上按钮的内部区域，避开字形、边缘与高光，转为 sRGB 8 位后取中位数。分别比较三张衬底上栏底与按钮相对 iOS 的差值，取同一组固定参数在三处的折中，不为单张衬底另调参数，也不按图切换。校准范围是栏底与栏上按钮的常态底材，不含裸放在照片上的按钮，也不含液态玻璃的折射、边缘高光等光学细节。按钮参数见 TOOLBAR-10，各端参数与当前读数见 platforms.md（SHELL-12）。
- **出现条件**：有分析栏或实际显示 EXIF 时铺满实际工具区；只有评分与命令（无分析栏、无实际 EXIF）时透明、不画分隔线，控件自身的玻璃材质保留。
- 其余栏位的背景出现规则：竖屏顶部行只在显示分析栏时有背景，EXIF/顶部行与分析瓦片之间共享一份 `shell.phone.rowInset`，不画分析栏顶部的分割线，也不叠加两层内边距；竖屏底部栏（胶片栏与其下的底部行）只在显示胶片栏时有背景，否则按钮直接叠在照片上；横屏刘海侧列在有胶片栏时有背景。宽形态中文件栏、胶片栏等其余栏位的背景同样取上述栏位材质，出现规则随各栏位的显隐（SHELL-01）。
- 圆按钮与合体按钮在 iOS、macOS 与 Windows 上使用平台原生按钮材质，Android 使用 TOOLBAR-10 的玻璃按钮配方，自绘平台使用 TOOLBAR-10 的按钮材质；合体按钮是一个胶囊容器加分段，段间不画分隔线。
- EXIF 块在上下布局控制栏与手机竖屏顶行是深色半透明模糊块；左右布局控制栏（宽形态与手机横屏）取无衬底变体——去掉块的模糊衬底与块内边距，只剩项目与项距，直接放在控制栏背景上（TOOLBAR-05）。Android 在 API 31 及以上以照片层模糊加 `color.toolbar.block.background` × `shell.glass.android.exif.tint.opacity@android` 承担这块衬底，取样与配方同栏底，见上方 Android 条目。
- 同一区域的玻璃控件放在同一个原生玻璃容器里共享取样——手机形态的圆按钮、合体按钮与星级控件胶囊为一组，宽形态控制栏的星级控件与命令圆按钮为一组：静止时各自独立，相邻元素靠近到 `shell.glass.container.spacing` 以内才开始融合（取值与按钮组间距相同），按压放大时与相邻玻璃按平台液态效果相连。控件内容放在玻璃的内容区，随按压一同缩放；宽形态控制栏采用与手机形态一致的玻璃兄弟层级，不在命令玻璃与共同容器之间夹入整组命中视图。常规状态更新与同尺寸重排不得重挂控件或重写正在由系统驱动的交互几何，松手与取消应保留系统回弹。EXIF 块（含无衬底变体）不进玻璃容器。
- **原生纪律**：非定制控件保留系统控件与默认状态；除上述主屏底材配置外，不手调圆角、阴影、模糊半径或着色。定制组件限于星级控件（RATING-07）、EXIF 块、胶片卡片（FILM-05）、筛选控件（FILTER-07），以及 TOOLBAR-10 的 Android 玻璃按钮与 MENU-03 的窗口内玻璃面板。
- 横屏胶片栏从按钮合体下方滚过时的边缘模糊用系统滚动边缘效果，不自绘。
