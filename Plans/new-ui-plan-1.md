# 移动端适应的 UI 重构 · Plan 1 · 执行规划

> 依据：作者原始需求 [new-ui-plan-0.md](new-ui-plan-0.md)（下文以"需求 1–10"引用其条目）及作者对首版规划的修正。分支：`new-ui`。
> 本文件回答两件事：**目标怎么定义**（每一步做到什么算完、用什么证明），**任务怎么分步**（U0–U6 完成 iOS/iPadOS 定版，U7 起跨端）。阶段号 `U*` 只用于本计划与提交标题，不进 `Design/` 与代码注释。

## 1. 总目标

**北极星**：iOS·iPadOS 上只有一套响应式主屏，分两种形态——**宽**（现有上下/左右布局的改造版）与**手机**（竖屏、横屏两种排布）。它覆盖大屏、小屏、竖屏、横屏、分屏/台前调度，以及触摸、触控板、键鼠，使用 iOS 26 原生控件；自定义只限星级控件、EXIF 块、胶片卡片、筛选控件四处。完成后主屏规范定版，再以它为基准对标 Mac/Windows（宽）与 Android（手机 + 平板宽）。

**iOS 部分完成判据**（U6 结束时同时成立）：

1. 设计规范：形态、槽位、图区避让、星级控件、卡片两档与输入分流、筛选控件（含计数）等规则已写入 `Design/spec/`，令牌在 `tokens.json`；`platforms.md` 的 `@ios` 与 `status.md` 的 iOS 列已回填，本计划中不再有待确认项。
2. 程序化：验收矩阵（§6）上的全部 iOS 套件 PASS（标准版与 AI 版），共享契约检查 0 FAIL；Mac/Windows/Android 的构建与既有回归不退化。
3. 无遗留：旧主屏组件（旧筛选条、旧控制栏、旧分区计算、独立来源浮窗、卡片上下文菜单）与阶段占位视图全部删除，按 §6.3 的零命中搜索证明；iOS 侧不存在 iOS 26 以下的版本分支。
4. 作者在 iPad 与 iPhone 真机上手验签字（触感、动效、旋转、分屏、外设）。

**不在本计划范围**：

- 相似聚类的手机形态入口（需求 5 明确先不做）。
- 折叠屏与 Android 机型检测（需求 3）。
- 手机形态的快捷键编辑：先不做、不显示，既有绑定照常生效。
- 各端对标的具体实现：U7 起各自另立计划。

## 2. 目标怎么定义（方法）

原则是**定义证明，而不是定义工作量**。每个阶段的目标都写成一份"完成契约"，包含五个部分，可以直接作为 `/goal` 目标文本使用（§5 每阶段附带一份）：

| 部分 | 写什么 | 本项目的取值方式 |
|---|---|---|
| 终态 | 什么必须成立 | 引用设计 ID 与组件名，不写"优化/改进" |
| 证明 | 可运行、可回看的证据 | 构建 0 错误；`CoreContractCheck` 0 FAIL；`--pv-native-*-check` 报告 PASS；截图集落在 `artifacts/acceptance/new-ui/<阶段>/`；零命中搜索 |
| 边界 | 能动哪里、不能动哪里 | 目录白名单；不改既有令牌取值；不改其他平台界面行为 |
| 循环 | 怎么迭代 | 每落一个槽位或组件就重跑对应检查，不攒到最后 |
| 停止规则 | 走不通时怎么诚实收尾 | 遇到未定的设计取舍、绑定缺失、模拟器无法驱动的场景，记入 §8 并停下报告，不自行发明规则 |

**三类证据分开记**：

- 程序化断言（几何不变量、事件序列、写回次数）：由 agent 自证。
- 截图集：供作者目视。
- 手感（触感反馈、动效、真机旋转与分屏）：只能由作者判定。

`/goal` 只覆盖前两类，所以每个阶段结束于一个**作者门**（G0–G6）。作者门不纳入 goal 的完成条件，goal 跑到"截图与报告已就绪"就停。

**防走偏的硬约束**：上一轮演示的教训是工作重心滑向液态玻璃特效。本计划对所有非定制控件设一条"原生纪律"：只用系统控件和系统默认配置（按钮配置、材质、菜单、滚动边缘效果），不手调圆角、阴影、模糊半径或着色。U4 用 §6.3 的搜索清单复核，命中就要解释或删除。

## 3. 已定决策

**作者已确认**：

1. **最低系统版本提到 iOS 26**。Mac 已是 26；iOS 删除 17–25 的兼容分支，不留回退。
2. **边栏背景先按需求做**（作者原话"先按我说的来"，观感在 G1 截图上复核）：
   - 边栏背景用系统深色模糊材质，出现规则见 §4。
   - 按钮和星级胶囊用液态玻璃。
   - EXIF 块是深色半透明圆角矩形，可叠模糊。
   - 胶片条滚到按钮下方时的模糊用系统滚动边缘效果，不自绘。
3. **图区避让先实现、看效果再定规则**（需求 8）。
   - U1 按"避让内边距"方案实现：主图视图始终满窗口，适应态按四边固定元素的内缘计算适应区；裸按钮再加一份按钮到栏缘的间距；放大后内容可以滚到栏位和按钮下方直到窗口边缘。
   - 裸按钮额外间距、栏背景边界都做成可调参数。
   - G1 看截图定规则，之后才写进 `Design/spec/`。
   - 共享 `PhotoViewport` 要区分视图矩形和适应矩形；Mac/Windows/Android 传零内边距，行为不变。
4. **横屏控制列固定为"不显示上下张"时的原位**：上下张只在刘海侧左下角，控制列上端为缩放适应/雾天增强，其余高度全给星级控件。
5. **横屏右侧是两竖排，分析栏与控制栏同在右侧**：小屏不再换行，EXIF 竖排位于控制竖排左侧（靠近主图）。分析栏的相对次序见第 18 条。
6. **筛选控件**：
   - 宽形态默认是三合体按钮（排序 / 方向 / 星级各一段，各自弹出菜单）。
   - 列布局：总宽等于胶片条宽度，这个宽度放不下三段就改用单一胶囊，弹出与手机相同的三分组菜单。
   - 行布局：不按胶片条同宽，三合体按内容自然宽度排布。
   - 手机形态始终是单一胶囊。
7. **计数**：所有形态的计数最终都收进筛选控件内部，由筛选控件专项（U5）完成。手机形态在 U5 完成前不显示计数；宽形态在此期间的处理见第 16 条。
8. **卡片评分的输入分流**：
   - 鼠标和触控板可以直接点卡片上的小星。
   - 手指触摸不响应小星，点星级行等同点卡片。
   - 长按卡片弹出新的星级弹窗进行评分。大小两档卡片相同。
   - 星级弹窗与冲突浮窗合并后共用 RATING-04 的条目格式（作者：完整名与时间不是必要的，但文件名与冲突浮窗同格式，时间无空位可放弃）：
     - 非冲突时只有一个条目，即该照片的文件名加星排；放得下时文件名后附拍摄时间，放不下就不显示时间。
     - 冲突时按来源逐条列出（每条自带文件名），不再另加头部。
   - 卡片上下文菜单退役；指针辅助点按卡片同样打开星级弹窗（本计划决定）。
9. **手机形态的快捷键编辑做最简处理**：作者给了两种都可接受的做法——先不做、不显示；或者做成设置列表里的二级页面或弹窗，简单处理即可。执行 agent 按实现成本择一，不做专项设计。
10. **手机布局下的开关按必要的来**，后续再补：本计划只新增"显示上下张按钮"一个开关。EXIF 块是否另设开关见第 17 条。

**本计划拿主意**（可在 G0 推翻）：

11. **继续用 UIKit（C#），不引入 SwiftUI 桥**。实测已安装的 `Microsoft.iOS` 27.0 绑定包含这次要用的 iOS 26 接口：
    - 玻璃按钮配置（`glass` / `prominentGlass`）；
    - `UIGlassEffect` / `UIGlassContainerEffect`；
    - 菜单项 `KeepsMenuPresented`；
    - `UIScrollEdgeElementContainerInteraction`；
    - 带圆角适应的安全区布局区域。

    主图仍是现有 Metal + `UIScrollView`。
12. **形态判定用系统尺寸类别**：
    - 任一轴为紧凑即为手机形态，覆盖 iPhone 竖横、iPad 1/3 与窄分屏、台前调度小窗。
    - 两轴都常规为宽形态。
    - 横宽于竖时取手机横屏排布。

    规范以"平台原生尺寸类别"表述，便于 Android 映射到 WindowSizeClass。桌面暂只有宽形态。
13. **布局模式增加"手机"**（需求 3），与上下/左右/自动并列。
    - "手机"选项由平台能力开关控制，只在实现了手机形态的平台出现（本计划内只有 iOS）。
    - Mac/Windows 读到该值时按自动处理。
    - iPhone 上隐藏整个布局模式分组，固定为手机。
14. **规范落地策略**：
    - 已确定的规则直接按目标态写进 `Design/spec/`，其他平台在 `status.md` 记"待实现"，这是 Design/README §6 的既有流程。
    - 仍在试的点（含第 3 条图区避让）写在本计划，到确认后才升格进规范。
    - **令牌只增不改值**：新 UI 用新令牌，Mac/Windows/Android 仍在消费的旧令牌保持原值，等最后一个消费者迁移后删除（U7 清理门）。
    - 共享代码同理：新几何写成新类型，旧类型在最后一个平台迁移后删除。
    - Web 参考壳的同步推迟到 U7；在此之前只要求令牌生成校验与 Web 单测不被新令牌打破。
15. **阶段内允许功能不全，但不写过渡适配层**（需求末段）：
    - 分支上的中间提交可以缺功能，例如 U1 的星级槽位只有占位、U3 到 U4 之间手指暂时无法在卡片上评分。
    - 不为"新旧并存"写适配代码。
    - 占位视图在被替换的阶段删除，U4 统一用零命中搜索复核。
16. **宽形态在 U5 前也不显示计数**：作者只明说了手机形态在专项前不显示。这里一并适用于宽形态，避免为过渡另做一份计数文本；代价是 iPad 在 U1–U4 期间暂时没有计数。
17. **EXIF 块不另设开关**：出现与否沿用 EXIF 页的显示项，没有启用项就不显示 EXIF 块，也不带横屏右栏背景。需求 7 的"打开 EXIF 显示"按此理解，未经作者确认。
18. **横屏右侧次序**：自内向外依次为分析栏（出现时）、EXIF 列、控制列。

|---|---|---|---|

## 4. 形态与槽位（G0 评审对象）

**手机竖屏**（需求 4、5）：

| 区域 | 前端（左） | 中间 | 末端（右） | 背景 |
|---|---|---|---|---|
| 顶部行 | 筛选胶囊（原地弹出菜单；计数在 U5 收入） | EXIF 块 | 更多（菜单） | 有分析栏时带顶栏背景 |
| 顶部栏体 | 分析栏（出现时） | | | 同上 |
| 中央 | 主图 | | | — |
| 底部栏体 | 胶片条（小档卡片，出现时） | | | 有胶片条时带底栏背景，否则裸按钮叠在照片上 |
| 底部行 | 上一张/下一张合体（开关关闭时隐藏） | 星级控件，占满剩余宽度 | 缩放适应/雾天增强合体 | 同上 |

**手机横屏**（需求 6、7）：自左向右列出，以刘海在左、下巴在右为例；刘海在右时整体镜像。

| 列 | 内容 | 对齐与背景 |
|---|---|---|
| 左栏（刘海侧） | 上：筛选/更多合体，可占刘海旁的显示区；中：胶片条，不被刘海遮挡；下：上一张/下一张合体，横向排列，开关关闭时隐藏 | 元素右对齐，左侧避让刘海与屏幕圆角；有胶片条时带背景，胶片条滚到按钮下方时有模糊 |
| 主图 | — | — |
| 分析栏（出现时） | 竖向一列，与控制栏同在右侧 | 自带栏背景 |
| EXIF 列 | EXIF 块纵排 | 有 EXIF 显示项时带右栏背景（与控制列共用一个背景） |
| 控制列（下巴侧） | 上：缩放适应/雾天增强合体；其余全部给星级控件（竖排，放得下就用展开态） | 竖屏底部行在"不显示上下张"状态下原地旋转图标、元素不位移；无论开关如何都不放上下张；无 EXIF 显示项时裸按钮叠在照片上 |

**宽形态**（需求 9）：

- 分区保持现有上下/左右布局，分析栏与相似面板位置不变。
- 文件栏：胶片栏背景换模糊材质；卡片用大档。
- 筛选：
  - 按第 3 节第 6 条：列布局与胶片条同宽、放不下三段时改单胶囊；行布局三合体按内容宽。
  - 计数在 U5 收进筛选控件，此前不显示（第 3 节第 16 条）。
  - AI 版相似聚类开关位置不变。
- 控制栏：命令换圆形玻璃按钮；星级用新控件，放得下就用展开态；EXIF 用新样式块。
- 尺寸：按钮与胶囊按苹果标准尺寸，相关间距跟着调整。
- 图区避让：规则同手机形态。

**原生控件清单**（U0 定稿，U1 起照此实现）：

| 元素 | 选型 | 定制程度 |
|---|---|---|
| 圆按钮、合体按钮 | 玻璃按钮配置；合体按钮放进玻璃容器效果里 | 原生 |
| 筛选单胶囊（手机 / 宽形态放不下时） | 按钮 + 菜单：三个单选内联分组，分组之间有分隔线，选项设"保持菜单展开"，失焦关闭 | 原生（计数在 U5 专项加入） |

## 5. 分步

各阶段依赖关系：U0 → U1 →（U2 ∥ U3）→（U4 ∥ U5）→ U6 → U7。

- U2 与 U3 可以并行，都依赖 U1 提供的槽位与共享几何。
- 卡片长按接星级弹窗需要 U2 与 U3 都完成，因此放在 U4。
- U5 只依赖 U1 的手机筛选胶囊与 U3 的宽形态筛选，可以与 U4 并行。

| 阶段 | 主题 | 覆盖需求 | 作者门 |
|---|---|---|---|
| U0 | 定义：规范草案、技术探针、验收矩阵 | 全部（定义层） | G0 评审形态表与控件清单 |
| U1 | 骨架：形态判定、槽位、图区避让、原生按钮与手机筛选胶囊 | 3、4、5、6、7、8、10 | G1 看形态截图，确定图区避让规则，复核边栏背景观感 |

- **做法**：
  - 先评估原生按钮配置（图标 + 标题/副标题、玻璃配置）能否承载计数并随筛选即时更新；能满足就用原生，不能满足再自定义（需求 10 的原生优先）。
  - 三合体中计数放在哪一段、以什么形式出现，由本专项出两三个候选，在 G5 定。
  - 同一帧内计数与列表一致（FILTER-04）。
  - 计数变化不改变相邻控件位置；列布局下不改变控件总宽（与胶片条同宽），行布局只允许控件自身宽度变化。
- **完成契约（/goal）**：
  ```text
  完成 new-ui U5 筛选控件专项。
  完成判据：FILTER-04 的新条款落地；iOS 两版构建 0 错误；layout 检查新增"计数在筛选控件内可见、与列表同帧一致、计数变化不移动相邻控件且列布局总宽不变、手机菜单点选不关闭"断言，并在 iPhone 17e、iPhone 17、iPad Pro 13（行布局、列布局、1/3 分屏）上 PASS；status.md 的 iOS 缺口关闭；截图落 artifacts/acceptance/new-ui/u5/。
  范围：PhotoViewer.iOS、PhotoViewer.Shared、Tools/CoreContractCheck、Design、Plans。
  停止：计数放进按钮后，窄屏顶部行放不下筛选、EXIF、更多三者，或列布局三合体因此放不下三段时，记录宽度与差值，停下等作者裁定。
  ```

### 6.2 不变量（程序化断言，同时在共享尺寸网格与模拟器上核对）

1. 适应态主图矩形与任何常驻元素（裸按钮再外扩一份按钮间距）不相交，并且贴到避让边界。G1 定规则后按定稿参数断言。
2. 放大态内容可以滚到窗口边缘，栏位与按钮下方不裁切。
3. 可交互控件命中区不小于 44×44 点；视觉尺寸取令牌。卡片小星只对指针生效，不受此条约束。
4. 除栏位背景外，所有元素都在带圆角适应的安全区内；横屏左栏右对齐，左侧避让刘海。
5. 刘海在左和刘海在右两种横屏互为镜像。
6. 横屏控制列不出现上下张，"显示上下张按钮"开关两态下控制列几何相同。
7. 横屏右侧自内向外为分析栏（出现时）、EXIF 列、控制列。
8. 胶片条可见卡片数不少于 5；所选档位符合选档规则。
9. 筛选控件：列布局宽度等于胶片条宽度，三段放不下时为单胶囊；行布局三合体按内容宽；手机形态恒为单胶囊。
10. 星级控件形态：可用主轴长度不小于展开态固有长度时用展开态。
11. 卡片星级：直接触摸不写值、只选中卡片；指针点星写值且不切主图；长按或指针辅助点按弹出星级弹窗，条目文件名与 RATING-04 同格式（U4 起）。
12. 形态判定的结果符合规范判定表（尺寸类别 × 设备 × 用户模式）。
13. 形态切换与旋转不改变当前照片、缩放中心与相对倍率（IMAGE-03），胶片条定位遵守 FILM-01 到 FILM-04。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 玻璃或模糊在 F16 扩展线性 Metal 表面上取样异常或掉帧 | S1 先验证；不行就把主图上方的材质改为系统模糊材质，不自绘 |
| "保持菜单展开"时勾选态不能就地刷新 | S2 先验证；退路是用延迟构建的菜单元素重建菜单，仍然原生 |
| 长按到滑动的连续手势在系统浮窗里断开 | S3 已预设退路：用窗口内玻璃面板；卡片长按与胶囊共用同一实现 |
| 卡片长按与胶片条滚动、系统抬升手势互相抢占 | S3 一并验证；卡片不再挂系统上下文菜单交互，长按识别器与列表滚动按系统优先级协调 |
| iPad 旋转与分屏无法程序化驱动 | 共享几何网格加 `traitOverrides` 覆盖；真实场景留给作者手验 |
| 共享层改动波及其他三端 | 新类型、新令牌并存，U1/U4 门槛包含 Mac 冒烟、Windows 类型检查与 Android 构建 |
| 图区避让效果不理想导致返工 | 参数可调，U1 输出候选组截图供 G1 选择；规则在 G1 后才写进规范 |
| 规范在探索期反复修改 | 未定项留在本计划，确认后才升格；`Design/` 只写已定项 |
| 工作重心再次滑向视觉特效 | §2 原生纪律加 §6.3 搜索复核；每个阶段门先看功能与几何，再看观感 |
