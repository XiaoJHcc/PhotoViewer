# 移动端适应的 UI 重构 · Plan 1 · 执行规划

> 依据：作者原始需求 [new-ui-plan-0.md](new-ui-plan-0.md)（下文以"需求 1–10"引用其条目）及作者对首版规划的修正。分支：`new-ui`。
> 本文件回答两件事：**目标怎么定义**（每一步做到什么算完、用什么证明），**任务怎么分步**（U0–U6 完成 iOS/iPadOS 定版，U7 起跨端）。阶段号 `U*` 只用于本计划与提交标题，不进 `Design/` 与代码注释。

## 1. 总目标

**北极星**：iOS·iPadOS 上只有一套响应式主屏，分两种形态——**宽**（现有上下/左右布局的改造版）与**手机**（竖屏、横屏两种排布）。它覆盖大屏、小屏、竖屏、横屏、分屏/台前调度，以及触摸、触控板、键鼠，使用 iOS 26 原生控件；自定义只限星级控件、EXIF 块、胶片卡片、筛选控件四处。完成后主屏规范定版，再以它为基准对标 Mac/Windows（宽）与 Android（手机 + 平板宽）。

**iOS 部分完成判据**（U6 结束时同时成立）：

1. 设计规范：形态、槽位、图区避让、星级控件、卡片两档与输入分流、筛选控件（含计数）等规则已写入 `Design/spec/`，令牌在 `tokens.json`；`platforms.md` 的 `@ios` 与 `status.md` 的 iOS 列已回填，本计划中不再有待确认项。
2. 程序化：验收矩阵（§6）上的全部 iOS 套件 PASS（标准版与 AI 版），共享契约检查 0 FAIL；Mac/Windows/Android 的构建与既有回归不退化。
3. 无遗留：旧主屏组件（旧筛选条、旧控制栏、旧分区计算、独立来源浮窗、卡片上下文菜单）与阶段占位视图全部删除，按 §6.3 的零命中搜索证明；iOS 侧不存在 iOS 26 以下的版本分支。
4. 作者在 iPad 与 iPhone 真机上手验签字（触感、动效、旋转、分屏、外设）。

**不在本计划范围**：

- 相似聚类的手机形态入口（需求 5 明确先不做）。
- 折叠屏与 Android 机型检测（需求 3）。
- 手机形态的快捷键编辑：先不做、不显示，既有绑定照常生效。
- 各端对标的具体实现：U7 起各自另立计划。

## 2. 目标怎么定义（方法）

原则是**定义证明，而不是定义工作量**。每个阶段的目标都写成一份"完成契约"，包含五个部分，可以直接作为 `/goal` 目标文本使用（§5 每阶段附带一份）：

| 部分 | 写什么 | 本项目的取值方式 |
|---|---|---|
| 终态 | 什么必须成立 | 引用设计 ID 与组件名，不写"优化/改进" |
| 证明 | 可运行、可回看的证据 | 构建 0 错误；`CoreContractCheck` 0 FAIL；`--pv-native-*-check` 报告 PASS；截图集落在 `artifacts/acceptance/new-ui/<阶段>/`；零命中搜索 |
| 边界 | 能动哪里、不能动哪里 | 目录白名单；不改既有令牌取值；不改其他平台界面行为 |
| 循环 | 怎么迭代 | 每落一个槽位或组件就重跑对应检查，不攒到最后 |
| 停止规则 | 走不通时怎么诚实收尾 | 遇到未定的设计取舍、绑定缺失、模拟器无法驱动的场景，记入 §8 并停下报告，不自行发明规则 |

**三类证据分开记**：

- 程序化断言（几何不变量、事件序列、写回次数）：由 agent 自证。
- 截图集：供作者目视。
- 手感（触感反馈、动效、真机旋转与分屏）：只能由作者判定。

`/goal` 只覆盖前两类，所以每个阶段结束于一个**作者门**（G0–G6）。作者门不纳入 goal 的完成条件，goal 跑到"截图与报告已就绪"就停。

**防走偏的硬约束**：上一轮演示的教训是工作重心滑向液态玻璃特效。本计划对所有非定制控件设一条"原生纪律"：只用系统控件和系统默认配置（按钮配置、材质、菜单、滚动边缘效果），不手调圆角、阴影、模糊半径或着色。U4 用 §6.3 的搜索清单复核，命中就要解释或删除。

## 3. 已定决策

**作者已确认**：

1. **最低系统版本提到 iOS 26**。Mac 已是 26；iOS 删除 17–25 的兼容分支，不留回退。
2. **边栏背景先按需求做**（作者原话"先按我说的来"，观感在 G1 截图上复核）：
   - 边栏背景用系统深色模糊材质，出现规则见 §4。
   - 按钮和星级胶囊用液态玻璃。
   - EXIF 块是深色半透明圆角矩形，可叠模糊。
   - 胶片条滚到按钮下方时的模糊用系统滚动边缘效果，不自绘。
3. **图区避让按"透明边栏"规则**（需求 8，作者在 G1 实机验收后裁定）。
   - 主图视图始终满窗口；放大后内容可以滚到栏位和按钮下方直到窗口边缘。
   - 每一行/列元素都视作一条边栏，栏缘 = 元素内缘 + 行内间距（`shell.phone.rowInset`），有没有背景都一样；适应区的边就是这条栏缘。控制栏这类一排按钮同样是边栏；单个按钮（如只剩"更多"）也按占满整条栏处理，不做异形避让。
   - 没有边栏的边只避让真正遮挡画面的刘海/灵动岛（竖屏顶边、横屏刘海侧），不避让 Home 指示条，也不避让横屏下巴侧那份系统对称给出的安全区。
   - 原"裸按钮额外间距"参数与令牌 `shell.photo.bareGap` 已删除。已写入 SHELL-11。
   - 共享 `PhotoViewport` 要区分视图矩形和适应矩形；Mac/Windows/Android 传零内边距，行为不变。
4. **横屏控制列固定为"不显示上下张"时的原位**：上下张只在刘海侧左下角，控制列上端为缩放适应/雾天增强，其余高度全给星级控件。（已被「U3 收尾：手机布局整理」取代：横屏控制栏改为桌面列布局，自上而下为 EXIF、星级、适应/增强。）
5. **横屏右侧是两竖排，分析栏与控制栏同在右侧**：小屏不再换行，EXIF 竖排位于控制竖排左侧（靠近主图）（已被「U3 收尾：手机布局整理」取代：EXIF 并入控制栏，取无衬底纵排位于其顶端）。分析栏的相对次序见第 18 条。
6. **筛选控件**：
   - 宽形态默认是三合体按钮（排序 / 方向 / 星级各一段，各自弹出菜单）。
   - 列布局：总宽等于胶片条宽度，这个宽度放不下三段就改用单一胶囊，弹出与手机相同的三分组菜单。
   - 行布局：不按胶片条同宽，三合体按内容自然宽度排布。
   - 手机形态始终是单一胶囊。
7. **计数**：所有形态的计数最终都收进筛选控件内部，由筛选控件专项（U5）完成。手机形态在 U5 完成前不显示计数；宽形态在此期间的处理见第 16 条。
8. **卡片评分的输入分流**：
   - 鼠标和触控板可以直接点卡片上的小星。
   - 手指触摸不响应小星，点星级行等同点卡片。
   - 长按卡片弹出新的星级弹窗进行评分。大小两档卡片相同。
   - 星级弹窗与冲突浮窗合并后共用 RATING-04 的条目格式（作者：完整名与时间不是必要的，但文件名与冲突浮窗同格式，时间无空位可放弃）：
     - 非冲突时只有一个条目，即该照片的文件名加星排；放得下时文件名后附拍摄时间，放不下就不显示时间。
     - 冲突时按来源逐条列出（每条自带文件名），不再另加头部。
   - 卡片上下文菜单退役；指针辅助点按卡片同样打开星级弹窗（本计划决定）。
9. **手机形态的快捷键编辑做最简处理**：作者给了两种都可接受的做法——先不做、不显示；或者做成设置列表里的二级页面或弹窗，简单处理即可。执行 agent 按实现成本择一，不做专项设计。
10. **手机布局下的开关按必要的来**，后续再补：本计划只新增"显示上下张按钮"一个开关。EXIF 块是否另设开关见第 17 条。

**本计划拿主意**（可在 G0 推翻）：

11. **继续用 UIKit（C#），不引入 SwiftUI 桥**。实测已安装的 `Microsoft.iOS` 27.0 绑定包含这次要用的 iOS 26 接口：
    - 玻璃按钮配置（`glass` / `prominentGlass`）；
    - `UIGlassEffect` / `UIGlassContainerEffect`；
    - 菜单项 `KeepsMenuPresented`；
    - `UIScrollEdgeElementContainerInteraction`；
    - 带圆角适应的安全区布局区域。

    主图仍是现有 Metal + `UIScrollView`。
12. **形态判定用系统尺寸类别**：
    - 任一轴为紧凑即为手机形态，覆盖 iPhone 竖横、iPad 1/3 与窄分屏、台前调度小窗。
    - 两轴都常规为宽形态。
    - 横宽于竖时取手机横屏排布。

    规范以"平台原生尺寸类别"表述，便于 Android 映射到 WindowSizeClass。桌面暂只有宽形态。
13. **布局模式增加"手机"**（需求 3），与上下/左右/自动并列。
    - "手机"选项由平台能力开关控制，只在实现了手机形态的平台出现（本计划内只有 iOS）。
    - Mac/Windows 读到该值时按自动处理。
    - iPhone 上隐藏整个布局模式分组，固定为手机。
14. **规范落地策略**：
    - 已确定的规则直接按目标态写进 `Design/spec/`，其他平台在 `status.md` 记"待实现"，这是 Design/README §6 的既有流程。
    - 仍在试的点（含第 3 条图区避让）写在本计划，到确认后才升格进规范。
    - **令牌只增不改值**：新 UI 用新令牌，Mac/Windows/Android 仍在消费的旧令牌保持原值，等最后一个消费者迁移后删除（U7 清理门）。
    - 共享代码同理：新几何写成新类型，旧类型在最后一个平台迁移后删除。
    - Web 参考壳的同步推迟到 U7；在此之前只要求令牌生成校验与 Web 单测不被新令牌打破。
15. **阶段内允许功能不全，但不写过渡适配层**（需求末段）：
    - 分支上的中间提交可以缺功能，例如 U1 的星级槽位只有占位、U3 到 U4 之间手指暂时无法在卡片上评分。
    - 不为"新旧并存"写适配代码。
    - 占位视图在被替换的阶段删除，U4 统一用零命中搜索复核。
16. **宽形态在 U5 前也不显示计数**：作者只明说了手机形态在专项前不显示。这里一并适用于宽形态，避免为过渡另做一份计数文本；代价是 iPad 在 U1–U4 期间暂时没有计数。
17. **EXIF 块不另设开关**：出现与否沿用 EXIF 页的显示项，没有启用项就不显示 EXIF 块，也不带横屏右栏背景。需求 7 的"打开 EXIF 显示"按此理解，未经作者确认。（手机形态已被「U3 收尾：手机布局整理」改为另设 EXIF 开关并写平台偏好；宽形态仍按本条。）
18. **横屏右侧次序**：自内向外依次为分析栏（出现时）、EXIF 列、控制列。（已被「U3 收尾：手机布局整理」取代：自内向外为分析栏（出现时）、控制栏，EXIF 无衬底纵排位于控制栏顶端。）

### 3.1 与现行规范冲突的条款

以下现行条款（除 FILTER-08 为"应当"外均为"必须"）与本计划的决定直接冲突。U0 改写 `Design/spec/` 时逐条处理；执行中遇到它们时以本计划为准，不按停止规则停下。条款号不能复用，改写时按 Design/README §4：原条款修订为新目标态，或标为已退役并指向替代条目。

| 条款 | 现行要求 | 冲突来源 | 处理方向 |
|---|---|---|---|
| SETTINGS-08 | 布局模式三选一，"不得只给移动端两档" | 第 13 条 | 改为四选一（"手机"受平台能力开关控制）；iPhone 隐藏该分组 |
| SETTINGS-08、INPUT-13 | 控制栏功能列表与快捷键编辑始终可编辑；连接外设即显示完整绑定 | 需求 3、第 9 条 | 手机形态隐藏功能按钮自定义；快捷键编辑按第 9 条处理 |

## 4. 形态与槽位（G0 评审对象）

**手机竖屏**（需求 4、5）：

| 区域 | 前端（左） | 中间 | 末端（右） | 背景 |
|---|---|---|---|---|
| 顶部行 | 筛选胶囊（原地弹出菜单；计数在 U5 收入；常驻） | EXIF 块（EXIF 开关打开且有显示项时） | 更多（菜单；常驻） | 有分析栏时带顶栏背景 |
| 顶部栏体 | 分析栏（出现时） | | | 同上 |
| 中央 | 主图 | | | — |
| 底部栏体 | 胶片条（小档卡片，出现时） | | | 有胶片条时带底栏背景，否则裸按钮叠在照片上 |
| 底部行 | 上一张/下一张合体（"显示上下张按钮"与「控制栏」开关同时满足时显示） | 星级控件，占满剩余宽度 | 缩放适应/雾天增强合体 | 同上 |

EXIF 开关关闭时筛选与更多上移到灵动岛/刘海两旁的显示区（下缘贴安全区，上缘距窗口缘不少于 `shell.phone.edgeMargin`，且不低于带 EXIF 时的位置）。「控制栏」开关只收起底部行，「胶片栏」开关只收起胶片条。

**手机横屏**（需求 6、7）：自左向右列出，以刘海在左、下巴在右为例；刘海在右时整体镜像。

| 列 | 内容 | 对齐与背景 |
|---|---|---|
| 左栏（刘海侧） | 上：筛选/更多合体；中：胶片条，不被刘海遮挡；下：上一张/下一张合体，横向排列（胶片栏开关与"显示上下张按钮"同时满足时显示） | 元素右对齐，左侧避让刘海与屏幕圆角；有胶片条时带背景，胶片条滚到按钮下方时有模糊；无胶片栏时筛选与更多分开落在刘海上下两旁的显示区 |
| 主图 | — | — |
| 分析栏（出现时） | 竖向一列，贴控制栏的栏缘 | 自带栏背景 |
| 控制栏（下巴侧） | 自上而下：EXIF 无衬底纵排（EXIF 开关打开且有显示项时）→ 星级控件 → 缩放适应/雾天增强竖排合体 | 按钮外缘距窗口缘 `shell.phone.edgeMargin`，不避让下巴侧系统对称安全内缩；EXIF 显示时带控制栏背景，否则裸按钮叠在照片上；长度不足时星级先保住 `rating.compact.minLength`，EXIF 只按整项裁掉末尾项 |

**宽形态**（需求 9）：

### U3 收尾：手机布局整理（U4 前）

作者在 U3 后实机复看提出的整理，只改手机形态，宽形态不变。目标是让每个开关只管自己那一栏、去掉重复的边距，并让手机横屏回到桌面列布局的控制栏组织方式。

**作者原话要点**：安全区自带视觉边距、不重复加；筛选与更多常驻；EXIF 在手机形态另设开关；控制栏开关只管星级所在那一栏；横屏控制栏改为桌面式（EXIF、星级、控制自上而下，EXIF 不再套衬底），作废「横屏控制列与竖屏底行同位」；横屏上下张归胶片栏开关；胶片栏关闭时筛选与更多缩到刘海旁。

**规则**（横屏以刘海在左为例，刘海在右整体镜像）：

1. **边距不重复**：
   - 贴实物遮挡（竖屏灵动岛/刘海、横屏刘海）的元素直接贴系统安全区边，不再加 `shell.phone.rowInset`：竖屏顶行上缘 = 安全区上缘；横屏胶片卡片左缘 = 刘海侧安全区（靠刘海一侧的卡片交叉轴内边距让进安全区）。
   - 没有实物遮挡的边（如 iPad 手机模式顶边）仍至少留 `rowInset`；横屏卡片不越出窗口缘。
   - Home 指示条的安全内缩同样自带约一份 `rowInset` 的余量：竖屏底行到底边 = max(安全区下缘 − `rowInset`, 本行两端到窗口缘的较小值)。iPhone 17 由 34 变为 26（与顶行到灵动岛、横屏卡片到刘海的视觉间隙同为约 13–14）；iPad 手机模式的 Home 指示条余量不足，由「不比两端更贴边」兜到约 19。
   - 我们代码里只有前两处真正叠加了边距；底行原本就贴着 34 的系统安全区，这里改的是压进系统余量，不是删除重复。
2. **筛选与更多常驻**：不随胶片栏、控制栏开关隐藏。
   - 竖屏：顶行带 EXIF 时三者同行（行上缘贴安全区）；不带 EXIF 时，筛选与更多上移进刘海/灵动岛两旁的显示区——按钮下缘贴安全区上缘、上缘距窗口缘不少于 `shell.phone.edgeMargin`，且不低于带 EXIF 时的位置（无刘海的 iPad 两者重合）。
   - 横屏有胶片栏：筛选/更多合体仍在刘海侧列顶端，列缘规则不变（卡片贴安全区后列缘相应左移 8）。
   - 横屏无胶片栏：筛选与更多分开，各占刘海上下两旁的显示区（上：筛选，下：更多），横向口径与竖屏耳区相同（内缘贴刘海侧安全区，外缘距窗口缘不少于边距）。这是竖屏顶行耳区旋转后的对应位置。
   - 两种耳区下主图仍按透明边栏让到按钮内缘 + `rowInset`（iPhone 17 竖屏 70、横屏左 70），比只避让灵动岛多 8。
3. **开关各管各的栏**：
   - 胶片栏：胶片条；横屏另含刘海侧列下端的上下张（它在胶片栏里）。
   - 控制栏：竖屏底行（上下张、星级、缩放适应/雾天增强）；横屏下巴侧控制栏（EXIF、星级、缩放适应/雾天增强）。
   - EXIF（新增，仅手机形态）：竖屏单条件；横屏须控制栏也可见（EXIF 位于控制栏内）。转回竖屏按 EXIF 开关单独决定。
   - 「显示上下张按钮」设置：竖屏与控制栏开关同时满足才显示；横屏与胶片栏开关同时满足才显示。
   - 四个开关全关时，筛选与更多仍在，「更多」菜单即恢复入口；旧规则「两者都收起时靠主图长按恢复」作废。
4. **EXIF 开关的入口与持久化**：主图长按菜单与「更多」菜单（同一份 `PhotoMenuCatalog`）在手机形态于栏位组末尾多一项「EXIF」（勾选），宽形态不出现；状态为共享 `MainViewModel.IsExifViewVisible`（默认开），与胶片栏/控制栏一样写平台偏好（iOS 键 `PhotoViewer.Native.ShowExif`），不进设置 JSON。EXIF 页的显示项为空时同样不显示，开关保留原值。
5. **横屏控制栏桌面化**（作废原第 3 节第 4 条与 SHELL-09「旋转不变」）：
   - 下巴侧不再避让系统对称给出的安全内缩：按钮外缘距窗口缘 `edgeMargin`，上下端按该列自身位置的带圆角适应值再加 `rowInset`（与刘海侧列同口径）。
   - 自上而下：EXIF 列、星级控件、缩放适应/雾天增强竖排合体；EXIF 与按钮同一中轴，星级取中间剩余长度。
   - EXIF 不套衬底、去掉块内边距（只剩项目与项距，宽 52），直接放在控制栏背景上；控制栏背景只在显示 EXIF 时出现（文字需要底），否则按钮裸叠在照片上，与竖屏底行无胶片栏时一致。
   - 长度不够时星级先保住紧凑态最短长度 `rating.compact.minLength`（88），EXIF 只按整项显示、裁掉末尾项；被裁的项仍可点 EXIF 进详情查看。iPhone 17 横屏默认四项：星级约 102，紧凑态。
   - 次序仍为主图、分析栏（出现时）、控制栏；分析栏贴控制栏的栏缘。控制栏关闭时分析栏仍按原口径止于下巴侧安全区。
6. **共享几何**：`PhoneScreenLayout` 已按上述规则重写（输入新增 `ExifVisible`、`FilmOuterPad`、`ExifCount`、`ExifItemSpacing`、`RatingMinLength`；输出新增 `ExifItems`；`TopRowY`、`LeadStripWidth`、`ControlStripWidth` 供宿主在元素实际位置探测贴角带）。`ExifBlockGeometry` 增加无衬底变体。`ControlBand` 横屏改为下巴侧控制栏自身列的探测值，不再缓存竖屏底行。

**边界情况裁定**（主模型决定，作者可推翻）：

- 竖屏顶行宽度不够放 EXIF 时沿用既有等分压缩；EXIF 被压到 0 宽时顶行仍按带 EXIF 的位置排，不在同一帧里再切耳区。
- iPhone 17e（刘海高 47）竖屏耳区：47 − 44 = 3 < 16，按钮上缘取 16、下缘越出刘海安全区 13，主图避让 68，仍比带 EXIF 的 99 省出 31。
- 横屏耳区与胶片栏打开时的合体位置不同（更多从顶端合体移到下耳区）：这是「胶片栏关闭让出整列」的直接结果，按钮各自始终贴刘海旁。
- 横屏 EXIF 打开但一项都放不下时（极矮窗口），EXIF 与控制栏背景都不出现，星级取全部剩余长度。
- 「更多」菜单在宽形态不含 EXIF 项；宽形态控制栏 EXIF 块仍由 EXIF 显示项决定，不读手机 EXIF 开关。
- 待设计、本轮不做：竖屏底行在紧凑星级旁追加更多控制按钮（作者：iPhone 上空间并不紧迫，可往星级同一栏放更多按钮）。

### 6.2 不变量（程序化断言，同时在共享尺寸网格与模拟器上核对）

1. 适应态主图矩形与任何常驻元素不相交（无背景的元素按透明边栏外扩一份行内间距），并且贴到栏缘；无栏的边只让刘海/灵动岛。

4. 除栏位背景外，所有元素都在带圆角适应的安全区内；横屏左栏右对齐，左侧避让刘海。

8. 宽形态胶片条固定大档；手机形态可见卡片数不少于 5，所选档位符合容量选档规则。
9. 筛选控件：列布局宽度等于胶片条宽度，三段放不下时为单胶囊；行布局三合体按内容宽；手机形态恒为单胶囊。
10. 星级控件形态：可用主轴长度不小于展开态固有长度时用展开态。
11. 卡片星级：直接触摸不写值、只选中卡片；指针点星写值且不切主图；长按或指针辅助点按弹出星级弹窗，条目文件名与 RATING-04 同格式（U4 起）。
12. 形态判定的结果符合规范判定表（尺寸类别 × 设备 × 用户模式）。
13. 形态切换与旋转不改变当前照片、缩放中心与相对倍率（IMAGE-03），胶片条定位遵守 FILM-01 到 FILM-04。

- 宽形态固定大档（含相似面板），不随窗口容量降到小档。
- 列布局筛选控件"与胶片栏同宽"取卡片列宽（大档 96 / 小档 64），与卡片左右对齐；实际总是单胶囊。单胶囊标题取星级筛选当前值，图标为筛选图标；计数仍待 U5。
- 行布局三合体整组超出安全内容区时同样改单胶囊（与列布局同一规则）。
- EXIF 块衬底用系统薄深色模糊材质，不另叠着色；圆角 12。
- 卡片朝下/朝上弹出的弹窗沿用紧凑态的投影取值：长按后在卡片上越过 8 点即按横向投影预览星级，抬手会提交；朝侧边弹出（列布局、手机横屏）时手指须移入弹窗星排的横向范围才预览。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 玻璃或模糊在 F16 扩展线性 Metal 表面上取样异常或掉帧 | S1 先验证；不行就把主图上方的材质改为系统模糊材质，不自绘 |
| "保持菜单展开"时勾选态不能就地刷新 | S2 先验证；退路是用延迟构建的菜单元素重建菜单，仍然原生 |
| 长按到滑动的连续手势在系统浮窗里断开 | S3 已预设退路：用窗口内玻璃面板；卡片长按与胶囊共用同一实现 |
| 卡片长按与胶片条滚动、系统抬升手势互相抢占 | S3 一并验证；卡片不再挂系统上下文菜单交互，长按识别器与列表滚动按系统优先级协调 |
| iPad 旋转与分屏无法程序化驱动 | 共享几何网格加 `traitOverrides` 覆盖；真实场景留给作者手验 |
| 共享层改动波及其他三端 | 新类型、新令牌并存，U1/U4 门槛包含 Mac 冒烟、Windows 类型检查与 Android 构建 |
| 图区避让效果不理想导致返工 | 参数可调，U1 输出候选组截图供 G1 选择；规则在 G1 后才写进规范 |
| 规范在探索期反复修改 | 未定项留在本计划，确认后才升格；`Design/` 只写已定项 |
| 工作重心再次滑向视觉特效 | §2 原生纪律加 §6.3 搜索复核；每个阶段门先看功能与几何，再看观感 |
