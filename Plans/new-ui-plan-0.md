## 移动端适应的 UI 重构 · Plan 0 · 作者原始需求

我们这个 app 最开始为桌面端设计，随后扩展至 iPad 和安卓，所以 UI 设计本质上是将桌面 UI 强行搬到触屏上用。现在我希望反过来，重新以 iPad 为核心平台，从 UI 和交互设计层面就考虑触屏优化，考虑不同屏幕大小，使用 iPadOS 原生控件和响应式逻辑，完善覆盖大屏、小屏、竖屏、触摸、触控板、键鼠（这些在 iPad 上全都可以通过分屏或外设实现）的统一规划设计，然后再把大屏效果对标放到 Mac 和 Windows，小屏 iPhone 对标到 Android，并做各自原生兼容。

我们曾经有个 archive new ui tag，那是较为失败的尝试，桌面端的设计改半天还是复刻了原样（原始现状几乎已是最优解），而手机端的兼容尝试则是有意义的，不知道那个demo有没有好好考虑组件的响应式复用，大中小屏的分级优化，所以参考价值可能也有限，我们需要考虑的更全面。另外demo的工作重点曾经走偏，过分强调堆砌液态玻璃特效，而没有服务于交互。不得照抄。

我现在以：现有桌面端——新demo手机端，这条两头极端形态作为主轴，来梳理秩序，以便在 iPadOS 上补齐这条轴中间过渡形态的完整设计，我认为为了兼顾移动端，核心差异有几点：

1. 手机端无法容纳完整的 0-5 星布局。缩小成单按钮是有必要的。但我想要个更优解，研究一个新控件，常态是短胶囊（五颗星叠压展示，宽度不宽），点击或长按胶囊后会向上弹出，然后允许手指左右滑动，来快速选择 0-5 星，并有合理的动效和触感。而在 iPad 或更大屏幕上，则可以容纳完整的 0-5 星，并且直接响应点击星级而不再依赖弹出，但保留拖动增减星级的能力。同一个控件的两种形态（或者两种控件）按可用空间响应式切换。并且该控件同时兼容横竖两种，弹出方向和滑动方向也做相应兼容。并且，该控件的短形态既然已经要向上弹出，则还可以顺便吞并冲突浮窗的功能。

2. 手机端无法容纳完整的胶片条信息量，并且小的星级按钮在触屏上几乎不可能准确命中。缩减信息量来紧凑布局是有必要的。我认为应该分级控制，根据屏幕大小来逐步减少信息量。目前先分两级，较大的一级是完整信息即现在的桌面端（缩略图、文件名、拍摄时间、完整星级、抖动标记），较小的一级是缩略信息即现在的手机demo（缩略图、星级数字、文件名，可以再补一个圆形抖动标记）。一个屏幕内至少能容纳五个胶片为好，更多不设上限。目前暂定两档固定大小，后期是否要做更多分级，或者尺寸大小也纳入响应式，后期看效果再决定。

3. 竖屏手机的操作区域放底部，信息显示或低频操作放顶部，是利于操作的。但横屏模式下左右均可布局操作区，不受此限。对于手机布局，在布局模式中增加一个选项，与上下左右并列，就叫“手机”。自动模式在屏幕较小时（包括iPad分屏）也切换至“手机”。只要用户主动切换至手机布局，或者当前设备确实为 iPhone，则不再显示功能按钮自定义，改为一些手机布局下可用的少量自定义开关（下面讲）。可以考虑直接锁定或隐藏其他布局模式，只允许选择手机。对于特殊手机，例如折叠屏 iPhone Duo，例如安卓如何检测，这里先不展开，先把典型手机做好。

4. 手机竖屏底部：底部左为上下张合体按钮，右为缩放适应+雾天增强合体按钮，中间剩余区域给星级胶囊自适应宽度。在设置中做开关“显示上下张按钮”，关闭时左侧不显示上下张，把空间留出以显示完整星级（如果空间够），右侧只留缩放适应和雾天增强。胶片条也位于底部栏，布局跟新 ios demo 差不多，有胶片栏时则有底栏背景，否则不设背景，液态玻璃的按钮和星级胶囊直接叠在图片显示上。

5. 手机竖屏顶部：顶部左为筛选按钮，采用直接原地弹出选项的方式，而非新demo的半屏，内容为原先三筛选条件依次排列，分割线分割，点击后不自动关闭，仅失焦时关闭。顶部右为更多按钮，约等于目前右键或长按菜单的内容，先这么放。顶部中间为 EXIF 信息区域，EXIF 与原始设计基本一致，性状依然是圆角矩形，背景为深色半透，不强调液态玻璃，但可以考虑模糊效果。分析栏也位于顶部，有分析栏则有顶栏背景。相似聚类列表及入口先不做。

6. 手机横屏顶部：这里顶部指手机物理顶部，即有刘海的一侧，主要围绕刘海布局。此处假定手机顶部朝左，若朝右则翻转。左上角为筛选+更多合体按钮，左下角为上下张合体按钮，横向，按钮允许占用刘海两侧的可显示区域。左侧中间为胶片条，不被刘海遮挡，背景规则依然是有胶片条时左边带背景，胶片条滚动到按钮下方时带模糊。开关关闭上下张显示则直接隐藏上下张按钮。左栏元素一律右侧对齐，左侧避让屏幕刘海和屏幕圆角。

7. 手机横屏底部：这里底部指手机下巴，此处假定手机底部朝右。右侧的控制栏完全就是原来的底部控制栏原地旋转 icon，不做任何位移，不做功能增减。但 EXIF 显示区域要在右侧，跟之前一致。打开 EXIF 显示则有右栏背景，否则直接按钮叠背景。

8. 上面说到的所有边栏，默认采用深色毛玻璃背景，照片在放大时会垫在下方模糊。照片不放大时，需要避让屏幕上的一切常态固定元素，即不被胶片栏、分析栏和各种裸按钮挡住任何部分。一般避让至贴合边栏，如果是无边栏背景的裸按钮，还需额外避让一点边距，不能让照片与圆或胶囊按钮直接相切，避让距离和圆按钮原本与边栏边界的间距相等。前面说的边栏对齐原则，也是为了让边栏元素避让照片，在规范的规则下，就可以做到简单的区域划分。但放大时照片依然允许垫在边栏和按钮底下，不做任何裁切，直到窗口或屏幕边缘。

9. 非手机模式，即布局较为宽阔时的模式，常用于 iPad，则基本保持现有布局，少量改造以和前述规则一致：胶片栏背景（边栏）改毛玻璃，缩略图卡片即前面所说的两级信息量中较大的版本（基于目前原始设计的信息要素和大体布局，但风格调整与小版本同源一致，或者小版本往现版本靠近，总之一致）。三项筛选器改新的按钮式筛选器。控制按钮用圆按钮，星级用新控件，EXIF 信息用新样式。胶囊和按钮遵循苹果大小规范，而不用做成原版大小，与之连带的一些尺度大小跟随微调。

10. 以上所有控件，优先采用 ios 26 及以上的苹果原生控件和符合规范的方式实现，除了少数定制控件（例如星级选择器）之外一律使用纯原生默认实现，核心是找到正确的控件，而不要过多地自定义风格、大小，或者通过各种非 26 的老旧控件调参、非原生的特殊手段做强行拟合。需顺应原生，以获得一个符合苹果规范的设计效果。如果以上有需求未完全明确的点，可以按苹果规范推荐先自行处理。

本次任务很可能过长，可以考虑分段执行，例如 EXIF 和星级这种自定义控件，需专项设计，而页面布局或液态玻璃的利用，基本可以直接用原生控件，而 UI 背后的实际功能接入也是一堆工作，你可以考虑下如何拆分任务。但注意不要为了过分追求功能安全，而使用阶段性的补丁方式，过程中不用考虑最小改动、历史兼容等保守取向，应直接向着最终最优目标做定向改造，应做到最后无历史烂账或补丁遗留。

现在属于半尝试性质，所以有些细节未准确描述，有些问题可能待实现后才会暴露。其他平台的对标，以及暂未完全确立的规范，可以在 iPad 做完之后再去详细敲定。已经确定的规范可以先行定版，暂未明确的先自己拿主意，后续改完细节 iPad 完全定版之后，会再彻底敲定设计规范。
