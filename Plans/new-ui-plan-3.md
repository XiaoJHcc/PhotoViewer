# 新 UI 跨平台静态首屏对标 · Plan 3 · 规则并行执行

> 依据：[原始需求](new-ui-plan-0.md)、[iOS 执行规划](new-ui-plan-1.md)及作者最新裁定。分支：`new-ui`。
> 本计划替代 Plan 1「U7+ 跨端对标」的顺序与范围：按已冻结规则同步推广，不逐平台串行，不等待筛选计数、星级弹窗和真机手感专项。
> 阶段号 `S1–S4` 只用于本计划、验收证据与提交信息，不进入 `Design/` 和代码注释。

## 1. 目标与完成定义

将当前 iOS 已敲定的**首屏静态布局与尺度**同步到 Web、Android、macOS：

- 主屏分区、响应式形态、元素位置、尺寸、边距、圆角、间距和收起态外轮廓一致。
- 布局模式与各栏位开关的静态结果一致，包括开关后的空间释放、末端锚点、贯穿与停靠。
- 主图适应区、胶片栏、筛选外框、控制栏、EXIF、分析栏和相似面板按同一套规则落位。
- 使用各平台原生材质与控件承载，保留平台字体、菜单和状态反馈，不复刻液态玻璃高光、折射等光学效果。
- Windows 界面迁移单独滞后；本计划只要求共享改动不破坏其构建和既有行为。

本轮集成提交须同时满足：

1. S1–S4 的静态验收门全部通过，Web、Android、macOS 的规定视口与开关组合均有实际几何证据；模拟器与真机证据分开标注。
2. 标准版与 AI 版均完成静态矩阵；既有业务行为与交互回归无退化。
3. 三端截图矩阵与差距清单已交作者目视复核；作者未签字前不标记“作者手验通过”，也不以材质差异或容量例外伪造几何一致。
4. `Design/status.md` 只回填本次实际覆盖的静态边界，不把未实施的菜单、弹窗或手势标为完成。

## 2. 冻结范围

### 2.1 本计划包含

| 规则范围 | 本次落地内容 |
|---|---|
| SHELL-01、04、07–12 | 宽/手机形态、行列/自动布局、满窗口主图、适应区、栏位材质、开关与持久化、末端锚点、工具区、贯穿与避让 |
| FILM-02、05、07 的静态部分 | 列表几何、两档卡片、静态内容、带厚、选档、首末停靠、列布局统一末端 |
| FILTER-01、06、07 的静态部分 | 筛选收起态外轮廓、AI 开关、行列落位与宽度；计数不属于本批 |
| TOOLBAR-01、02、05、07、08 的静态部分 | 三组顺序、流式换组、EXIF 横竖排与无衬底变体、44 点命令按钮、设置变更后的几何、溢出宿主 |
| TOOLBAR-03、04 的静态部分 | 星级控件收起态外框、命令图标与静态按钮外框；不包含 tooltip 和星级内部新交互 |
| ANALYSIS-05、SIM-07 | 分析栏和相似面板的分区、宽度、接缝、显隐后的静态几何 |
| SETTINGS-08、17 与 SHELL-04 相关接线 | 按平台能力提供布局模式和既定开关，沿用原生设置页样式 |
| PhotoViewport 的适应区部分 | 视图矩形与适应矩形分离，静态重排保持当前照片、缩放中心与相对倍率 |

筛选与星级控件以**已冻结的收起态外轮廓**为布局槽位。内部可继续承载平台现有静态内容和既有业务逻辑；本计划不认定内部呈现已经定稿，也不为其新增过渡手势、菜单或弹层适配。既有计数不重新设计、不新增独立占位，任何保留方式都不得挤动冻结外框；计数内部呈现不纳入本轮几何结论。

### 2.2 本计划不包含

- FILTER-04 的计数收入控件，FILTER-08 的菜单结构、屏上勾选、滚动和焦点。
- RATING-04、07 的紧凑星簇、拖动选择、星级弹窗、冲突来源合并、触感与动效。
- 卡片长按、辅助点按、指针/触摸评分分流，以及下拉、右键、长按等二级菜单。
- 液态玻璃高光、折射、融合、按压回弹和平台专属光学效果。
- Windows 原生界面迁移、旧几何与旧令牌清理。

既有功能继续可用，但上述行为的新设计不属于本批验收。不得为了配合静态外框而提前实现后续专项。

## 3. 平台口径

| 平台 | 形态范围 | 单位与响应式 | 材质与控件 |
|---|---|---|---|
| Web | 以 iPad 自动模式为标准，覆盖宽形态和紧凑分屏对应的手机形态；不模拟 iPhone 设备专属矩阵 | CSS px = pt；自动模式按 `<600` 宽映射横向紧凑，不读 User-Agent；安全区只读公开 `env(safe-area-inset-*)` | CSS 原生 `backdrop-filter`；主屏 DOM/Canvas，零新增依赖；筛选采用 iPad 的 96 点「筛选 / 更多」合体 |
| Android | 直接对标 iOS，覆盖手机竖横屏与平板宽形态 | dp = pt；原生尺寸类别映射到共享 `ScreenFormResolver`，真实 Insets 参与几何 | Views + Material 3；应用内模糊只使用公开原生能力 |
| macOS | 对标 iPad 大布局，只覆盖行、列、自动宽形态 | pt；不启用手机形态，保留系统标题栏与交通灯 | AppKit + `NSVisualEffectView`；系统菜单与原生状态反馈 |
| Windows | 后续按同一静态规则包迁移宽形态 | DIP = pt；本批不改界面 | 本批仅做共享兼容、类型检查与既有回归 |

iPad mini 1/3 分屏沿用当前 iOS 的实测容量例外，作为独立配置记录，不据此新增第三档卡片或修改冻结尺寸，也不把该例外推广成通用规则。

## 5. 分阶段任务与验收门

### S1 外壳与响应式规则包

**D 任务**

- 按既定规范核对 `ScreenFormResolver`、`ShellPaneLayout`、`PhoneScreenLayout`、`FilmSideGeometry`、`ToolRegionGeometry`、`PhotoViewport.SetFitInsets` 的共享输入与契约，以共享几何计算结果作为跨端基准。
- 先补 `ToolbarFlowLayout` 的完整分组落位 API 与无衬底 EXIF 尺寸输入，输出文档尺寸及逐组矩形，避免 Mac / Android 各自复制换行、居中和交叉轴公式；保留 Windows 继续依赖的旧入口。
- 在 `CoreContractCheck` 对配置网格穷举胶片栏、控制栏、分析栏、EXIF、评分、上下张和 AI 相似入口的开关组合，断言矩形非负、边界相接、适应区合法、镜像与释放规则正确。
- 定义各端共用的静态几何节点清单。必需节点缺失即失败，单边独有节点只有已登记平台差异才可豁免。
- 保持 Windows 所依赖的旧入口可用，本批不执行清理。

**W/A/M 并行任务**

- W：实现响应式形态判定、满窗口主图、栏位背景与内容、适应区和栏位开关；设置状态沿用 `localStorage` 既有键。
- A：启用手机形态能力，接入共享宽/手机几何与真实 Insets；补齐布局模式、EXIF 和上下张开关的原生设置接线，沿用 Material 设置页。
- M：接入 `ShellPaneLayout` 与适应区，仅实现宽形态；保留标题栏、交通灯、窗口恢复和系统菜单行为。

**S1 验收门**

- 三端相同规则配置下的必需外壳节点在 0.5 pt/dp 容差内一致。
- 行/列/自动/手机按平台能力正确切换，旋转与视口变化只重排，不重建照片会话。
- 开关组合的空间释放、背景出现、透明边栏避让和末端锚点通过共享契约与实际 frame 双重检查。
- Windows 类型检查通过；共享影响 iOS 时复跑 form/layout/photo/gesture 的代表配置。

### S2 胶片栏与筛选外框规则包

**D 任务**

- 按既定规范核对 `FilmCardGeometry`、胶片列表静态几何和 `WideFilterLayout` 筛选收起态外框。
- 导出卡片外框、照片区、文本区、静态徽标、筛选外框、AI 开关和相似面板节点。
- 契约覆盖两档尺寸、选档、带厚、首末停靠、末端对齐、标准/AI 差异与登记的容量例外。

**W/A/M 并行任务**

- 实现两档卡片及静态内容，宽形态固定大档，手机按主轴容量选档；相似面板复用大档。
- 实现胶片栏贯穿、首末内容留白、列布局末端锚点与静态相似面板几何。
- 实现筛选收起态外轮廓和 AI 开关的位置、尺寸与静态选中外观；保留既有筛选业务入口，菜单专项不随本批改动。

**S2 验收门**

- 卡片尺寸、照片区、静态文本区、徽标、筛选外框及相似面板节点全部通过几何差分。
- 宽形态不降档，手机选档与可见容量符合规则；iPad mini 1/3 只按登记例外出证。
- 标准版不残留 AI 入口或空槽，AI 版开关与面板静态占位一致。
- 既有点选、筛选、排序和定位行为回归通过，不新增长按或菜单行为断言。

### S3 控制栏与工具区规则包

**D 任务**

- 收口 `ToolbarFlowLayout`、`ExifBlockGeometry`、`RatingControlGeometry` 的收起态外框、`AnalysisPanelGeometry` 与工具区几何。
- 导出 EXIF 块与项目、评分外框、44 点命令按钮、分析瓦片、连续背景、唯一外边界和接缝节点。
- 契约覆盖整组换行/换列、交叉轴居中、评分与 EXIF 开关释放、无衬底整项裁剪和空组移除。

**W/A/M 并行任务**

- 按 EXIF → 评分 → 命令排列三组，实现 44 点命令按钮、静态评分外框和 EXIF 横竖排/无衬底变体。
- 实现宽形态整组换组与溢出宿主，手机形态固定槽位；保留既有评分写回和 EXIF 详情入口。
- 实现分析栏与控制栏的共同工具区、连续材质宿主、唯一外边界、接缝及同轴居中。

**S3 验收门**

- 三组顺序、按钮尺寸、评分外框、EXIF 项目、换组和工具区几何全部通过差分。
- 关闭评分或 EXIF 后的空间释放符合各形态规则；空组不占位，禁用不引起几何抖动。
- 既有评分、命令、EXIF 导航和分析展示回归通过，不新增星级弹窗、拖动或 tooltip 断言。

### S4 材质复核与三端联合验收

**任务**

1. 接入或确认各平台原生栏位材质，只核对外观连续性、背景出现条件和照片上方取样，不比较系统材质像素。
2. 三端按统一节点清单导出静态几何，V 以共享几何计算结果为基准执行 Web/Android/macOS 差分；规范已登记的平台差异按原口径保留。
3. 运行 §6 的完整矩阵与既有回归，整理失败、平台差异和后续专项边界。
4. 更新 `platforms.md` 的实际入口、`status.md` 的静态覆盖边界和本计划证据索引，证据保存到 `artifacts/acceptance/new-ui/cross-platform-static/`。

**S4 验收门**

- 必需节点无缺失，几何差分在 0.5 pt/dp 内；所有豁免均能指向已登记平台差异。
- 材质只使用公开原生方案。若 Android 公开能力无法覆盖主图上栏位模糊，保留几何结论并单独报告材质边界，不以截屏、离屏拷贝或自绘光学效果冒充完成。
- 集成门：三端标准版与 AI 版构建、静态检查和既有回归通过，提交截图矩阵与差距清单。产品验收门：作者复核截图与原生材质/手感后另行签字，不以程序化通过代替。

### 6.2 检查与证据

- 共享：`CoreContractCheck` 标准版、AI 版均 0 FAIL；令牌生成校验通过。
- Web：Node 单测、静态页内检查及既有 `?check=all`；保留旧行为断言，新增静态节点检查。
- Android：两版构建，`layout`、新增/扩展的 `form`、`main`、`analysis`、`similarity` 及既有相关模式；真实设备与模拟器证据分开标记。
- macOS：两版构建，layout、filmstrip、toolbar、analysis、similarity 及相关既有套件。
- iOS：共享代码受影响时复跑代表配置的 form、layout、photo、gesture，确认参考实现未退化。
- Windows：类型检查与既有可用回归；不以 macOS 上的类型检查冒充 Windows 原生界面验收。
- 证据：每配置保存几何 JSON、原生报告和截图，命名包含平台、版本、形态、布局、视口与开关组合。

## 7. 变更控制与停止规则

- `Design/spec/` 与 `tokens.json` 不在本计划中改写；`platforms.md` 只登记平台映射、公开能力边界与实际入口，`status.md` 按实际证据回填。执行疑问按 `Design/README.md` 的权威顺序核对，平台工作线不得本地拟合或另立规则。
- 需要新增或改变本计划未批准的 UI 行为时，单独列出触发条件、显示内容和影响平台，报作者审批后再纳入；默认继续完成其余静态项。
- 不用平台私有常量、截图测量值或字体经验补偿覆盖令牌。文字度量差异只影响文本，不改变冻结外框。
- 不删除既有失败断言来制造通过；确属旧前提失效时，保留等价行为覆盖并在证据中说明替换理由。
- 原生材质能力不足时只登记真实边界，不发明模糊、折射或高光方案，也不让材质问题阻塞已完成的几何验收。
- 当前工作树中的 iOS U4 与共享布局成果是本计划的参考基线，开工时不得重置或以旧平台版本覆盖。

## 8. 提交与后续

本轮由集成者在三端实现与验证完成后统一审查并形成一次集成提交。提交前重读全部改动，清理会话标号、负向补丁描述和无来源常量；按实际参与模型填写落款。作者截图复核后的返工另行提交，不把待手验项写成已通过。

- 交互专项：筛选计数与菜单、星级控件与弹窗、卡片输入分流和二级菜单。
- Windows 静态迁移：复用本计划同一规范、节点清单和几何基线，最后完成旧几何与旧令牌清理。


## 9. 实施与验收结果

### 9.1 实现与路线复核

Web 已按 iPad 自动响应式口径实现宽形态与紧凑分屏；Mac 只启用宽形态；Android 同时接入手机竖横屏与平板宽形态。三端均把主图视图与适应区分离，栏位开关、连续工具区、卡片两档、筛选及评分收起外框按共享规则落位。Windows 原生界面与 iOS 源码保持不变；iOS 手册仅修正共享入口索引。

原生壳复用既有共享几何，新增 `ToolbarFlowLayout.Arrange` 汇总分组落位；无衬底纵排固定 44 点容器，没有任意交叉轴宽度参数。Web 独立依据设计实现，未引入依赖。Mac 使用 AppKit / NSVisualEffectView / NSMenu；Android 使用 AndroidX Window、Views、Material 3、RecyclerView 与公开 Insets，没有私有 UI API、按型号拟合、截图模糊或离屏主图模糊。

终审已纠正：Web EXIF 脱离控制栏滚动文档、手机横屏隐藏控制栏残留按钮、上下张及适应/增强缺少单一合体外框、控制节点导出的坐标空间、计数越框与重复评分槽公式；Android 放大态切换栏位的中心偏移、纵排评分槽两轴、小档卡片内部坐标与误用列表边距、宽形态圆按钮与评分胶囊、合体状态层裁剪、重复布局重绑及菜单锚点；Mac 验收坐标/编译错误、计数宿主宽度与系统截屏。Mac 增强验收固定 1200×850 窗口并恢复适应态：最小窗口全开栏位曾使读回区域缩为 3×2 像素，不能用其判定增强效果；阈值仍为平均差 ≥6、最大差 ≥30，双版实测最大差 49。

### 9.3 证据索引

所有本机证据在 `artifacts/acceptance/new-ui/cross-platform-static/`，不入库：

- `web/`：双版与 mac 配置档几何 JSON、代表截图。
- `macos-standard/`、`macos-ai/`：按套件分目录的运行记录、原生报告与真实系统窗口截图。主窗口图片直接由系统合成器截取，不再补画/缩放胶片文档；材质像素不作跨平台相等结论。
- `web-*-required-geometry.json`、`mac-*-required-geometry.json`、`required-geometry-checks.txt`：归一化必需节点与差分结论。
- `reports/`、`android-static-report.md`、`android-*.png`：Android 原始检查、公开 Insets 与截图。手机横屏及镜像图为 2400×1080；平板行图 1000×1600、列图 1600×1000，已核对实际画面而非仅按文件名推断。
- `ios-regression/`：共享增量的 iPad 标准版 / iPhone AI 版八套代表报告。

Android 模拟器为 API 35 arm64 软件 GPU，仅证明几何与行为，不验证真实 GPU 性能或 P3。验收后已还原模拟器尺寸、密度和方向并停止本轮启动的 Android 模拟器；既有 iOS 模拟器保留。

### 9.4 待作者复核与公开能力边界

- 作者尚未签字：需复核三端真实界面的静态观感、系统字体/材质、真机圆角与刘海、触控手感及大字体。程序化通过没有提升为作者手验通过。
- Android 的 SurfaceView 主图没有现成公开的应用内背衬模糊方案，本轮使用半透明深色与 Material 形状/状态层；没有为对齐 iOS 玻璃而做截图、PixelCopy 或离屏复制。
- Android 目前沿用冻结的 44dp 控件与命中几何；Google 通用无障碍指南建议至少 48dp 触摸目标。该建议与本轮冻结尺寸需要分开裁定，尚未擅自放大控件或引入相邻命中区重叠；若要求 48dp 为硬门，应另定可视框与触摸宿主规则。此项不宣称已满足 48dp 建议。
- 筛选计数内部样式、筛选菜单新设计、星级紧凑交互/弹窗/拖动与卡片输入分流仍属后续专项。现有功能保留不等于新交互已定稿；Mac 原生右键菜单继续沿用。
- Web 材质的 alpha / blur 尚无独立令牌，当前只用公开 CSS 能力与已有色彩/模糊令牌，取值待材质专项统一；细项见 `web-shell-gaps.md` G49–G54。浏览器不具备 iOS 的逐带圆角探测。
- Windows 原生界面迁移未做，真机色彩、真实性能与外接显示未由本轮模拟器结果代替。
