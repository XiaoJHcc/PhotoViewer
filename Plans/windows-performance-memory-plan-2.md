# Windows 性能与内存专项 方案 2

## 目标与边界

补齐大图提交显示测量和持续压力约束，再以同口径对照验证大图资源复用、RAW 一次开发复用。保持代理尺寸、F16 色彩、方向、缓存租约与既有界面，不强制所有 RAW 直接 Full，不改适配器选择或引入硬件解码依赖。Git 提交按用户明确授权执行，不自动推送。

## 测量口径与环境

- 本轮主机 i5-13600K / 20 逻辑处理器 / 约 48GB。启动拓扑确认设备在 **RTX 4080**，本地输出 `DISPLAY1` 为 3840×2160，DPI 150%，SDR 使用实际关联 ICC；核显另接输出。与方案 1 的远程/虚拟显示核显会话不同，不把跨环境差异当本轮提速。
- 素材 `D:/照片2026/2026-5-4 湘湖/A7C2`，161 组 RAW+HIF（322 文件），翻页用默认同名组合并后的 HIF；RAW 探针每类取 6 张，首张预热、n=5。
- 新压测以 `present-return` 为终点，含目标正式纹理提交，旧口径是会话像素就绪；旧/新 p95 不直接比较。Present 返回不代表物理屏幕扫描完成。
- 固定视口前必须等首次布局完成，避免启动默认尺寸覆盖测试 resize。早期 `large-before/small` 两轮实际视口相同（1495×1264），**不得用作大小窗口对照**；后续 `small-final/large-final` 已按报告确认真实尺寸。
- 报告位于 `artifacts/acceptance/windows-perf-2/`；隔离设置、库、日志分套件输出，内存事件也指定套件路径。此前旧初始化接口只按默认目录写内存诊断，本轮补了可选日志路径；未改用户设置和源照片。

## staging 候选的否决证据

大窗口 100 翻，顺序 OFF→ON→ON→OFF：

- 阻塞 Map 复用 99/100 次；上传墙钟 p95 由 OFF 的 145.66/65.17ms 降至 ON 的 44.02/36.09ms，但 Map 引入 p95 13.94/6.40ms、max 57.41ms 的 UI 等待。只看后台搬运会误判收益。
- DO_NOT_WAIT 后代理仅 14/100 次复用；上传墙钟 p95 ON/OFF 为 59.01/71.73ms，而整条切图 p95 为 448.6/351.5ms，未证明净收益。Full 配对的切图 p95 ON/OFF 为 609.9/594.7ms，上传墙钟为 84.81/114.31ms。
- 两类均零超时，结果受预取/解码跑间波动影响；不足以为了这组上传子指标增加约 148–251MiB 的常驻 staging。所有候选代码、环境开关、统计和专属测试已移除，保留原有一次在途上传与小图空纹理复用。

## 未覆盖边界

真实 8/16GB 设备、远程/虚拟显示核显会话的新计时重测、实际 HDR/ACM 开关与跨屏校准。HEIF 平面准入是保守估算，不是 FFmpeg/DPB 峰值上界；P0 保留原有豁免契约。一般 RAW 是否直接 Full 仍不默认实施；当前方案只复用开发源，不改变首屏代理策略。

## 来源浮窗高 DPI 修复

按后续要求独立修复 RATING-04，不再把已确认的基线失败留作性能专项的收尾阻塞。

- 新增「计划外形与真实原生 Presenter 尺寸」断言后，修复前在常规横排入口即失败：计划 `206×194 DIP`，实际 `206.666656×194.666687 DIP`，`RasterizationScale=1.5`。两条 1 DIP 原生边框分别取整为 2px，共 4px，旧算法只计 3px；贴工作区下缘时一像素溢出触发整块二次翻转。
- Windows 壳现在对内容与四侧边框分别按当前 DPI 做物理像素取整，再换回 DIP，使用真实外形预测值调用原有共享 `RatingSourcesLayout.Place`。不改令牌、星排尺寸、原生材质、方向规则或原有位置容差。
- 新尺寸断言独立对照真实 Presenter（误差不超过半个物理像素），原位置逐轴 ±1 DIP 断言保留；补 100/125/150/175/200/250% 的纯计算取整用例，并在 150% 本机覆盖下/右/左/上与双轴夹取、关闭状态同步、回到工作区后的复位。
- 双轴用例初试右下时窗口多数面积进入相邻显示器，真实查询已切到另一个工作区，故并不满足两轴同时越界的前提；用例改到左下以保持目标显示器，仍严格要求两轴同时发生夹取，不放宽断言。
- 增加隔离入口 `--pv-native-rating`（复用完整 smoke 中同一套真实评分/浮窗检查，报告 `rating-checks.json`），无需 DINO/上传等无关前置即可复验。首轮原修复的完整 Release smoke 为 38 PASS；扩展四边/双轴后的独立评分专项 3 PASS。
- 排查中曾有一轮完整 smoke 在首个控制栏浮窗打开时超时，未据此宣称另一个原因已修复；最终以同一交付构建的完整复验结果为准。其它缩放比例目前只覆盖纯计算，真实 DPI 跨屏切换仍保留硬件验收边界。
- 扩展边缘用例后的完整复验先通过浮窗，随后在标题栏背板素材的 Full 检查超时。该脚本仅等 `PhotoLoadSession.Image` 就绪就调用 Fit/ToggleFit，未等异步代理纹理换入；缩放会作用于旧几何，与 Windows 壳既有的上传等待契约不符。补 `WaitForUploadAsync("背板素材代理上传")` 后才执行缩放，Full 断言与超时均未放宽，产品视口逻辑未改。
