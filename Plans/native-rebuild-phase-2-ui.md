## 1. 主窗口

跨平台对账 ID 与已确认要求参照 [UI 交互草稿](../Design/ui-contract.md)。**2026-10-15 最新要求**：本轮只对拍主界面，布局结构、尺寸和边距按原 Avalonia 设计对齐；背景取原设计或合适的原生深色，边框、圆角先按原生；菜单、字体、字重和颜色规范接近原设计或效果更好时可保留原生，需判断而非机械堆砌控件。设置界面及 P3 功能不在本轮范围。此决定替代此前主界面几何仅“近似”的宽松约定。

### 1.1 布局

保留现有 `LayoutMode.Col / Row / Auto`，读取原设置，不重置用户布局：

```text
左右（横屏）                       上下（竖屏）
┌────────────────────────────┐    ┌──────────────────────────────┐
│ 筛选 │                 │EXIF│    │ 排序 · 方向 · 星级筛选 · 计数 │
│──────│                 │评分│    │            胶片条             │
│胶片条│      主图       │按钮│    ├──────────────────────────────┤
│      │                 │    │    │                              │
│      │                 │    │    │             主图             │
│      │                 │    │    │                              │
└──────┴─────────────────┴────┘    ├──────────────────────────────┤
                                  │ EXIF · 评分 · 控制按钮        │
                                  └──────────────────────────────┘
```

- 左右布局：左边一列缩略图，筛选控件在上；主图占剩余空间；右边依次为 EXIF、评分、已启用的控制按钮。
- 左右文件栏内容宽 116 点，另计分隔线 1 点；筛选控件占位 90×32、顶部 34，三下拉间隔 5、计数自然测量；与 96 点卡片占位共用 x=58 中线。原生按钮的可见边框、字体和菜单沿用系统绘制。
- 上下文件栏筛选区高 52、列表高 159、分隔线 1，共占 212 点；卡片 90×138、四周 3 点占位，列表边距左右 10/上 5/下 10。短横向列表整体居中，溢出后使用原内边距滚动。主图不另加内边距。
- 上下布局：筛选条与横向胶片条在上，主图居中，EXIF、评分和控制按钮在下；底栏空间不足时换行。
- 自动布局：沿用现有按窗口内容区方向判定的规则，调整窗口尺寸后切换，不依据照片横竖切换。
- 胶片条与控制栏可分别隐藏；隐藏后空间归主图。全屏沿用当前布局和显隐状态，使用系统全屏按钮及菜单。
- 主窗口继续采用**隐藏式标题栏**：内容延伸至窗口顶边，没有独立占高的标题条，也不新增常驻文件名/操作工具条。系统交通灯嵌入左上角，筛选控件局部避让；沿用现有顶边悬停显示拖拽区域、离开/失焦收起的意图，不能吞掉筛选器或照片手势。标题文字仅保留为系统窗口元数据。
- 原生实现使用 `NSWindow` 的完整内容区、隐藏标题文字与透明标题栏能力；保留交通灯、窗口拖动、缩放与系统全屏，不通过取消窗口装饰来模拟。上下布局的拖动区域避让居中筛选条，左右布局局部避让交通灯。
- 观片区域黑底；控件区使用原生深色外观，维持现有观片环境。菜单、下拉框、滚动条采用原生控件；按钮的边框、圆角、悬停/禁用反馈接近原生，同时遵守下方几何约束。

### 1.2 胶片条与标识

原生 `NSCollectionView` 虚拟化。保留照片、文件名、拍摄时间、0–5 星评分和抖动徽标，卡片面积接近现有规模；文件名截断时悬停可看全名。**缩略图容器保持正方形，照片在其中等比适应/留黑，不能拉伸照片或把容器拉成横向矩形。**

| 状态 | 具体呈现 | 交互/含义 |
|---|---|---|
| 当前照片 | 卡片外缘清晰蓝色描边 | 单击切换主图但不滚动；翻页/打开的显式请求按 FILM-01/02 用 350ms 三次缓出居中，首尾受边界约束 |
| 主图已缓存 | 照片内部较淡的蓝色细边 | 与当前项描边分层，继续沿用 `IsInCache` 语义；不能把缩略图已加载当成主图已缓存 |
| 评分 | 已评分为金色实心星，未评分为灰色空星；独立清零入口 | 星级按钮点击只改该卡片的评分，不触发父卡片切图；主图评分按钮改当前照片 |
| 已判为抖动 | 照片右下角橙色“抖”徽标 | 仅 `IsShake == true` 显示；未分析不显示，不推断为正常 |
| 缩略图加载 | 简洁占位及延迟显示的进度 | 滚动不等待解码；加载失败仍可点击尝试打开主图 |
| 无筛选结果 | 胶片条简短空状态 | 保留筛选控件，不自动改用户筛选条件 |

评分仍复用既有写回、同名文件同步和安全写入策略；成功后刷新文件内存状态与筛选结果。原生 UI 对写入失败提供简短可见错误，不能只写控制台日志或显示成功星级。

排序、筛选、改星、交换上一张及普通 CurrentFile 赋值不主动居中；新定位从当前帧接续，点选/滚轮/滚动条接管时取消排队请求及旧动画。系统减少动态效果直接定位。Mac 重新显示胶片条/切换方向仍定位当前项，作为 FILM-04 平台差异登记；普通 resize 只限制偏移范围。

### 1.3 筛选与控制栏

- 筛选条保留原有排序方式、升降序、星级筛选及筛选后计数，换成原生下拉框；名称、取值和排序语义保持一致。
- 筛选菜单通过公开 `NSMenu.PopUpMenu` 定位到按钮左下角，内容左边缘与按钮对齐；内容锚点向下预留 8 逻辑点，包含 macOS 26 菜单向上延伸的 5 点外框后，菜单与按钮之间保留 3 点可见间距。保留原生选中勾号、鼠标跟踪、键盘选择及取消，不使用默认按选中项文字定位的左移锚点。
- 控制栏保留设置启用的 EXIF 项及顺序、评分、上一张/下一张、切换上一张、适应/放大切换、预设缩放等现有可用命令。
- 2026-10-15 工具栏对拍修正：EXIF/评分/命令作为三个整体分组，按可用空间换行/换列并居中，不摊平成长列；EXIF 保留标签与强调值的信息层级及完整内容 tooltip。评分横向 0→5、纵向 5→0，隐藏后不留空分组。工具按钮采用可变高度的原生 SmallSquare 边框与圆角裁剪，验证实际绘制覆盖 40×40 区域，避免固定高度边框显示成扁条；显示的评分快捷命令保留星数。命令 tooltip 使用苹果主次绑定，设置显隐/排序和绑定变化即时刷新。
- 可用控制按钮继续由 `Hotkeys.IsDisplay` 及用户排序驱动，不另建硬编码工具栏配置。图标按下方语义映射提供，悬停显示命令名和实际快捷键。
- P3 功能入口在原生主窗口菜单/控制栏隐藏，包括分析栏、相似聚类、增强预览、工具页及 EXIF 详情跳转；保留其持久化配置，旧壳仍可使用。主控制栏的 EXIF 摘要继续显示。

### 1.4 几何约束与原生控件边界

| 元素 | 原实现参考尺寸（逻辑点） | 原生版约束 |
|---|---|---|
| 缩略图区 | 80×80 | 宽高 1:1；图片按原比例留边；外卡片仍为包含文字/星级的竖向矩形 |
| 控制按钮 | 40×40 | 保持方形点击区域与位置，图标居中；按钮外观可原生化，不由文字长度拉宽 |
| 主评分按钮 | 30×30 | 保持方形且按原布局横排/竖排，使用独立评分符号 |
| 抖动徽标 | 16×16 | 方形、圆角、橙底“抖”，保持缩略图区右下角含义 |
| EXIF 信息块 | 50×40 | 主轴两端各 4，块间另隔 4，交叉轴居中；#222 底和原生文字层级 |
| 下拉框 | 90×32 占位 | 保留位置、5 点间距和整体居中，系统原生边框/箭头/菜单可比占位更紧凑 |
| 细节/诊断瓦片（P3） | 方形外容器、内部 letterbox | P3 沿用原方形约束，内容比例与容器比例分开处理 |

本轮 macOS 主界面几何以旧壳同配置实测为准，Retina 通过逻辑点与 backing scale 处理；不能改变结构、占位、分组边距与方形比例。系统按钮/菜单的可见边框与字体光学留白不强制逐像素仿制，须与布局占位区分。

### 1.5 字体图标迁移

**建议 Apple 原生壳优先采用 SF Symbols**，通过 AppKit `NSImage.GetSystemSymbol`（iOS 对应 `UIImage.GetSystemImage`）加载；字号、字重、颜色由原生控件统一配置。共享层仍只提供命令标识和状态，平台层维护“命令 → 图标”的显式映射，不修改已有快捷键 JSON 的私用区字码。

| 语义 | SF Symbols 候选（实施时核对最低系统可用性） |
|---|---|
| 打开 | `folder` |
| 上一张 / 下一张 | `chevron.left` / `chevron.right` |
| 切换上一张 | `arrow.left.arrow.right` |
| 适应 / 放大切换 | `arrow.up.left.and.arrow.down.right` |
| 放大 / 缩小 | `plus` / `minus` |
| 有评分 / 无评分星 | `star.fill` / `star` |
| 清零评分 | `xmark` |
| 设置 | `gearshape`（仅在已有图标入口需要时使用） |

- 各图标在方形按钮中保持相近视觉尺寸，不能按系统符号的固有宽高改变按钮形状。评分金色与抖动橙色继续使用原语义。
- 无语义匹配的业务图标，明确指定复用原 Uicons 字体并由原生文字绘制，或提供专用矢量资产；不使用缺字方框、随机相似符号或 Emoji 替代。每项只指定一个正常来源，系统版本兼容处理仅限已知不可用的符号。
- Windows/Android 的图标在各自平台映射，同一命令保持可识别含义；不把 Apple 符号资源当作四平台共享字库。原字体资源继续服务旧壳及确需保留的图标。
- 当前交互示意使用通用符号表达位置与用途，**并非 SF Symbols 真屏样式**；最终字号、笔画与留白在 AppKit 原生实现中验收。

## 2. 主图交互

| 操作 | 推荐行为 |
|---|---|
| 双击照片 | 在“适应”与点击位置的 100% 放大间切换，缩放锚点不漂移 |
| 适应命令（现有 F 等绑定） | 沿用适应/100% 切换；放大优先对焦点，无对焦点则视图中心 |
| 触控板捏合 | 连续缩放，以手势中心为锚点；允许短动画，尊重系统减少动态效果设置 |
| 放大后鼠标拖动 | 平移照片，边缘约束避免整张拖出视口 |
| 触控板双指滚动 | 平移，并保留系统惯性阶段；不把高频连续滚动事件当作连续翻页 |
| 鼠标滚轮 | 保留现有手势绑定，默认上下滚轮上一张/下一张；修饰键缩放亦读取现有配置 |
| 键盘与鼠标快捷键 | 沿用用户 `AppGesture`、苹果修饰键映射及主/次绑定，不重置为新快捷键表 |
| 文本框/快捷键录制获焦 | 暂停照片全局快捷键，防止输入数字改评分、方向键误翻图 |
| 放大时切图 | 沿用当前缩放状态及对焦点/相对位置策略；适应态切图继续适应 |
| 代理升级 Full | 保持位置、缩放和显示朝向，不因纹理尺寸变化产生跳变 |
| 快速翻图 | 未命中新照片时清旧图，作废过期加载；加载提示延迟出现，减少闪烁 |
| 缩放导航图 | 保留右下角缩略导航图、可见区域框与百分比，遵循原显示开关；使用小纹理，不重画全分辨率图 |

**100% 口径建议（需拍板）**：一个源像素对应一个屏幕物理像素，Retina 下不将一个源像素扩成 2×2 屏幕像素。达到 100% 或代理覆盖不足就请求 Full；Full 就绪前不宣称已具备全分辨率细节。其他缩放档位也按相同口径显示百分比。

触控板事件和离散鼠标滚轮需要分开识别；显式用户自定义手势优先。具体惯性/动画参数由真屏实测决定，保留快速选片时的直接响应。

## 3. 菜单、打开与窗口

- 应用菜单：设置、关于、退出。设置使用 macOS 常规入口及 `⌘,`。
- 文件菜单：打开文件、打开文件夹。使用 `NSOpenPanel`，照片与目录选择各有明确入口；原“打开”命令及现有绑定继续有效。
- 显示菜单：上下/左右/自动布局、胶片条显隐、控制栏显隐、系统全屏，均显示当前勾选状态。
- 照片右键菜单：打开、胶片条/控制栏显隐、设置等本阶段可用项，替换旧自绘覆盖层。
- Finder“打开方式”、Dock 拖入、命令行打开统一进入现有外部打开流程，目标文件成为当前照片；可访问父目录时加载同目录，权限受限时沿用单图模式。
- 窗口位置、尺寸及现有持久化状态延续；恢复时约束到当前可用屏幕。跨屏时重新上报物理像素比例及显示色彩空间，不重新读文件。

## 4. 原生设置窗口

**作者确定的方向：参考已有 iOS 原生设置，以 macOS 原生设置风格实现，功能一致即可。** 参考实现为 [iOSNativeSettingsPresenter.cs](../PhotoViewer.iOS/Core/iOSNativeSettingsPresenter.cs)：分类导航 → 分组表单 → 复杂项的专门编辑页，以及设置工作副本会话。复用分组与交互思路，Mac 使用 AppKit 控件与桌面窗口交互。

具体采用独立原生设置窗口：固定 DarkAqua 深色外观，左侧 NSSplitViewController 的系统 Sidebar 与 SourceList 分类导航，右侧语义色分组表单。保留“文件 / 预览 / 控制 / EXIF / AI”五个功能类别；每页的项目排列、组间留白、对齐与编辑方式按 macOS 设置惯例组织。侧栏使用系统材质与 SF Symbols，滚动容器无外框、使用 overlay 滚动条。

- 原生侧栏/分栏承载分类，使用原生复选框或开关、弹出菜单、数值输入框、表格及系统警告框；语义颜色、字号与选中态由系统绘制，设置窗口按作者要求固定深色。
- 原生表单按含义分组；主要标签和控制对齐，必要的单位、范围与错误信息靠近编辑控件。长列表使用原生滚动与拖动排序，复杂配置进入独立编辑区或 sheet。
- 文件格式及优先级、缩放预设、快捷键录制与冲突、EXIF 显隐与排序等必须完整可操作；排序采用视图式 NSTableView，复选框独立列，名称区域支持系统行选择与拖放，逐行 pasteboard writer 提供系统拖动预览/行间插入/自动滚动。控制功能名称、显隐勾选和主次快捷键必须同一行；冲突显示系统橙色，录制完成只刷新行、不重建整页。
- 主窗口的隐藏式标题栏与观片布局约束作用于主窗口；设置窗口采用 macOS 设置窗口的系统标题栏及导航，不照搬主图壳的装饰。
- 网页示意里的设置页仅为先前讨论稿，已被本节方向替代；实现后提供真实 AppKit 截图和操作清单验收。

| 分类 | 功能覆盖 | 原生迁移方式 |
|---|---|---|
| 文件 | 格式启用/优先级、同名合并、解码线程、缓存上限、各类预载数量及延时 | 格式列表可拖动排序；滑条与数值输入同步；保留平台预算范围 |
| 预览 | 缩放导航图、缩放预设及添加/编辑/删除 | 数值编辑完成再校验，禁止编辑半个数字就触发重载 |
| 控制 | 上下/左右/自动、控制按钮显隐/顺序、主次快捷键、苹果键盘映射 | 原生列表排序与手势录制；冲突继续可见 |
| EXIF | 主控制栏 EXIF 项显隐/顺序、评分显隐、安全修改 | 原生字段列表及评分选项组，功能和持久化语义一致 |

## 6. 实施前需验证的工程修订

以下不需要作者选择 API，但必须实证后写回阶段清单：

- **线性数据与标签必须一致**：scRGB 是线性传递函数；Apple 线性 F16 表面应核对 `kCGColorSpaceExtendedLinearSRGB`，不能把线性数据直接标为非线性的 `kCGColorSpaceExtendedSRGB`。M1 数值探针与 M2 真屏对拍定论。
- **代理图不能提前裁剪源色域**：Mac 代理若统一转 8bit sRGB，会在 fit 时丢失 P3/Adobe RGB 饱和颜色；推荐 Mac 代理也走受 Governor 准入的 F16 线性产物，或保留源色域并在采样时正确转换。测试结果决定单一可靠路径。
- **混合缓存不能以 sRGB 8bit 作为广色域原图唯一中间态**：冷条目需保留源色域/ICC 或等价的无色域裁剪中间态。编码、色彩空间、方向及实际分配字节必须是明确契约；继续遵守旧壳/AI 输入与持久化契约。
