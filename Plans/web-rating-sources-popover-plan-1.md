# Web 星级来源冲突浮窗复刻计划

## 目标与边界

在独立分支 `feature/web-rating-sources-popover` 中，将 macOS 已有的 RATING-04 来源浮窗复刻到 Web 参考壳。以 `Design/spec/rating.md`、`Design/tokens.json` 和现有 Web 分层为唯一实现依据，不读取或照搬其他平台源码。

本次只做来源浮窗及必要的卡片、控制栏、相似卡片入口接线；不改变真实评分来源模型，不新增 UI 文案或第三方依赖。液态玻璃、原生箭头曲线等装饰可简化，但位置、宽度、布局、字号、圆角、星按钮槽位与交互必须遵循规范。

## 几何与视觉验收

- 星排固定为 6 个 `toolbar.rating.button.size`（30×30）槽位，水平排列、间距与控制栏评分组一致；星与清零叉字形、字号、颜色及 hover/pressed 反馈复用控制栏规格。
- 条目宽 = 星排宽 + 2 × `popup.ratingSources.entryPadding`；浮窗内容宽 = 条目宽 + 2 × `popup.padding`，文本不得撑宽或压缩星排。
- 外层内边距取 `popup.padding`，条目内边距/条目间分隔线节奏/信息行与星排间距/长名行距分别取对应 `popup.ratingSources.*` 令牌。
- 文件名 11px、来源与状态 10px；默认文件名居左、来源标签与状态居右且同一垂直中线。长名时文件名独占首行，来源与状态第二行居右；文件名截断，不溢出。
- 来源标签有 `badgePaddingX` 与 `badgeCornerRadius` 对应的标签底；条目间为 `dividerHeight` 分隔线；浮层圆角取 `popup.cornerRadius`，材质可简化为深色半透明背景。
- 每个来源纵向排列，星形按该来源 rated 真值点亮；其他状态不冒充 0 星。

## 行为验收

- 胶片栏、相似面板和控制栏冲突三角只打开浮窗，不写值；非当前卡片入口不切换主图。
- 卡片及相似卡片默认向下，底部横排控制栏向上，右侧竖排控制栏向左；卡片下方不足且上方足够时向上。浮窗夹在宿主可视范围内，入口与浮窗间保留规范余量。
- 任一条目点击 0–5 均走现有整组 `app.rate` 路径；成功且冲突解除后关闭，失败时保留并刷新条目，不新增 sidecar。
- Esc、外部点击、切图、当前照片因筛选改变、入口隐藏/移除、布局重排、胶片栏或控制栏滚动时关闭；打开期间外部来源变化能刷新条目。
- 重复开合不重复注册全局监听，不残留多层浮窗；菜单/下拉打开时不得叠加冲突浮窗。

## 实施步骤

1. 在 `PhotoViewer.Web/src/shell/` 新增独立来源浮窗组件与 CSS，挂载到主窗口层，复用 `icons.js`、`dom.js` 与令牌 CSS 变量。
2. 在 `main.js` 组装组件并注入上下文；为 `card.js`、`controlbar.js` 提供冲突入口回调，保持现有评分路径不变。
3. 用真实 DOM 文本测量决定单行/双行；打开及刷新时重新定位，按当前布局选择方向。
4. 更新 `?check=rating` 的 RATING-04 检查，覆盖几何、两类入口、方向、整组写入、成功关闭、失败保留、Esc/切图/滚动/重排关闭和重复开合；必要的纯几何逻辑加入现有 Node 测试体系。
5. 同步 `PhotoViewer.Web/AGENTS.md`、`Design/platforms.md`、`Design/status.md` 中长期事实，删除“Web 未实现”的旧描述；规范中所有卡片入口均默认向下。
6. 执行 `npm test`、`python3 Tools/generate-design-tokens.py --check` 与真实浏览器 `?check=all`；保存浮窗截图并核对关键计算样式与位置。

## 完成标准

- 上述几何与行为检查全部通过，既有 Node 与页内检查无回归。
- 浏览器中实际打开浮窗，目视确认短名/长名、卡片/控制栏入口、两向控制栏及长名截断。
- 工作树只包含本任务改动，不触碰主工作区正在进行的 iOS 修改，不提交、不推送。
