## 下一步验证项（未经验证不贸然实施）

- Windows RAW：受控对照已确认开发与精缩代价；一般尺寸代理仍需定出开发源保留/直接 Full 的预算、失效及压力修剪规则，不只凭单张更快而强制增加常驻内存。
- Windows 冷帧合成长尾：本地直连显示与远程/虚拟显示分开复测，不把呈现等待当解码耗时。
- 安卓 P3→sRGB 全图转换在强制回退场景已确认可达约 601ms；下一步优先验证与串行 skcms 逐字节一致的分带转换，以及后台准备的代际/租约/表面协商边界，不先重写 EGL 线程架构。当前数据不代表该回退在日常浏览的发生频率。
- 安卓绘制合帧、独立渲染/上传线程与共享 EGL 上下文：需单独设计线程、表面生命周期与背压，先保留同步提交契约。纹理存储分配本机约 0.01–0.04ms，未证实省掉重分配有收益，不贸然取消驱动 orphaning 机会。
- JPEG 多次 SAF 打开、HEIF 按 extent 随机读取、硬件 HEVC：需先补分段计时与格式覆盖，避免扩大支持面或改变解码画质。
- 真实 HDR/ACM 开关、跨显示器与校准精度，以及非小米 ROM 的 P3 表面矩阵。

## 验收记录

### HEIF 回落色彩

- 共享 `PhotoViewer.Heif` 仅链接 Windows/Android/验证工具，无新增 NuGet 依赖，Apple 不受影响。修复 RGB24 行距被当图宽、高位深中间图被当 BGRA32 返回，以及取消/缩放异常路径的产物租约释放。
- 真机新增强制回落对照发现，旧 `BitmapFactory` 段在 sRGB 与 P3 ICC HEIF 的灰阶上都可偏 18 级；不放宽容差，安卓 HEIF 展示回落统一到共享 libheif，兼容入口也不再调用系统 HEIF 解码。共享引擎不能解释的编码/色彩如实失败；系统专属 AVIF 等支持面仍需另备素材验证，不能宣称全格式等价。
- Windows/Android 的 `IHeifDecoder` 统一返回已转正 sRGB8 并声明 `OutputPreRotated=true`；真实入口覆盖 irot=1/2/3，`ThumbnailService` 的 180° 色卡检查通过，不再双转。
- Windows Release 构建 0 警告/0 错误；色彩 16 PASS + 1 硬件边界，原生 smoke 35 PASS。共享色彩 68 PASS；Core 契约 914 PASS / 1 平台 SKIP / 0 FAIL；HEIF e2e/smoke 通过，含真实 ICC/nclx、强制高位深三出口、12 位暗平面、租约和取消。
- Android 标准 Release 与独立包名验收包均构建成功；删除旧系统段后剩余警告为既有内存探针平台版本与原生库重复项。小米 13/API 33 的独立 Release AOT 包色彩 105/105、主流程 22/22；Debug 轮次还覆盖缩放 30/30、输入 27/27。正式应用未覆盖安装，用户数据未动。


### HEIF 文件读取

- 稳定长度的可寻址流直接填充最终数组；非寻址流、部分读取、长度增长/缩短保留真实字节，超出数组可容纳范围明确报错；打开与读取传递取消，异常与取消均释放流。
- Windows 主图与 Android 主图/展示缩略图在快速路径回落时复用本次字节，不重新打开文件。Android 真机 PQ/HLG 的完整入口回落检查均 `opens=1`，色彩检查增至 107/107。
- `HeifFastDecodeTest read` 全通过；8MiB 文件读取实测分配 8,388,808B（有效载荷 8,388,608B），稳定长度路径只剩一份文件级数组，而非原来的两份。HEIF e2e/smoke、Windows Release、Android Release AOT 验收包通过。
- Windows 同机同目录/同参数探针：HIF Full 184.4ms、5120 代理 214.9ms、列表缩略图 7.2ms。相对审查轮次 240.1/274.9/14.2ms 有下降，但 CPU/驱动与系统负载存在跑间波动，不把这组单轮差异全归因于读取优化；确定收益是少一份文件数组与回落零重复打开。


### 安卓顶点缓冲

- 每个 renderer 延迟创建一次 64B direct buffer、native-order float 视图及复用顶点数组；每帧只覆写顶点，EGL 上下文重建保留 CPU 缓冲，释放时视图先于 owner，异常分配路径不留半初始化资源。
- 新增四项真实绘制回归：八方向的顶点/UV 与缓冲身份、方向 8 的非对称四象限 GPU 字节对照、缩放平移后顶点更新、两次上下文重建后身份和分配次数保持。两轮重建后累计分配仍为 1。
- 小米 13/API 33，独立 Release AOT 包：最终 color 107/107、zoom 30/30、input 27/27；主流程先前 Release 22/22。真实 26MP HIF 代理 2496×1664、Full 6192×4128，解码 643.1/842.8ms；会话双击升级 Full 与纹理缓存正确，UI 心跳最大间断 119.5ms。GL 上传仍同步，本轮不宣称冷上传达到 16ms，也不把顶点缓冲复用当作 HEVC 解码提速。

### 后续优先级

1. Android 全图色域回退转换：已确认强制回退时约 601ms，先验证分带 skcms 与串行出口的逐字节一致及实际收益，再设计后台准备/提交的代际与租约契约；不将这轮强制回退当成日常发生频率。
2. Windows RAW 一般代理的一次开发复用：对照证据已齐，需定出直接 Full 或保留开发源的内存预算、文件失效、压力修剪与并发规则；不增加无边界的常驻缓存。
3. AVIF、非恒等 clap、复杂镜像组合与多 ROM 素材矩阵：明确共享 libheif 原生插件覆盖及不支持提示；不恢复未经数值校验的系统 HEIF 色彩出口。
4. 本地直连显示器的 Windows 冷帧长尾与真实 HDR/ACM/跨屏验证。

### Windows RAW 受控对照与租约收尾

- 将 RAW 源获取、解码后取消检查与 EXIF 方向读取全部纳入同一 `try/finally`；取消或元数据失败不再遗留开发源租约。主图算法、色彩、方向与代理尺寸未改。
- 最终 Release 构建 0 警告/0 错误；色彩 16 PASS + 1 BOUNDARY，smoke 最终 35 PASS。smoke 曾两次在既有 RATING-04 浮窗间距项失败；干净基线和本次构建随后均通过，记录为摆放状态相关的不稳定项，不为其修改 UI。
- 同目录 6 张 a7C II RAW（7008×4672），首张预热后 n=5：WIC 开发中位 1073.4ms，5120 Mitchell 缩放 359.2ms，代理转 F16 13.2ms，Full 转 F16 24.2ms。产品解码器代理/Full 中位 1450.1/1088.1ms。单次开发生成的代理和 Full 均 6/6 与产品入口元数据、ICC 及有效像素逐行逐字节一致。
- 池化产物：全幅 BGRA 128MiB、代理 BGRA 72MiB、代理 F16 144MiB、Full F16 256MiB；对照实验四份合计 600MiB 是派生产物账，不含仍作为对照基准保留的产品代理/Full，也不是进程峰值。普通缓存允许代理和 Full 同时存在，不能假定二者择一。
- 单次开发下 Full 直出比 5120 代理少约 347ms，但初次展示需额外 112MiB 像素内存；此证据仅覆盖本机/本组文件，尚不据此强制所有 RAW 直接 Full 或常驻保存开发源。优先补齐已达源分辨率的代理对 Full 请求的无副本复用，再单独决定一般 RAW 的开发源保留策略。

### 源分辨率代理对 Full 的复用

- 同步缓存查询与异步 Full 请求在 Full 档未命中后，复用已达源分辨率且编码可用的 Proxy 原实例。两维分别验源长短边；合法展示编码仍按 F16/8 位保真度比较；旧编码仅允许布局完全相同，不将 BGRA 当 RGBA。只借一份调用方租约，不新增 Full 缓存条目或像素副本。较小代理仍正常解码升级。
- `CoreContractCheck` 新增 43 项缓存/会话/租约/编码边界检查，最终 957 PASS / 1 macOS SKIP / 0 FAIL；`ColorTestTool` 68 PASS，最大线性误差 0.000946。
- Windows 最终 Release 构建 0 警告/0 错误；色彩专项增至 17 PASS + 1 BOUNDARY。真实 7008×4672 RAW 的 7680 请求已产出源分辨率，随后同步/异步 Full 都复用同一 F16 实例，未新建 Full 条目，异步请求约 0.58ms；这是已有完整像素命中，不是首次开发耗时下降。
- 最终完整 Windows smoke 两次均在既有「RATING-04 横排控制栏来源浮窗与入口间距 206」失败（此前 RAW 里程碑也出现过），最后报告为 26 PASS 后 1 FAIL，不以此前 35 PASS 代替最终结果。未改浮窗、布局或放宽断言；该项仍待独立排查。Apple 原生壳本轮没有构建/实机验证。

### Android 完整提交墙钟与真实转换代价

- `up_*` 仍是旧 GL 四段口径；`submit_*` 才覆盖同步提交的等锁、EGL 绑定、实际色域转换、GL 提交与收尾。缓存命中上传为零，但提交仍按真实耗时记录；转换分位数不混入零转换样本。中间拷贝是上传段的子指标，不重复相加。计时器改用时间戳，不再为每次上传创建 `Stopwatch` 对象。
- 真机加入跨色域命中不重转、同色域零转换、分段被外层墙钟覆盖、同尺寸空纹理命中、尺寸不符与 EGL 重建拒绝误命中及 GPU 像素检查。空纹理只复用纹理名，保留 `glTexImage2D` 存储分配，不声称已复用存储。
- 最终标准 Android Debug/Release 及隔离 Release AOT 包构建成功，均 15 项既有警告（内存探针平台版本、原生库重复）/0 错误。小米 13/API 33 独立包：color 118/118、zoom 41/41、input 27/27、main 22/22。
- 真实 6000×4000 P3 夹具（有效像素 96,000,000B）：强制 sRGB 表面时转换 601.09ms，GL 四段仅 35.60ms，完整同步提交 636.75ms；P3 表面重建后同源完整重传零转换，提交 43.55ms。两相 GPU 样本均与正确目标色域字节一致。这是强制回退的单次成本，不是发生频率或 p95，也不包含 Draw/Swap/合成器等待。
- 真实 26MP HIF 的 2496×1664 代理/6192×4128 Full 解码 678.2/793.9ms；Full 同步提交 52.80ms，实际会话 UI 心跳最大间断 102.6ms，未宣称达到 16ms。首次 Debug 启动在检查前曾触发既有原生 SIGSEGV，后续 Debug/最终 Release 检查通过；没有把这次崩溃归因于计时代码或宣布已修复。
- 原生 libheif 构建脚本明确禁用 AOM/dav1d 和运行时插件加载，不能将当前 HEVC 构建当作 AVIF 支持承诺。系统 HEIF 输出仍不恢复；AVIF 及其他容器变换的素材/插件支持矩阵继续待验。
